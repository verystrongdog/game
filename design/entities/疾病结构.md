## 一、与旧结构的关系

**内容一字未改。** 26 张病卡的病名 / 开门 / 关门 / 代价 / 风味逐字取自 [`疾病特长.md`](疾病特长.md) §4.1·§4.3，《无法离开医院》取自 §4.6。变的是**结构**：

| 旧 | 新 | 为什么 |
|---|---|---|
| **8 个疾病父类**（按神经机制分组）作为归属轴 | **删掉**。浏览改由 9 个查询式视图（按门类 / 按形态 / 没有固定情境 / 固有项） | 它是单值归属键，而"拿父类当轴"正是旧经历结构失败的原因；且它的分组依据是机制层概念，属拦截规则禁止项。⚠️ 只删 `data/` 里的键，`design/entities/diseases/_parent-classes/` 那些机制文档不动。 |
| **四种表现形态**存为字段 | **派生**，不存字段。判据 = 玩家看得见的三件事：会不会打断你（`break_in`）· 说话的人还是不是你（`speaker_change`）· 是不是按周期来（`phase_cycle`） | §4.2 原文的判据是表征数值（F/N/D_seg 阈值）——机制参数，不得进数据。派生表能机械复现原来的 9/8/1/8。 |
| 临时加成写成一格文本「情境 → 属性」 | 拆三项：`bonus.visible`（**闭集**触发情境）+ `bonus.attr`（引用 `attributes.ids`）+ `bonus.at_least`（重复几次才生效） | 触发条件写成自由文本就不可查询——那是经历那轮修掉的错。 |
| 「+1」「重档 +2」写在病卡里 | 移进 `tiers`（带 `source`），病卡不写数值 | 数值不硬编码，病卡只说"有没有加成、加在哪一项"。 |
| 「遭遇门」是一类正常内容门 | 词表保留 `encounter` 但标 `status: "paused"`；**不建模撞到点**（`where: []`） | 战斗层已暂停。 |
| 病卡与经历两侧各写一份疾病列表 | 名册只在 `data/diseases.json`；经历侧只存 id | 一份权威数据。 |

## 二、词表

**`name` 是玩家可见的**（`describeDisease()` 会渲染到卡面），一律用人话。

| 词表 | 卡面上的名字 | 单/多 | 取值 | 调用方拿它查什么 |
|---|---|:-:|---|---|
| `door_kind` | **门类** | 单 | 对话门 · 调查门 · 空间门 · 遭遇门（`paused`） | 「按门类看」用哪扇门代表一张卡；界面据此决定渲不渲染 |
| `door_where` | **会在哪里撞到** | 多 ≥1 | 走廊 · 病房 · 护士站 · 扭曲病房 · 房间 · 线索页 · 自问页 · 对话选项 · 说不出的话 · 带「存疑」的记录 · 读不全的小字 · 没印象的条目 · 时段 · 休息 · 相位播报 · 另一个人的对话 | 关掉的门在哪个场景/界面被玩家撞到（§5.2 关门必须可见） |
| `visible` | **看得见的触发情境** | 单（可为空） | 24 个（危险可能重现 · 身体不对劲 · 你怕的那类东西在场 · … · 有明确规则） | 临时加成什么时候生效；界面据此把 +1 亮出来 |
| `speaker` | **说话的人** | 多 0–1 | 不是你 | 形态派生：出现时说话的人还是不是你 |
| `used_for_group` | **哪扇门代表这张卡** | 多 | 用开着的那扇门 | 「按门类看」里一张病卡只出现一次——用哪扇门出现 |

**空值怎么念写在数据里**：`visible.empty_label` = 「没有固定情境」（两张病没有单一成立情境）；`speaker.empty_label` = 「还是你」。代码不写死。
**没有通配符，没有 `unknown` / `待定` 取值。**

## 三、记录 schema

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `^dis_\d{4}$` | 主键。与 §4.1 行号一一对应（`dis_0001` = PTSD … `dis_0026` = ADHD）。不透明、不含语义、永不复用 |
| `label` | string | 病名，逐字搬 §4.1 |
| `plain` | string | 风味，逐字搬 §4.3 |
| `break_in` | bool | 会不会打断你正在做的动作/对话 |
| `speaker_change` | `[]` 或 `[speaker 取值]` | 出现时说话的人还是不是你 |
| `phase_cycle` | bool | 是不是按一个来回的周期出现 |
| `doors` | array（恰好 2 项） | 1 项 `open:true` + 1 项 `open:false`，门类不得重复 |
| `doors[].what` | string | 逐字搬 §4.1 对应那格 |
| `doors[].where` | `door_where` 数组 | 生效的门 ≥1；暂停的门必须为 `[]` |
| `doors[].used_for_group` | `used_for_group` | **仅开门项**有 |
| `bonus` | `null` 或 `{visible, attr, at_least}` | `null` = 没有固定情境 |
| `bonus.attr` | 引用 `opening.json.attributes.ids` | 不新建词表，这是同一份权威 |
| `bonus.at_least` | int ≥2 或 `null` | 触发要重复几次（现仅 ADHD = 3） |
| `cost` | string | 逐字搬 §4.1 末列。**纯叙事、不查询** |
| `source` | string | `…§4.1 总表第 N 行` |
| `always_on` / `signs` | 仅固有项 | 《无法离开医院》：`doors: []`、`bonus: null`、四条症状逐字搬 §4.6.2 |

**禁止出现的字段**：`category` · `theme` · `parent` · `lineage` · `form` · `form_id` · `class` · `tags` · `note` · `comment` · `weight` · `severity` · `intensity` · `views` · `from`（反向键）· `trigger`（自由文本）· 任何 `*_profile` / 机制参数键。校验器把**任何未知键**当错误。

## 四、接口

实现：[`web/src/character-creation/diseases.js`](../../web/src/character-creation/diseases.js)。**全部无状态纯函数**，`ddb` 由调用方传入。函数名一律带 `disease` 前缀，避免与 `opening.js` 互相遮蔽。

| 组 | 函数 |
|---|---|
| 读取 | `diseaseById` · `diseaseIds` · `diseaseLabel` · `diseaseValues` · `diseaseEmptyLabel` · `doorVisible` |
| 查询 | `clauseHitsOnDisease` · `evalDiseaseSelector` · `queryDiseases` · `evalDiseaseView` · `diseaseViewIndex` |
| 派生 | `formOf`（形态不存字段，现算） |
| 门 | `openDoors` · `closedDoors` |
| 接缝 | `diseasesOfExperience` · `sourcesOf`（反查）· `diseaseCandidates` · `diseaseCoverage` · `diseaseCanStillPick` · `rosterOf` |
| 渲染 | `describeDisease` · `renderDiseaseTable` |
| 校验 | `validateDiseases` · `migrationCoverage` · `formOf` |

**疾病侧的额外子句形状**（与经历侧同一套求值语义）：

```js
{ facet: 'doors', open: true, kind: 'dialogue' }   // 有没有这样一扇门
{ facet: 'form',  in: ['intrusive'] }              // 派生形态
{ facet: 'bonus', not_empty: true }                // 有加成
```

### 增删改口径

| 操作 | 改几个文件 | 说明 |
|---|:-:|---|
| 加 / 删 / 改**一条经历** | **1** | `data/opening.json`。只写病 id，不复制任何病数据 |
| 改一条病的**内容**或**结构** | **1** | `data/diseases.json` |
| 加一条病 | **2** | `diseases.json` 加卡 + `opening.json` 在**至多 2 条**经历的 `diseases` 里加 id |
| 加一个门类 / 撞到点 / 触发情境取值 | **1** | `diseases.json` 词表 |
| 加一个疾病视图 | **1** | 记录侧零改动 |

> ⚠️ **诚实标注：「加一条病 = 2」，不是 1。** 把病并进 `opening.json` 才是 1，但那样病卡正文与经历会互相污染。**经历侧的不变量（加一条经历 = 1 个文件）在两种方案下都成立**——这是本契约要保住的那条。

## 五、与经历契约的接缝

> 🔧 **阶段 7（2026-09-27，owner 裁定）：本节（§五）的「并集诱发 + 池级筛选力」口径退役。** 病不再由十段经历的并集诱发，而是由**一件事**直接激活（候选 = `data/opening.json` 的 `events[].activates`，上界 4）；`pool_rule` 在数据里**就地标了退役、键不删**，疾病侧的新口径是 `data/diseases.json` 新增的 `candidate_rule`。现行口径见 [开局经历疾病接回](../presentation/开局经历疾病接回.md) §三 · §五。**下表保留作历史**——它记录的「上界是纯组合的」这个推理方式仍然成立，只是换了一个更紧的上界（4，不再是 `min(c·k, u_pool)`）。

| 问题 | 答 |
|---|---|
| `diseases` 引用谁？ | `data/diseases.json` 的 `items[].id`。名册整块从 `opening.json` 删除，换成 `disease_roster_moved` 指针——留一份就会漂。 |
| 反查怎么算而不存第二份？ | `sourcesOf` 每次遍历 `db.experiences` 现算。病记录里**没有** `from` / `experiences` 反向键。（🔧 阶段 7 起反查有了**第二个方向**：事件 → 素材，即 `events[].source_experiences`；它服务的是审计素材覆盖，不是反查键。） |
| 候选筛选力（判据可算） | `每条经历指向 ≤ c` ∧ `选 k 段` ⟹ `\|候选\| ≤ c·k`。`c=2`、`k=10` ⟹ **上界 20 < 名册 26** ⟹ **本局至少 6 张病结构上不可能出现**。上界是**纯组合**的，与名册内容无关。校验器把它写成硬错误 `candidate_filter_too_weak`。 |
| **池级筛选力（2026-09-27 由格级平移）** 🔧 阶段 7 退役 | 一局的池子 `P_pool`（问诊第 4–7 问筛出、玩家逐条核对的那一池）装下了全部候选：`候选(S) ⊆ ⋃_{r∈P_pool} diseases(r)` ⟹ `\|候选\| ≤ min(c·k, u_pool)`，`u_pool` 是池子的病并集。`u_pool = 4` ⟹ `min(2×10, 4) = 4`，**本局至少 22 张病不可达**（旧口径 6 张）。上下界写在 `pool_rule`（`diseases_min 2` / `diseases_max 4`）：上界太小会把患者意见栏掏空，下界太大则候选失去筛选力；放池子时按它收口（实测池病并集恒为 4，见[经历结构 §10.4](经历结构.md)）。🔧 旧口径按「锚点格」写（`cell_rule`）——格已退役，`cell_rule` 整块改名重写为 `pool_rule`，不留第二份权威。 |
| 🔧 **事件级筛选力（2026-09-27 阶段 7）** | 候选 = 那件事的 `activates`（本批每件事 **4** 张，一套语言指纹一张）减去已答扩展位声明排除的病；一局说话的调子定下来之后再收窄到该调子代言的那一张。上界 = `event_rule.candidate_max` = 4 = `candidate_rule.candidate_max`（两侧同值，见 `data/diseases.json` 的 `candidate_rule`）。**名册 26 张本批全部有归宿**（`event_coverage`），所以「不可达」这个说法在结构上指的是**一局之内**：一局最多 4 张候选、调子定下来时只有 1 张。 |

## 七、不变量与「没有工具时人肉怎么核」

> ⚠️ **没有任何门禁在跑 `validateDiseases()`**（全仓校验器 2026-09-17 撤销）。下面是人工兜底。

| # | 不变量 | 人肉核法 |

| J1 | `id` 唯一、`dis_NNNN`、不复用 | 抄出 `"id": "dis_` 行排序看重复；与 `tombstones` 对眼 |

## 八、反例清单——出现任意一条即失败

| # | 失败形态 | 具体长什么样 |
|---|---|---|
| 1 | **单值归属键** | `"parent": "焦虑谱系"` · `"category": "创伤相关"` · `"form": "intrusive"`（形态必须是派生视图） |
| 2 | **语义藏在文案里** | 加成写成 `"trigger": "危险可能重现时"`；`at_least` 只写在 `what` 文本里而字段缺失 |
| 3 | **两份手写副本** | `opening.json` 里留名册又开 `diseases.json`；病卡里存 `"from": [...]`；设计文档里手抄病卡清单 |
| 4 | **字段不可查询** | 触发情境是自由文本；`where` 写散文；门类写成「遭遇（暂）」这种带尾巴的值 |
| 5 | **依赖机制层概念** | 脑区 · 连接组 · W 矩阵 · 意识结构 · 情境原语 · `AppraisalProfile` · α 模式 · 环境基调 · β/k/g · 表征数值阈值 |
| 6 | **数值硬编码在代码里** | `const BONUS = 1`；`const MAX_PICK = 1` 不读 `presentation` |
| 7 | **加一条病要先决定它「属于哪一类」** | 新增病卡前必须先在某个 `categories` 数组里挑槽 |
| 8 | **用 id 分支业务** | `id.startsWith('dis_00')` 这类前缀判断 |
| 9 | **静默改 canon 门类** | 把 7 扇遭遇门偷偷改判成对话/调查/空间门而不标 ⏳ |
| 10 | **死门** | 生效的门 `where: []`；或 `what` 说了但没有任何地方能撞到 |
| 11 | **给暂停的门建模** | 给遭遇门填 `where`——战斗层暂停期间不得建模撞到点 |
| 12 | **加成为白给** | 有 `bonus` 但关卡表的关门无关——§2.3 要求加成是那把锁的另一面 |
| 13 | **为完整性加字段** | 补 `severity` / `intensity`，却写不出一句「调用方拿它查什么」 |
| 14 | **把固有项当第 27 个病** | `dis_0027` 进候选、占额度，或参与 `roster_size` 统计 |
