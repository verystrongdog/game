## 一、与旧结构的关系

旧结构（`疾病特长.md` §3.2）是 **8 个玩家主题 → 8 个疾病父类**，48 段经历每段落在一个主题里。它已作废，理由是结构性的，不是内容不好：

| 问题 | 事实 |
|---|---|
| **"8 主题 → 8 父类"不成立** | 逐病核对 `design/entities/diseases/*.md` 的 `父类:` 字段：奖赏系统障碍占**两个**主题（贫困/排斥），社会认知障碍**零席**（唯一子类走发育轨）。实为 8 → 7。 |
| **单归属撑不住多出口** | 8 个主题里 6 个的疾病候选横跨 3–5 个父类，靠一句补丁语言压着：「一段经历只出现一次，若同时关联多个父类，疾病候选在该卡内部合并」。 |
| **主题用后果命名输入** | "长期危险与警觉 → 焦虑唤醒障碍"：浏览轴的名字就是它预测的病。不预告结局就无法陈述一段人生。 |
| **真语义藏在字符串里** | "长期 / 反复 / 从小 / 被迫"只存在于卡面文案，机器读不到——所以任何调用方都只能逐条点名，谈不上接口。 |
| **两份手写副本** | 同一批记录同时存在于 md 表格与 `character-data.js` 字面量，已漂出死引用（「慢性疼痛」不在疾病总表里）。 |

**不设兼容、不做迁移映射。** 新结构与旧结构是两套东西：旧的是"给每段人生指定一个父亲"，新的是"给每段人生填一张表"。

## 二、facet 与词表

11 个 facet。**每个 facet 必须能回答"调用方拿它查什么"**（`ask`），答不上来就删——校验器把空 `ask` 当错误。

⚠️ **问诊里有 12 个答案轴，但只有 11 个 facet**：第 1 问（患者自述疾病）的答案轴是 `self_report`，它**不是记录 facet**——288 条记录里没有这个字段，它只写进病历的主诉栏（闭集在 `data/opening.json` 的 `complaint.self_report`）。判据见 §10.1 与 `interview_nonfacet_question_matches` / `interview_facet_source_conflict`。

**`name` 是玩家可见的**（`describe()` 会把它渲染到卡面），所以一律用人话写。
⚠️ 2026-09-20 修：初版把这批名字写成了设计系统黑话（`relation` 叫「对手方」——金融术语 counterparty，且中文「对手」含敌意；`context` 叫「地方」是社会学词；`consequence` 叫「后果出口」是 output slot 的直译）。全部替换为卡面上能读出口的问句：

| facet | 卡面上的名字 | 单/多 | 取值 | 调用方拿它查什么 |
|---|---|:-:|---|---|
| `context` | **在哪** | 单 | 家庭 · 学校 · 工作 · 社会 · 生存环境 | 分组浏览 + **配额计数** |
| `relation` | **和谁** | 多 0–6 | 父母 · 伴侣 · 同伴 · 上级或师长 · 陌生人 · 群体 | 分组 + 没有人的经历是否合法 |
| `role_care` | **谁照顾谁** | 单 | 被照顾者 · 照顾者 · 不适用 | 分组 + 组合校验 |
| `role_power` | **谁说了算** | 单 | 被管理者 · 执行者 · 管理者 · 不适用 | 分组 + 组合校验 |
| `role_belong` | **圈内还是圈外** | 单 | 圈内人 · 局外人 · 不适用 | 分组 + 卡面提示 |
| `event` | **发生了什么** | 多 1–3 | 获得 · 失去 · 冲突 · 威胁 · 失败 · 成功 · 暴露 · 改变 | 筛选 + 疾病候选筛选 |
| `duration_span` | **多久** | 单 | 瞬时 · 短期 · 长期 | 「长期」分组 + 时间线排序 |
| `duration_pattern` | **怎么发生的** | 单 | 单次 · 持续不断 · 反复发生 | 「反复」分组 + 时间线排序 |
| `onset` | **从什么时候开始** | 单 | 童年 · 少年 · 成年 | 「从小」分组 + 时间线排序 |
| `agency` | **你能决定多少** | 单 | 主动 · 部分主动 · 被迫 · 完全无法控制 | 分组 + 卡面提示 |
| `consequence` | **留下了什么** | 多 1–6 | 能力 · 关系 · 资源 · 信念 · 行为模式 · 情绪反应 | 镜子屏**输出**——**不作为分组** |

**id 与 `name` 分工**：id 是机器键，永不变、不译、不带语义（`relation` 不叫 `duishoufang`）；`name` 只是卡面标签，可以随时重写成更顺口的中文而**不影响任何接口**。改 `name` 不需要动记录、视图或测试。

**空的「和谁」怎么显示**：`relation` 允许空数组（一个人）。它的取值表里不能放 `none`（多值 facet 禁止），所以空值怎么读由词表的 `empty_label` 决定——`relation.empty_label` 现为「一个人」。校验器要求：任何 `min_items: 0` 的多值 facet 必须有 `empty_label`。

**输出槽怎么标**：`consequence` 在词表里带 `"output": true`。`describe()` 据此把它从卡面的分组行里排除，只当"留下了什么"一节（`channels`）——否则它会既出现在 facet 列表又出现在输出里，卡面上重复一行（这是初版的真 bug）。**标记写在数据里，不写死在代码里**；校验器要求 `output: true` 的 facet 恰好一个（`output_facet_count`）。

相对 owner 草案的四条改动（逐条给理由）：

| 草案 | 改为 | 理由 |
|---|---|---|
| `Role` 一张表 | 拆 `role_care` / `role_power` / `role_belong` | 谁照顾谁 · 谁说了算 · 圈内还是圈外，是三个互不相干的轴。"管理者"与"局外人"不是同一种对立，同表会互相污染。 |
| `Duration` 四值 | 拆 `duration_span` + `duration_pattern`；新增 `onset` | 原四值混了两件事：「反复 × 短期」在原表里**无法表达**。`onset` 收「从小」——它原来只活在文案里。 |
| `Relation` 五值 | 增至六值：加「上级或师长」 | 五值下「工作 × 被管理者」找不到人可填（上司既不是父母也不是陌生人），该组合只能落空。 |
| `Consequence` 与 `Context` 平级 | 保留为**多值输出槽** | 它是**结果**，不是身份。与输入平级会重犯旧轴的错（拿后果当分类）。它的 `ask` 写的是"输出"而不是"筛选"。 |

**没有通配符，没有 `unknown` / `待定`。** 开局经历由作者编写，不存在"作者也不知道"。写不出 `onset` 就说明这条记录还不该存在。单值 facet 的"不适用"必须显式写 `none`；多值 facet 用空数组（只有 `relation` 允许，代表独自）。

## 三、记录 schema

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `^exp_\d{4}$` | **主键。不透明、不含语义、永不复用**（删除后进 `tombstones`） |
| `title` | string ≤8 字 | 卡片标题，纯叙事 |
| `summary` | string ≤48 字 | 卡片正文，纯叙事；受文本 lint |
| `context` `relation` `role_care` `role_power` `role_belong` `event` `duration_span` `duration_pattern` `onset` `agency` `consequence` | 词表引用 | 全部必填，见 §二 |
| `effects.attributes` | `{attr: int}` 1–2 项，**和 = +2** | 界面数值的**唯一来源** |
| `diseases` | string[] ≥1 | 引用 `disease_roster` 的 id |

**禁止出现的字段**：`category` · `theme` · `parent` · `kind` · `class` · `views` · `tags` · `note` · `comment` · `weight` · `severity` · `intensity`。校验器把**任何未知键**当错误——这是"语义不许走私"的兜底。

```json
{
  "id": "exp_0001",
  "title": "空着的碗筷",
  "summary": "饭桌上有一副碗筷没人用。作业本上的签名是你自己写的。",
  "context": "family", "relation": ["parents"],
  "role_care": "care_receiver", "role_power": "managed", "role_belong": "outsider",
  "event": ["loss"],
  "duration_span": "long", "duration_pattern": "intermittent", "onset": "childhood",
  "agency": "powerless",
  "consequence": ["ability", "relation", "belief", "emotion"],
  "effects": { "attributes": { "will": 3, "communication": -1 } },
  "diseases": ["dis_0001", "dis_0003"]
}
```

注意这条记录里**没有任何地方说明它"属于哪一类"**。它落在哪些分组里，由 `views` 的 selector 查询决定。

## 四、接口

实现：[`web/src/character-creation/opening.js`](../../web/src/character-creation/opening.js)。**全部是无状态纯函数**，`db` 由调用方传入（Vite 下 `import db from '../../../data/opening.json'`，与 `hospital-map-prototype` 同一模式）。五屏之间可任意回退、重放，一个 id 数组就能分享同一个开局。

| 组 | 函数 |
|---|---|
| 读取 | `byId` · `facetSpec` · `labelOf` · `facetIds` · `valuesOf` |
| 查询 | `clauseHits` · `evalSelector` · `queryByFacets` · `evalView` · `viewIndex` · `describe` |
| **问诊** | `interviewRule` · `interviewQuestions` · `questionById` · `questionOfFacet` · `matchQuestions` · `matchFacets` · `facetsAnsweredBy` · `answerSpec` · `answerOptions` · `isAnswered` · `answersComplete` · `answerText` · `answerChoices` · `toggleAnswer` · `answerHitsClause` · `answersForceCombos` |
| **池子** | `answersMatchRecord` · `matchedCount` · `scoreAnswers` · `answerMask` · `orderByHits` · `levelPredicate` · `poolCandidates` · `poolFloors` · `poolStats` · `poolMeetsFloors` · `fillPool` · `interviewPool` · `poolIdsFor` · `poolCensus` · `answerCardinality` · `mutexCanCoexist` · `maxSelectable` |
| 合法性 | `mutexNeighbors` · `quotaState` · `canStillComplete(db, sel, poolIds?)` · `canSelect(db, sel, id, poolIds?)` |
| 结算 | `settleAttributes` · `bandOf` · `timeline` |
| 疾病 | `diseaseCandidates` · `diseaseCoverage` |
| 校验 | `validate` · `validateInterview` · `renderTable` |

`poolIds` 的默认值是 `null`（= 整个库可选）。传了池子之后，池外的记录会被 `not_in_pool` 挡住——**一局的池子就是这一局的全部可选项**。

**视图 = selector，不是容器。** 记录侧不存在任何视图引用，所以增删视图对数据零影响。

```json
{ "id": "view_long_repeat", "label": "长期反复",
  "selector": { "all": [ { "facet": "duration_span", "in": ["long"] },
                         { "facet": "duration_pattern", "in": ["intermittent"] } ] } }
```

子句三种形态：`{facet, in:[…]}` · `{facet, not_in:[…]}` · `{facet, empty:true}`。
**非法 facet 组合用完全相同的子句形状**（`forbidden_combos`），所以一份求值器同时服务两者，不存在两套匹配语义。

### 病历单调用点

| 纸上那一步 | 调用 | 得到 |
|---|---|---|
| **问诊条**（自述 + 七问） | `answerChoices(db, 已答的)` | 当前那一问的可点性（灰掉理由：非法组合 / 多选已满） |
| 写进病历 | `answerText(db, q, value)` | 这一笔写在纸上的字（空值念 `vocab[facet].empty_label`） |
| **既往史：这一池** | `interviewPool(db, ddb, answers)` | 本局的池子（放宽阶梯选中的那一级、池子的段数 / 地方跨度 / 病并集） |
| 逐条核对 | `describe(db, id)` · `quotaState(db, sel)` · `canSelect(db, sel, id, poolIds)` | 条目的文字与形状 · `已核实 n/10` · 可点 / 灰掉 + 理由（地方满 / 已满十段 / 不在池子里 / 会造成死局） |
| **2 属性结算** | `settleAttributes(db, sel)` → `bandOf` | `raw / clamped / band / overflow`，五项终值与档位 |
| **3 疾病候选** | `diseaseCandidates(db, sel)` → `describeDisease(db, ddb, id)` | 候选 + 来源经历（「因为你有：…」）+ 固有项（`always_on`，不占候选） |
| **4 选疾病** | `diseaseCanStillPick(db, ddb, sel, id)` | 写回 `selectedDisease`（必须 ∈ 候选集） |
| **5 镜子** | `timeline(db, sel)` → `describe` | 按 `onset → duration_span` 排序的人生线；`overflow > 0` 时提示被上限截掉的点数 |

**开局不再用视图浏览。** 六个视图（`view_family` 等）仍在数据里，供反查与将来的笔记本页使用；它们不参与开局流程，删掉任意一个也不影响记录。

### 增删改口径

| 操作 | 改几个文件 |
|---|:-:|
| 加 / 删 / 改一条经历 | **1**（`data/opening.json`） |
| 加 / 删一个视图 | **1**（记录侧不动） |
| 加一个词表取值 | **1**（记录不动，视图按需） |
| 改配额、档位、起始值、净值规则 | **1** |

**答案是 1**，靠"单文件"这个决定。视图不需要改，是因为 selector 是 facet 查询式——新记录的字段值自动决定它落在哪些视图里。**会变成 2 的唯一情形**是把 `disease_roster` 拆成独立文件，所以本契约坚持不拆。

## 五、可调参数（都在 `data/opening.json` 里，各带 `source`）

> 游戏初期，**下面每个数都可调**。改完跑一次 `validate(db)` 即可。

| 块 | 现取值 | 说明 |
|---|---|---|
| `bands` | 0–2 笨拙 / 3–4 协调 / 5–6 精通 / 7–9 娴熟 / 10 本能 | 复用五档正式名。**只有 10 点叫本能** |
| `base_attributes` | 五项全 **0** | 起始全部笨拙——「你没干过的事，你就是笨拙」 |
| `attribute_bounds` | 0–10 | 封顶 10，超出作废 |
| `effects_rule` | `net 2` · `max_abs_term 3` · `max_terms 2` | 由「+2 / +1+1 / +3−1」推出 |
| `quota` | `total 10` · `per_facet context` · `per_value_max 3` | 见下 |
| `interview` | 八问（自述 + 七问追问：问法 · 答案闭集 · 写进哪一栏 · 是否参与池子）· `who_answers`（患者 7 / 院方 4）· 池子口径（展示上限 12 · 放宽四级 · 起手 8 次）· 屏文案 | 见 §十 |
| `mutex` | `[]`（已退役） | 旧两对全是跨格死条款；现判据换成「病并集超过池子上界」（§10.5） |
| `text_lint` | 禁数字 + 禁「多久」「怎么发生的」「从什么时候开始」的标签 + 标题 8 字 / 正文 48 字上限 | 语义不许藏在文案里 |

**两条由结构推出、不是选择的结论**：

1. **配额轴只能是 `context`。** 要凑满 10 段且受"同类最多 N 段"约束，配额轴必须是**单值** facet（多值轴的"同类计数"语义不明：一条记录命中两个值算 1 段还是 2 段）。五个单值 facet 里只有 `context` 取值数最多。
2. **`per_value_max` 是 3 而不是 2。** 5 个取值 × 2 = **恰好** 10，会把玩家锁成「每个地方正好 2 段」——没有偏科自由，而"我的大半辈子都在工地上"正是这个游戏要说的事。改成 3 后上限合计 15 ≥ 10，偏科与整类空缺都成为可能。校验器把这种"上限×取值数恰等于总额"的情形报为 `quota_forces_full_domains` 警告。

## 六、不变量与「没有工具时人肉怎么核」

> ⚠️ **没有任何门禁在跑 `validate()`**。全仓校验器已于 2026-09-17 撤销（[AGENTS.md §三](../../AGENTS.md)）。下面是人工兜底办法。

| # | 不变量 | 人肉核法 |
|---|---|---|
| I1 | `id` 唯一、形如 `exp_NNNN`、不复用 | 抄出所有 `"id": "exp_` 行排序看重复；再和 `tombstones` 对一眼 |
| I2 | 键齐备 + 无未知键 | 字段表只有 14 行；挑 3 条逐行打勾，多余键靠字段表眼看 |
| I3 | 词表收口（无未登记取值） | `grep -o '"\(context\|agency\|onset\)": "[a-z_]*"' data/opening.json \| sort -u` 与词表比对 |
| I4 | 取值可达（无死值） | 对每个取值 id「查找全部」：**计数 = 1 就是死值**（1 次是词表定义本身） |
| I5 | 多值项数范围 + 无重复元素 | 数 `relation`（0–6）`event`（1–3）`consequence`（1–6）长度 |
| I6 | `effects` 净值和 = +2、项数 ≤2、单项 ≤3 且 ≠0 | 逐条心算代数和 |
| I7 | `ability` 出口 ⟺ 属性负载非空 | 逐条看：有 `"ability"` 就必须有 `effects.attributes` |
| I8 | 文本 lint | 把「多久」「怎么发生的」「从什么时候开始」的标签抄成词表，在 `title`/`summary` 里搜一遍；再搜数字 |
| I9 | 疾病引用完整、无死疾病、每记录 ≥1 | 名册 id 逐个「查找全部」，计数 ≥2 才算有人指向 |
| I10 | 互斥形状 / 无自环 / 无重复对 / id 存在 | pair 列表**结构上**不可能不对称，只需看有无重复对 |
| I11 | 非法组合零命中 | 按第一个子句筛出候选（如 `context=school` 只有 3 条），再看第二个子句 |
| I12 | 配额轴单值 + 可达 + 存在满额合法选择 | 看 `context.multi === false`；数每个地方有几条；`canStillComplete(db, [])` 应为 true |
| I13 | 视图非空 | 照 selector 数一遍（`viewIndex(db)` 直接给） |

### 10.1 八问：问法、答案闭集、写进哪一栏

八问与答案**全部收口在 `data/opening.json`**：问法、顺序、是否参与池子在 `interview.questions`；答案闭集在 `vocab`（第 2–8 问）与 `complaint.self_report`（第 1 问）。写入位置写在 `record_shell.paper.columns[].writes[].from` 上——「哪一问落在纸的哪一行」只有那一份。

| # | 谁问 | 问（玩家可见） | 答案闭集 | 参与池子 | 写进病历的哪一笔 |
|:--:|:--:|---|---|:--:|---|
| 1 | 患者**自述** | 你哪儿不舒服 | `complaint.self_report` **18 值** | ✗ | 主诉·自述（患者笔迹）+ 主诉那一行（经拼句） |
| 2 | 病历撰写人 | 得这个病之前，发生过什么（多选 1–3） | `event` 8 值（92 种组合） | ✓ | 现病史·诱因与前驱事件 |
| 3 | 病历撰写人 | 那些事发生在哪儿 | `context` 5 值 | ✗（只排序） | 个人史·社会环境 |
| 4 | 病历撰写人 | 当时身边有谁（可空 = 一个人） | `relation` 6 值 + 空值（64 种组合） | ✓ | 个人史·人际 |
| 5 | 病历撰写人 | 那时候你能决定多少 | `agency` 4 值 | ✓ | 现病史·功能与一般情况 |
| 6 | 病历撰写人 | 这个样子，是从什么时候开始的 | `onset` 3 值 | ✗ | 主诉（经拼句）+ 现病史·发病情况 |
| 7 | 病历撰写人 | 从那以后是一直这样，还是断断续续 | `duration_pattern` 3 值 | ✗ | 主诉（经拼句）+ 现病史·病程形式 |
| 8 | 病历撰写人 | 一次能持续多久 | `duration_span` 3 值 | ✗ | 现病史·主要症状特点 |

**三条口径，每一条都是可算的**：

1. **第 1 问的答案轴不是记录 facet**（`facet: self_report`，`answer_from: complaint`）。患者自述的那个病只写进主诉栏：它拿不到任何一条记录的取值，所以它 **`matches` 必须是 false**（`interview_nonfacet_question_matches`），也**不许与 11 个 facet 重名**（`interview_facet_source_conflict`），并且必须标 `who: patient`。**界线上的一句反话**：自述能决定的只有「纸上的症状怎么写」，决定不了「他会被问出哪些条目」。
2. **参与池子的仍是三问**：`event` · `relation` · `agency`。顺序变了，池子口径一个字没变——§10.4 的四个数（30225 分支 / 24741 需放宽 / 最坏 10 段 / 最坏 4 个地方）在改序前后**完全相同**，因为池子只看这三问的答案集合，不看问题排在第几。
3. **主诉 = 自述症状 + 起病缓急 + 持续时间**（第十八条（二）的法定格式）。三个答案缺一，主诉那一行就写不出来（`complaintText` 返回 `null`，纸上是 `complaint.empty`）。

**答案侧的合法性**：`forbidden_combos` 现在同时管**答案**——「瞬时 × 持续不断」（`fc_02`）与「学校 × 伴侣」（`fc_01`）这两个组合，在那两个按钮上就是灰的。判据与记录侧共用同一份数据，不存在第二套匹配语义。

**问法的口径**：按**现病史五要素**（发病情况 / 主要症状特点 / 伴随症状 / 诊疗经过 / 一般情况，[检索记录 §5.1](../spec/material/ref/精神科入院病历-书写规范-检索记录.md)）写成临床问诊口吻，不是问卷口吻；每一问的法定依据记在 `questions[].basis.clinical`，顺序的理由记在 `basis.order`。

**自述那一问的内容纪律**（可机核，`validateComplaint`）：取值一律是患者口吻的症状说法（睡不着 / 听见别人听不见的声音 ……），**不得出现诊断名**（省级细则明文「原则上不能用诊断名称代替主诉」，检索记录 §5.6——对着 `data/diseases.json` 的 26 个病名逐条核）、不得含数字，且 18 × 3 × 3 = 162 条可能的主诉**每一条都不得超过 20 字**（实测最长 19 字）。

### 10.2 谁答哪一面：`who_answers`

`interview.who_answers` 把 11 个 facet **完全划分**成两份（不重不漏，`interview_facet_unclassified` / `interview_facet_multiply_classified`）：

| 归属 | facet | 为什么 |
|---|---|---|
| **患者答**（7） | `onset` · `duration_pattern` · `duration_span` · `event` · `context` · `relation` · `agency` | 第 2–8 问就是这七个。答的是**患者自己带来的说法**，落成病历上的「患者陈述」 |
| **院方答**（4） | `role_care` · `role_power` · `role_belong` | 谁照顾谁 / 谁说了算 / 圈内还是圈外是**事态给的位置**，由病前经历那几问答出的条目定，走院方笔迹 |
| | `consequence` | 输出槽（`output: true`）：它是结果不是处境，问诊阶段不结算 |

⚠️ **第 1 问（自述）不在这张表里**，因为表记的是 11 个**记录 facet** 的归属，而自述不是 facet。它的「谁答」写在问题自己身上（`who: patient`），判据是 `interview_question_not_patient`——所以「八问全由患者开口」这句话照样可机核，只是分了两处记。

**红线没有松，松的是「谁开口」而不是「谁定」**：记录里那 11 个 facet 的取值**一个都不由玩家写**（288 条记录全部由作者写死），玩家答的八问只是**他自己的病史陈述**，用来把已经写好的条目排先后；主诉栏里他自己那一句也只改「症状怎么写」，不改任何记录的取值。旧口径「系统定的 8 > 玩家定的 3」记的是 facet 计数，那份计数随七问退出；替它的是两条更硬的判据：① 输出槽永不在患者侧（`interview_output_facet_answered_by_patient`）；② 每个已答前缀下的池子都装得下十段（§10.4）。

### 10.3 池子口径：匹配 + 放宽阶梯

**匹配**（`interview.pool.match_basis`）：相符 = 答案与这条记录的对应取值对得上——单值问要求相同，多值问要求至少有一个相同，答「一个人」（空数组）只与「和谁」为空的记录相符。相符的问数越多，条目排得越前。

**放池子**（`interview.pool.fill_basis`）：候选按相符问数排序（同分按库内原顺序），逐条放进池子；**每个地方最多 `quota.per_value_max` 条**，**病并集不得超过 `data/diseases.json` 的 `pool_rule` 上下界**；放满 `display_size`（12）为一池。起手那一条顶破了界就换下一条重来（`pool.seed_tries`，实测需要换起手的分支占 7.7%，最多用到 8 次）。

**放宽阶梯**（每一级都有名字，`interview.pool.ladder`）：

| 级别 | 名字 | 收哪些记录 |
|---|---|---|
| `matched_all` | 每一问都相符 | 相符问数 = 已答问数 |
| `matched_drop_one` | 去掉最难相符的一问 | 去掉「去掉它之后候选最多」的那一问，其余照旧 |
| `matched_any` | 相符任意一问 | 相符问数 ≥ 1 |
| `library` | 全库兜底 | 全库都算候选，仍按相符问数排序 |

从 `matched_all` 往下走，取**第一个同时满足三条下限**的级别：

| 下限 | 值 | 来源 |
|---|:-:|---|
| 池子段数 | ≥ 10 | `quota.total`——少一段玩家就卡在既往史栏 |
| 地方跨度 | ≥ 4 | `ceil(quota.total / quota.per_value_max)` |
| 病并集 | 2–4 | `data/diseases.json` 的 `pool_rule` |

**「不用格」不等于「不用约束」**：格子退役了，判据一条没丢——它们从「每一格」搬到「每一个已答前缀」上（§10.4 的实测就是它们的可执行形式）。

### 10.4 可完成性是**算出来的**：全部已答前缀的实测

参与筛选的那几问的每一种答案状态（含「还没答」，多值问取词表允许的全部子集）都跑一遍池子。`web/scripts/pool-census.mjs` 与 `interview.test.js` 各跑一次全枚举，`validateInterview(db, ddb, { census: 'full' })` 也报同一批数：

```
参与相符判断的问   event · relation · agency
① 分支总数         30225
② 需要放宽的分支   24741（81.9%）
③ 放宽后最坏池子   10 段        （下限 10）
④ 最坏地方跨度     4 个地方     （下限 4）
池病并集 4–4（pool_rule 2–4）· 池子撑不起一局的分支 0
每一级各占多少分支 matched_all 5484 · matched_drop_one 17463 · matched_any 7266 · library 12
```

🔧 **2026-09-27 复核改：`context`（这些事发生在哪儿）退出筛选，只写病历 + 参与排序。** 原先它是筛选维之一，结果是**自相矛盾**：把「发生在哪儿」当筛子，严格相符的条目就必然只落在一个地方（实测严格集的地方跨度**中位 1、最大 1**），而配额（`total 10` ÷ `per_value_max 3`）要求池子跨 ≥4 个地方 —— 两条要求互斥，于是 96.7% 的已答前缀只能靠放宽阶梯兜住，「筛」这件事基本没发生。

改动前后的对照（同一套脚本，两组数都是实测）：

| 量 | 四问全筛（原） | 只筛 event / relation / agency（现） |
|---|---|---|
| 分支总数 | 166470 | 30225 |
| 需要放宽的分支 | 160986（96.7%） | 24741（81.9%） |
| 掉到「相符任意一问」那一级 | 119448（71.7%） | 7266（24.0%） |
| 严格全相符集的条数（中位 / 90 分位 / 最大） | 2 / 10 / 21 | 19 / 37 / 60 |
| 严格全相符集的地方跨度（中位 / 最大） | 1 / 1 | 4 / 5 |
| 严格集为空的前缀比例 | 21.9% | 2.5% |
| 池子撑不起一局的分支 | 0 | 0 |

**若将来要让「发生在哪儿」重新当筛子**，必须先换配额轴（`quota.per_facet`）——不能两样都要。这条理由与数字同时逐字写在 `data/opening.json` 的 `interview.questions[q_context].basis.why_not_a_filter` 里，改数据的人先读到它。

**四条判据现在都是池子级的**（`validateInterview()`）：池子 ≥ `quota.total` 段 · 跨 ≥ `ceil(total/per_value_max)` 个地方 · 病并集在 `pool_rule` 的 2–4 之间 · **每个已答前缀都不锁死**（`interview_pool_never_locks`）。校验器默认抽样（已答 ≤2 问全跑 + 其余抽 1/40，1 秒内），全枚举留给脚本与那一条测试。

**为什么 12 而不是刚好 10**：池子 12 段、要认满 10 段、每处最多 3 条 ⇒ 玩家必须放弃两条；3/3/3/3 的十二段池子有 66 种认法，而刚好十段的池子只有 1 种（确认按钮变成纯仪式）。

### 10.5 互斥：死条款的判据换了

旧的两对互斥是「跨格」死条款（一局的池子只装一格，两条永远见不到面），所以整块退役为空。格退役之后这句话不成立了（全库都可能进池），死条款的判据换成可算的那一条：**两条的病并集超过池子的病并集上界时，它们永远进不了同一个池子**（`mutexCanCoexist` → `mutex_never_cooccurs`）。现 `mutex` 仍为空。

### 10.6 玩家仍然「无法选择出现什么」的证据

| 由系统定、玩家看不到也改不了 | 依据 |
|---|---|
| 每条记录的 `title` / `summary` / `event` / 三个 role / `agency` / `context` / `relation` | 都在记录里由作者写死；玩家答的八问不写进任何记录的取值（自述那一问连记录字段都不碰） |
| `consequence`（留下了什么） | 输出槽，问诊阶段不结算；`who_answers` 把它划在院方侧 |
| `effects`（属性净值） | 每段固定 +2，玩家不能分配点数 |
| `diseases`（指向哪张病） | 记录里写死；玩家只能在候选里决定「要不要让它成为病」 |
| 池子本身 | 由放宽阶梯产出，**不由某一句答案关掉**；池外的记录连按钮都没有（`not_in_pool`） |

### 10.7 屏文案与判据

| 位置 | 现在写的 | 为什么合规 |
|---|---|---|
| 问诊条 | 医生问一句，你答一句；答完，病历上就多一行。 | 问的是已经发生的事，写的人不是你 |
| 既往史栏 | 医生把这些年的事一条条念给你听；你只核对哪几条属实。 + 「以上属实」 | 供史者对已写病史的确认语，不是"提交选择" |
| 病历单 | 入院记录 · 一般情况 / 主诉 / 现病史 / 既往史 / 个人史 / 家族史 / 专科情况 / 初步诊断 / 患者意见 / 落款 | 栏目名逐条有法规出处（`paper.columns[].basis`） |

**机械判据**：`interview` 的**上屏文案**（`screen.*` / `questions[].ask` / `doctor` / `reanswer` / `answer_note` / 各级放宽的名字）与 `record_shell` 的整块（含嵌套）都不得出现内部实现词（`锚点` · `输出槽` · `维度` · `字段` · `facet` · `selector` …）——`interview_copy_leaks_internal` / `record_shell_copy_leaks_internal`。问诊块的**键名**不扫（它们是契约名，一个都不上屏）。
口头判据：**任何一句能改写成"我想要…"而不别扭的文案，就是违规。**

### 10.8 增删改口径

| 操作 | 改几个文件 |
|---|:-:|
| 加 / 删 / 改一条经历 | **1**（`data/opening.json`；它进不进得了某一池由池子的三条下限现算） |
| 加一问 / 改问法 / 改答案取值 | **2**（`interview.questions` + `who_answers`；新 facet 还要 `vocab` 与 `paper` 的写入位置）。⚠️ 若这一问的答案轴不是记录 facet（像第 1 问那样），就改为 **2**（`interview.questions` + 它的闭集所在的块），`who_answers` 不动——那张表只管 11 个 facet |
| 加 / 删 / 改一句**患者自述**的取值 | **1**（`data/opening.json` 的 `complaint.self_report`；问诊那一问照着它取，不留第二份） |
| 改屏文案 | **1**（问诊六句在 `interview.screen`，病历栏目在 `record_shell.paper`） |
| 改**主诉**的拼句或自述的拼接符 | **1**（`data/opening.json` 的 `complaint` 块；起病缓急与病程形式复用 `vocab` 的 label，自述复用 `complaint.self_report.values`） |
| 改**池子口径**（展示上限 / 放宽阶梯 / 起手次数） | **1**（`interview.pool`；下限本身是推出来的，不在数据里占第二位） |
| 加一个**人物来源** | **2**（`character_source.characters` + `index.js` 的渲染入口） |
| 加一个**姓名用字 / 性别取值** | **1**（`character_source.name_pool` / `character_vocab.gender.values`） |
| 加一个**玩家可填的一般情况笔** | **3**（`character_vocab` 加闭集 + `character.fields` 加登记 + `general` 加一行） |

### 10.9 校验

`validateInterview(db, ddb, { census })`（开发期函数，**没有任何 CI 在跑它**）：谁答哪一面是完全划分 · 输出槽不在患者侧 · 每一问都有栏目接着 · 放宽阶梯四级齐全 · 上屏文案不漏内部词 · 不是记录 facet 的答案轴不当筛子 / 不与 facet 重名 / 标了患者 · **全部已答前缀的池子都满足三条下限**。
🔧 **2026-09-27 阶段 3**：由 `validateAnchors()` 平移而来（格级 → 池级），函数名跟着旧口径一起退役。另两套仍是 `validate(db)` 里的**病历单与人物来源**判据（`record_shell_*` / `paper_*` / `character_*`）与 `validateComplaint(db)`（主诉 9 条）。当前实测 **0 / 0 / 0 错误**（`validateInterview` 1 条已知警告 = 81.9% 的前缀需要放宽，这是设计而非故障；`validateDiseases` 3 条既有警告）。
没有工具时的人肉核法：数两份名单的长度（7 + 4 = 11）、数放宽阶梯四级、随便挑三个前缀跑一遍 `interviewPool()` 看池子够不够十段。
