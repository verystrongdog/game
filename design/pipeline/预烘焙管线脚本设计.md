## 一、管线全貌

```
设计师参数 (--tags, --san, --type)
        │
        ▼
┌─────────────────────────────────────────┐
│  Step 1: 髓鞘化分布                       │
│  基线 m × L + 标签偏移 + 连带偏移           │
│  → 全链路完整 m 值                     │
├─────────────────────────────────────────┤
│  Step 2: 情境→链路匹配 (模型 A)              │
│  分层门控 + L3+ 噪声 ε ~ N(1.0, 0.3)       │
│  → 每条链路在每个情境下的 rel 值              │
├─────────────────────────────────────────┤
│  Step 3: Softmax 采样                     │
│  P(i) ∝ exp(β × m_i × rel_i)             │
│  不放回多选 (Luce's choice axiom)           │
│  → 每情境×每SAN段的链路配置抽样              │
├─────────────────────────────────────────┤
│  Step 4: 校验 + 聚合                       │
│  至少1条输出 / 不能全输出 / 恐慌 flee×3      │
│  ≥1% 截断去重                              │
│  → 配置级概率分布表                         │
└─────────────────────────────────────────┘
        │
        ▼
  输出 JSON (npc_<name>.json)
```

## 三、Step 1: 髓鞘化分布计算

### 3.1 基线

所有 NPC 从分层基线出发，与玩家起始髓鞘化对齐（[核心机制 §十](../rules/%E6%A0%B8%E5%BF%83%E6%9C%BA%E5%88%B6.md#十数值基线)）：

| 层级 | 基线 m 范围 |
|------|-----------|
| L0 | 0.15–0.30 |
| L1 | 0.10–0.25 |
| L2 | 0.05–0.20 |
| L3 | 0.10–0.25 |
| L4 | 0.00–0.05 |
| L5 | 0.00–0.05 |

具体值由 NPC 类型确定——杂兵在每个范围内取随机值；Boss/友方可由设计师逐条指定。

### 3.2 标签偏移

```
m_final(i) = m_base(L_i) + Σ tag_offset(t, i) + collateral(i)

tag_offset(t, i):
  +main_offset   if i ∈ core_links(t)   (主偏移 ±0.4)
  0              otherwise
```

多标签叠加规则：取绝对值最大者，不累加（[NPC AI §4.2](../rules/skill-tree/NPC%20AI%20%E8%A1%8C%E4%B8%BA%E6%A8%A1%E5%9E%8B.md#42-6-标签设计师界面)）。

### 3.3 连带偏移

自动计算：与核心链路共享源或靶脑区的其他链路，自动获得连带偏移 `±0.15`。

```
collateral(i) = ±0.15  if ∃ t, ∃ j ∈ core_links(t):
                          (regions_a(i) ∪ regions_b(i)) ∩
                          (regions_a(j) ∪ regions_b(j)) ≠ ∅
                        AND i ∉ core_links(t)
```

## 四、Step 2: 情境→链路匹配（模型 A）

### 4.1 分层门控

```
         ┌─ L0     : rel = 2.0    if region_intersection ≠ 0  else 0.5
         │  L1     : rel = 1.5    if region_intersection ≠ 0  else 0.5
         │  L2     : rel = 1.3    if region_intersection ≠ 0  else 0.5
rel(i,s)─┤  L3-L4  : rel = 1.0×ε  if region_intersection ≠ 0  else 0.5×ε
         │  L5     : rel = 1.0×ε  (不受脑区匹配约束)
         └─

region_intersection = regions(link_i) ∩ key_brain_regions(situation)
ε ~ N(1.0, 0.3), 截断到 [0.2, 2.0], 每链路每采样轮次独立抽取
```

**设计原则**：
- L0-L2 反射/边缘链路：脑区命中 → 大幅提升权重（自动激活倾向）。不命中也保留 rel=0.5（不排除）。
- L3-L4 感知皮层：脑区命中 → 标准权重 × 噪声。噪声 ε 是涌现意外行为的核心机制。
- L5 整合皮层：不受脑区匹配约束，总是 rel=1.0×ε。高层策略链路在任何情境下都是候选。

**ε 的神经基础**：蓝斑核去甲肾上腺素相位发放的随机爆发性（Aston-Jones & Cohen, 2005, *Annu Rev Neurosci*），噪声幅度 30% 对应 LC-NE 相位模式的 burst 变异性。

### 4.2 脑区名称规范化

`situation_primitives.json` 中所有 `key_brain_regions` 名称已规范化为 `brain_regions.json` 的 functional_id（2026-08-03 迁移完成，204 个脑区名转换零错误）。详见 `code/tools/migrate_zh_to_functional.py`。

## 五、Step 3: Softmax 采样

### 5.1 权重公式

```
w(i) = m(i) × rel(i, sit) × (1 ± 5% jitter)
```

### 5.2 Softmax 概率

```
P(link_i) = exp(β × w_i) / Σ_j exp(β × w_j)
```

### 5.3 β 动态模型

β 受 SAN + 标签双重驱动：

```
β = clamp(β_base(SAN) + Σ β_tag_mod, 0.1, 5.0)

β_base(SAN):
  SAN ≥ 60  → 3.0   (高确定性战术选择)
  SAN 30-59 → 1.5   (中等探索)
  SAN < 30  → 0.5   (接近随机，flee 链路因 rel 高而倾向逃跑)
  SAN = 0   → 0     (均匀随机，不走 softmax)

β_tag_mod:
  抑制不足    → -0.8   (冲动，缺乏选择一致性)
  敏化-奖励    → -0.4   (奖赏驱动型冲动)
  社交钝化    → -0.2   (缺乏情境线索调谐)
  敏化-威胁    →  0     (不直接影响果断度)
  反刍        → +0.3   (固着于内在思维回路)
  过度抑制    → +0.6   (过度控制，行为刻板)
```

**效果范围**：一个"抑制不足 + 敏化-奖励"的 SAN 正常 NPC 的 β = 1.5 - 0.8 - 0.4 = 0.3（接近恐慌级随机）；"过度抑制 + 反刍"在 SAN≥60 时 β = 3.0 + 0.6 + 0.3 = 3.9（极其刻板）。

### 5.4 不放回多选

对于每回合的链路配置选择，使用 **Softmax 乘积近似**（Luce's choice axiom, Luce 1959）：

1. 计算全链路的 P(i) = softmax(β × w_i)
2. 按 P(i) 不放回抽样一条链路
3. 扣除其聚焦成本
4. 在剩余链路中重新归一化 P(i)
5. 重复直到聚焦容量耗尽
6. 配置概率 = 各步选中概率的乘积

**选择公理保证**：当备选项 > 50 时，不放回乘积近似与严格联合概率的偏倚可忽略（Luce 1959）。

### 5.5 聚焦成本

| 层级 | 聚焦成本 | 理由 |
|------|---------|------|
| L0 | 0 | 脑干反射——不可控、最低代谢 |
| L1 | 0.5 | 边缘系统——半自动，有代谢成本 |
| L2+ | 1 | 和玩家标准一致 |

聚焦容量 = `4 + floor(SAN/30)`（[核心机制 §二](../rules/%E6%A0%B8%E5%BF%83%E6%9C%BA%E5%88%B6.md)）。

## 六、Step 4: 配置校验与聚合

### 6.1 校验规则

每次采样产出的链路配置通过以下校验：

| 约束 | 规则 | 理由 |
|------|------|------|
| **必须有输出** | 至少 1 条 `attack_*` 或 `flee` 或 `approach` | NPC 不能只感知不行动 |
| **不能全输出** | 不能全部是 `attack_*` + `approach`（无 `perceive`/`defend`/`support`） | 纯攻击配置缺乏战术趣味 |
| **恐慌特殊性** | SAN<30 且 flee 角色存在 → flee 权重 ×3 | 恐慌强化逃跑 |

校验失败 → 丢弃，重新采样。每 (情境, SAN段) 至少收集 N=200 个有效配置。

### 6.2 聚合与截断

```
配置出现频率 → 归一化为概率分布
  → 截断: 丢弃频率 < 1% 的配置
  → 配置数 ≈ 20-50 (覆盖 ~90% 概率质量)
  → 尾部回退到 default 配置 (仅 L0 强制激活链路)
```

### 6.3 SAN=0 的特殊处理

SAN=0 时：从全链路中均匀随机不放回采样，仅受聚焦容量约束。不查 Softmax 概率表。输出中 `"zero": null` 标记此行为。

```json
{
  "template_id": "threat_patient_mild",
  "baked_at": "2026-07-31",
  "parameters": {
    "tags": ["threat_sensitization"],
    "san_baseline": 50,
    "type": "grunt",
    "beta_profile": {"high": 3.0, "normal": 1.5, "low": 0.5, "panic_flee_boost": 3.0}
  },
  "san_segments": {
    "high": {
      "acute_threat": {
        "configs": [
          {"links": [12, 45, 78, 103], "probability": 0.23},
          {"links": [12, 45, 89, 103, 156], "probability": 0.15}
        ],
        "default": [12, 45]
      }
    },
    "normal": { },
    "low": { },
    "zero": null
  }
}
```

### 运行时查表逻辑

```
1. 确定当前情境主导原型
2. 读取 NPC 当前 SAN 分段
3. 查表: (situation, san_segment) → 配置列表
4. 骰 [0,1) 随机数 → 按 probability 累积分布滚动 → 命中配置
5. 未命中（尾部 ~10%） → 使用 default 配置
6. SAN=0 → 完全随机均匀采样，不查表
```

## 八、dry-run 中间产物

首次运行时输出以下中间数据供检查：

1. **髓鞘化分布摘要**：按层级统计 m 的 min/mean/max，标注标签覆盖链路的 m 值分布
2. **情境匹配热力图**：27 情境 × N 链路（按层级分组）的 rel 值矩阵（采样前静态计算部分）
3. **采样收敛报告**：每 (情境, SAN段) 的有效采样次数、丢弃次数、配置去重数
4. **β 配置报告**：各 SAN 段 × 标签修正后的最终 β 值

用 `--dry-run` 标志触发。

## 七、技能效果验证（派生输出，2026-08-03 Grilling #20）

> 技能效果验证并入管线（§7.2 第 6 项落地，D21 质量门禁）。管线 Step 1-3 已有链路 m×rel 计算，技能效果作为**派生输出**——不新增模拟器。

### 7.1 输入

- `link_contexts.json`：链路 → 上下文集合映射（网络 × 主导角色）
- 管线的 Step 1 输出：全链路的完整 m 值
- 聚焦状态：构建层配置（玩家聚焦链路集）

### 7.2 计算

```
对每个候选技能上下文 (network, role):
  skill_links = {link | (network, role) ∈ contexts(link)}
  skill_effect(context, situation) = Σ_{i ∈ skill_links} m_i × focus_i × rel(i, situation)
```

### 7.3 输出

- `skills_<npc>.json`：候选技能清单 + 各情境效果数值
- 质量门禁：每个技能必须能计算效果数值，否则标记 `UNVERIFIED`（不算完成）

### 7.4 与 NPC 行为表的关系

- 技能效果是**玩家侧**的派生输出；NPC 行为表（主输出）不变
- 两者共用 Step 1 的 m 计算——单份链路状态，两个消费端
