**🔧 修正（2026-09-12，探针实测）：`Sit To Stand.fbx` 可用，原「无可用槽位」结论已作废。**

原结论出自原 Windows 拷贝的实现（`AnimatorWalker` 注释：「`Sit To Stand` clip 与坐下 clip 的坐姿基准不匹配，接缝下陷/跳动，实测多次仍无法干净衔接，故弃用」）。该结论**方向正确但从未留下读数**，探针把它量化了，并找到了真因与修法：

- **真因**：Unity 的 root motion 参考系是**各 clip 自己的首帧**。`Stand To Sit` 首帧 = 站姿（`RootT.y` 0.97545）→ 姿势基准归一化到站姿；`Sit To Stand` 首帧 = 坐姿（0.65010）→ 归一化到坐姿。两者**姿势基准差 0.337 m**，链式播放必然跳。实测接缝不连续量 = **0.338 m**（Sit 末帧 `hipsY` 0.5921 → Stand t=0 0.2551）。
  - ⚠️ 注意不要与另一个量混淆：两条 clip 的位移增量 `ΔY`（−0.32773 / +0.32944）与 `ΔZ` 是**严格互逆**的（差 1.7 mm / 3.6 mm），所以 **transform 往返是干净的**（实测 −0.328 + 0.329 = +0.0018）；**不干净的是姿势基准**。两个量不同，不能互推。
- **修法 ①（Y 烘进姿势，已落地）**：把两条 clip 的 **Root Transform Position (Y) → Bake Into Pose** 打开（`ModelImporterClipAnimation.lockRootHeightY = true`），XZ 与旋转不动。
  - 效果：`applyRootMotion = false`（ActionLab 原口径，无需改）+ CharacterController 保持启用 → 坐姿成立（`hipsY` 0.5921、足底落地），接缝不连续量 **0.338 m → 0.0177 m**（↓19×；Y 分量 337 → **7.2 mm**）。
  - **这不是「例外」，是补上原口径缺的一步**：`applyRootMotion = false` 要求垂直由姿势承载（Y 烘入），水平仍归 CharacterController（XZ 走 root motion 但被丢弃）。此前没做这一步，坐/起才被迫开「接管 root motion」的例外（禁 CC + `OnAnimatorMove`）。**现在那个例外不需要了。**
  - ⚠️ `.meta` 里**没有 `lockRoot*` 字段**，烘焙策略是经 `keepOriginal*` 反相序列化的，且 `clipAnimations` 的读回值不代表写盘值——**只有 Play 实测能验**。
- **修法 ②（裁末帧，已落地）**：`Sit To Stand.fbx` 的 `lastFrame` 68 → **54**（clip 长度 2.2667 → 1.8000 s）。原因：末 20% 是一段「漂」——t=0.80 时 `footLow` +0.0042 / 躯干 3.8°，到 t=1.00 变成 +0.0175 / **13.9°**（脚离地、躯干前倾、髋继续升）。裁掉后末帧 = 躯干 **4.0°**、`footLow` **+0.0021 / +0.0105**（接地）。
- **修法 ③（三段同源，已落地）**：三段链 = `Sit`（派生件反转）→ `SitIdle`（循环）→ `Stand`（原件）。**原件 `Stand To Sit.fbx` 不接线**——它的坐姿端与 `SitIdle`/`Sit To Stand` 不同族（踝前后差 149 mm、膝角差 17.6°）。
  - **为何用派生件而不是负 `AnimatorState.speed`**：实测在**非循环**状态上设 `speed = -1`，Unity 把时间钳在 [0, length]，状态**卡死在 clip 首帧**（`normalizedTime` 却一路涨到 2.4+）；`CrossFade(…, normalizedTimeOffset: 1f)` 与 `CrossFadeInFixedTime(…, 秒偏移)`、`Play(state, 0, 1f)` 三种进入方式**全部无效**。而派生件是**正速度**播放，无此问题，且 `humanMotion=True` 得以保住（Humanoid 曲线可整体反转）。
  - **派生件规格**：`Assets/Animations/Derived/SitDown.anim`，由 `code/unity/Assets/Editor/DerivedClipBuilder.cs` 非破坏生成（菜单 `YANTF/动作演示/重建派生动画（SitDown 倒放）`）；`VerifyDerived()` 现场重算并与磁盘资产**逐曲线比对**（130 条），不一致即报错——源 clip 的导入设置被改、或派生件被手改，都会被抓到。
- **残留**：起身末帧髋高 1.0354 vs 当前 Idle 的 1.0126（**+23 mm**）。⚠️ 此处**不是 bind pose**——`Idle` 态在工程里播的是 **KI 的 `HumanM@Idle01`**（2.700 s），而坐立三段是 Mixamo；**这是状态机里混了两个动捕家族的差**。切完 [#139](https://github.com/verystrongdog/game/issues/139)（locomotion 整条切 Mixamo）后该残差会变。
- **两条 Mixamo 坐立 clip 不是严格的一对**：坐姿端髋高仅差 7.2 mm，但**膝角差 17.7°**（98.5° vs 116.2°）→ 各自按不同坐面高录制。「坐姿不匹配」主要在**腿的构型**，不在髋高；导入设置只能对齐根位，对不齐腿的构型（后者由足 IK 兜底，见 §四·乙）。

**这把「近似镜像动作误配更隐蔽」的担心坐实了**——但同时说明：**判「不可用」需要读数，一句「实测多次仍无法衔接」不足以锁死一条已入库资产。**

## 三、词表元规则

### 3.1 分层判定（二维）

- **Q-a 消费端就绪度**：现役消费者在驱动？若无，是否在已排期路线图（设计已闭合/批次已列）？
- **Q-b 动画来源就绪度**：现成资产可引用，还是缺口（采购/制作/程序化）？

| Q-a | Q-b | 层级 | 处理 |
|---|---|---|---|
| 现役 | 现成 | L1-引用 | 本期接 clip |
| 现役 | 缺口 | L1-制作 | 本期补缺口 |
| 已排期（设计闭合） | 现成 | L2-登记 | 锁名 + 资产锚，不制作 |
| 未排期 或 形态未设计 | — | 不入表 | 扩展协议快轨 |

### 3.2 分类枚举（受控）

`category ∈ {locomotion, combat, reaction, social, interaction, status}`——词条必带，可按类检索；新类出现走扩展协议。

### 3.3 扩展协议（元规则，Grilling #123 用户采纳）

1. **命名只增不删**：动作 id 发布后不改名；改名/删除走 `🔧 修正注记`（同决策树闭合后修正机制）+ 全项目一致性清扫。
2. **新增 = 快轨**（不等 grilling，沿 term_registry 即时更新惯例）：提出须满足三条件——(a) 有正典来源或呈现形态定义，(b) 命名符合词表规范，(c) 声明状态（L1/L2）与来源；裁决后入表。仅当触碰命名规范或新资产采购/制作 → 升级 grilling。
3. **状态迁移**：L2→L1 触发 = 消费端就绪（批次/issue 启动）；L1 动画落地单独走实施批次。
4. **防漂移校验**：PlayMode 测试断言 controller 状态覆盖全部 L1 id、每状态有 clip；AI 引用动作只允许词表内 id。

## 四、引用契约（形态 A + 形态 B 混合）

**分工原则**：**离散的一次性动作留 A，连续与过渡迁 B**。判定看该动作是否需要「连续参数插值」或「跨动作的姿势对齐」——不需要的不要迁移。

### 甲、契约 A（保留：一次性动作、终态）

- **Controller = 纯状态集**：零参数、零手动 transition；每动作 1 状态，**状态名 = 词表 id = 代码字符串**（三面对一）。
- **切换 = 运行时 `Animator.CrossFade(id, fade)`**（不依赖 transition）；衔接决策在 C#（`ActionPlayer`）：
  - 优先级：`Down(4) > HitReaction(3) > 一次性动作(2：物攻/精攻/坐/起身) > 持续态(1：Defend/SitIdle) > locomotion(0)`（受击/倒下可打断出招；一次性动作播放期间锁移动切态与物理位移）。
  - 一次性动作播完（计时 `clip.length + 0.05s`）→ **① 若词条声明了 `nextState` 就切它**（`Sit → SitIdle`：坐下播完要"坐得住"，而不是弹回站姿）；**② 否则** CrossFade 回 locomotion 目标态。
    - `nextState` 是本轮为坐立三段新增的字段（`ActionEntry.NextState`）。没有它，"坐在凳子上"无法成立——一次性动作的原口径一律回站姿。
    - 续切目标若是循环持续态（`SitIdle`），续切后**不锁移动切态**（与 `Defend` 同口径）。
  - **循环持续态**（`Loop == true` 的动作词条）：`TickLocomotion` 收到移动意图（`speed01 > 0`）即退出，或更高优先级动作打断。**判定按 `Loop` 标志而非硬编码 id**——新增持续态只改词表。
  - `Down` 为终态：停留末帧，须显式 `ResetToIdle()`。
- **适用词条**：`PhysicalAttack` · `MentalAttack` · `HitReaction` · `Down`（一次性）· `Defend` · `SitIdle`（循环持续态）· `Sit` · `Stand`（坐立三段的一次性段）。
- **手动侧微流程**（每动作恒定 3 步，兼作 Animator 学习）：① Create State ② 挂 clip ③ 命名 = 词表 id。

### 乙、契约 B（新增：locomotion 与过渡）

针对触发器①（连续速度/方向混合），locomotion 由「离散三态 + CrossFade」改为**参数化混合**：

- **1D Blend Tree（速度轴）**：`Idle(0) → Walk(走速) → Run(跑速)` 三点混合，单一混合相位。**取代**原来 Idle/Walk/Run 三态在阈值处硬切——硬切**不做相位对齐**，走跑换挡处会产生步频相位跳。
  - 速度阈值来源：`ActionLabDriver.walkSpeed = 3.0` / `runSpeed = 6.0` m/s（**演示常量，非正典数值**，代码位置 `ActionLabDriver.cs`）；blend tree 的三个采样点即 `0 / walkSpeed / runSpeed`。
- **层与 Avatar Mask**：**本轮不预建**。触发器②未触发——按需在 Play 反馈证实「需要边移动边出招/受击」时才加层。预建层会在没有需求时增加调试面。
- **过渡相位对齐**：B 的混合由参数驱动，不再依赖 CrossFade 的时长插值；一次性动作 ↔ locomotion 之间的切换仍走 A，其 fade 口径见 §七。
- **位移口径（🔧 已裁定：坐/起例外，须开 root motion）**：本规格原为「位移全走 CharacterController + `applyRootMotion = false`」。**实测推翻了它在坐/起上的适用性**（原 Windows 拷贝里的实现，2026-09-07）：
  - **坐下段必须接管 root motion**：临时禁用 CharacterController（默认 root motion 走 `cc.Move` 会被地面碰撞挡住 → 坐姿沉不下去、双脚离地），并由 `OnAnimatorMove` 手动把 `animator.deltaPosition` 施加到 transform。
  - **起身段走了过程性过渡**，因为 `Sit To Stand` clip 与坐下 clip 的坐姿基准不匹配（根位基准差 ≈ 0.31 m），纯姿势混合在接缝处下陷/跳动。
  - **结论**：`applyRootMotion = false` 作为**默认口径仍适用于 locomotion 与一次性上身动作**，但**凡涉及体位改变（坐/站/倒地类）的衔接，纯姿势混合不够**——这正是「姿态切换自然」在本项目里第一个被证据否定的假设。
  - 待 #137 补齐的是**数值读数**（就座落点与锚点的水平/垂直偏差）与**clean 实现**（合并两侧分叉），而不是「纯姿势混合行不行」这个方向性问题。
  - **🔧 再修正（2026-09-13，就座交互 §四·丁 引入后）：坐立三段的 XZ 根位移重新启用，但理由与 2026-09-07 那次不同。** 那次要解决的是**"沉不下去"（Y）**——已由「Y 烘进姿势」解决，故 §二 修正块"那个例外不需要了"对**就地坐**仍然成立；这次要解决的是**"从椅子前面退到坐面上"（XZ）**：
    - 就座锚点在坐面中心**前方 0.423 m**（实测，§四·丁），而实心椅子把角色挡在**离坐面中心 0.522 m**处 → 这 0.42 m 的位移正是 clip 自带的 XZ 根位移（实测 Sit 段 root `Δz = −0.3201`）。丢弃它，人只能"就地蹲下"，落点在坐面中心前方 0.423 m 的空中。
    - **口径**：按词条声明 `RootMotionXZ`（与 `nextState`/`ExitVia` 同构，**不硬编码 id**）——`Sit` / `SitIdle` / `Stand` = true，其余词条一律 false。
    - **施加方式**：`OnAnimatorMove` 取 `Animator.deltaPosition` 的 **XZ 分量**经 `cc.Move` 施加。**Y 丢弃**（仍由姿势承载）；**旋转不施加**（朝向由对齐段锁在椅子 forward——实测 Sit 的 `RootQ` 会让角色坐下后偏航 **+7.08°**，且带来 19 mm 横向漂移）。
    - **前置（实测）**：`applyRootMotion = false` 时 `Animator.deltaPosition` **逐位为 0**（实测 `(0,0,0)`，此时 `norm=2.13` 正在播 Sit）→ 驱动层必须按 `RootMotionXZ` **逐帧切换** `Animator.applyRootMotion`。故「场景侧一律 `applyRootMotion = false`」的旧口径改为「**按状态**」，`ActionPlayer.cs` 头注同步。
    - **占用期间忽略与椅子的碰撞**：就座后角色整体在坐面 footprint 内（胶囊半径 0.3117 vs 坐面半深 0.21），重叠是必然 → 不忽略则根位移被自己的椅子挡住。占用结束（`Stand` 播完）复原。
- **足部贴地（🔧 已触发并实现，2026-09-12）**：原口径为「不在本轮预建。仅在探针或 Play 证实**地面起伏**导致脚悬空/陷入时才引足 IK」。
  - **触发条件扩写（owner 裁定，2026-09-12）**：触发源不止地面起伏——**clip 与载体比例不符**同样构成触发条件。探针实测（X Bot，平地场景、与地形无关）：坐下 clip 坐姿端足底陷入**左 62.8 mm / 右 11.9 mm**、坐下中段 28.7 / 6.9 mm、起身中段 63.5 / 54.9 mm、起身末态悬空 14.7 / 34.2 mm。
  - **实现**：`code/unity/Assets/Scripts/FootGroundingIK.cs`（`OnAnimatorIK` 每帧设目标）。口径 = **只上抬不下压**——需要量 ≤ 0（已贴地或悬空）时 IK 权重归 0、完全不介入；> 0 时权重按 `blendDistance`（20 mm）爬升，目标 = 脚当前位置 + 需要量。因此可常开。
  - **前置**：Animator 所在层的 **IK Pass** 必须打开（`AnimatorControllerLayer.iKPass = true`），否则 `OnAnimatorIK` 不被调用。`ActionLab.controller` 当前为 `m_IKPass: 0`，接入时须一并改。
  - **两个实测教训（已写进代码注释防复发）**：① `Animator.SetIKPosition` **不是持久状态**，Unity 每帧重置，必须在 `OnAnimatorIK` 里逐帧设置——从外部设一次无效（实测跨真实帧读数逐位不变）；② 需要量为 0 时若仍给权重 1，求解器会为「够到脚当前位置」这个目标**把腿拉弯**（实测起身末帧膝角被拉弯 14.6°、脚反而扎入地面 9.5 mm）。
  - **效果（实测）**：坐姿足底 −60.0 / −9.1 mm → **+2.4 / +1.0 mm**（模型基准 +2.8）；左右差 51 mm → **1.4 mm**；膝角仅变 8.7° / 0.9°（腿自然前摆，非硬掰）；髋高与躯干角完全不变。起身中段 −63.5 / −54.9 → +0.9 / +0.8 mm。起身末帧原本已接地 → IK 读数与关闭时**逐位一致**（不介入，无副作用）。
  - **残留**：起身末帧右足 +10.5 mm（高于基准 7.7 mm）——「只上抬不下压」的必然结果；坐下中段左脚 −3.7 mm（求解精度残差）。
  - 试验场若换用真实起伏地形（如玫瑰花海），`groundY` 须改为**逐脚向下射线**取地表高度，而不是现在的常量。

### 丙、机器源与数据契约

- 机器源 = `data/action_set.json`：词条元数据（id / 呈现词 / category / 层级 / 循环性 / 优先级 / fade / clip 路径）+ locomotion 混合参数。
- 消费方式：**Editor 侧生成器**读它，产出 ① controller 资产 ② C# 静态表（运行时消费生成的 C#，**运行时 Unity 不跨边界读 `data/`**）。
- 生成器必须**非破坏**：只补缺失、不覆盖 Editor 侧已手调的值（否则手调成果在下次生成时被吞掉）。
- 依赖边声明见 [ARCHITECTURE.md §二](../../ARCHITECTURE.md)。

### 丁、就座交互：先找到椅子（2026-09-13）

> **要解决什么**：按 `6` 就播 `Sit`——**不看有没有椅子、也不看人在哪**。凳子位置是**烘死的常量**（`ActionLabBuilder.StoolCenterZ = −0.104`，按"角色 transform 在原点"的实测摆位 + `StoolSeatTopY = 0.4449`），所以"坐到椅子上"只在出生点成立；走开一步再按 6，人就坐在空气里。

**裁定（owner，2026-09-13）**

| # | 决策 | 依据 |
|---|---|---|
| 1 | **就座必须先"找到椅子"**：椅子是场景中具名可交互物（`ChairSeat`），提供**就座锚点**——由椅子**当前 transform 实时求得**，不烘任何世界坐标 | 玩家操控走到椅子前才允许坐；椅子被推动后锚点自动跟随 |
| 2 | **"找到"= 三条件同时成立**（按键**当帧**求值，不缓存）：① 角色到锚点水平距离 ≤ `interactRadius`；② 角色位于椅子**前侧**（`dot(角色XZ − 坐面中心XZ, 椅子 forward) > 0`）；③ 椅子**空闲**。多张椅子取**最近**的一张 | ①②的取值见下；③防两人同坐一张 |
| 3 | **未命中 → 不切态**、不改位移，HUD 提示"附近没有椅子（最近 x.xx m）" | 按键**不得**产生"原地坐下"——这正是本条的存在理由 |
| 4 | **命中 → 对齐 → 坐下**：在 `alignSeconds` 内把角色移到锚点、朝向对齐 `椅子 forward`，再播 `Sit`（其 `nextState` 续切 `SitIdle`） | 坐姿落点相对角色固定（髋在角色 transform 后方 0.103 m），**只有站在锚点上臀部才落在坐面上** |
| 5 | **坐立三段改用 XZ 根位移**（口径变更见 §四·乙 再修正） | 锚点 0.423 / 实心椅子阻挡 0.522（均实测）→ 这段 0.42 m 的"退到椅子上"正是 clip 的根位移 |
| 6 | **占用锁**：`Sit` → `SitIdle` → `Stand` 全程椅子 `isKinematic`（不可推、不可被抢占）+ **忽略与角色 CharacterController 的碰撞** | 就座后角色整体在坐面 footprint 内（胶囊半径 0.3117 vs 坐面半深 0.21），重叠必然 |
| 7 | **离座要先起身**：坐姿下收到移动意图 → 先播 `Stand`（词条新增 `ExitVia` 字段）→ 播完才回 locomotion | 「先找到才能坐」的对称要求：坐下与离座都走完整动作。`ExitVia` **按字段判定**、不硬编码 `SitIdle`（与 `nextState` 同构） |
| 8 | **三张椅子**，各带 BoxCollider + Rigidbody（可被角色推开） | 单张时"找到"与"位置烘对了"不可区分；可移动则验证锚点确实是实时的 |

**就座锚点（实测，2026-09-13，Editor 6000.5.2f1 直驱 ActionLab 场景）**

- **锚点 = 坐面中心 + `椅子 forward` × 0.423 m**（= Sit 段根位移 0.3201 + 姿势内髋后移 0.103）。
  - 测法：`applyRootMotion = true` + CC 关闭，`Play("Sit", 0, 0)` 播完 → root `(−0.0194, 0, −0.3201)`、hips `(−0.0313, 0.5993, −0.4230)`；`root − hips` 的 XZ 差 = **0.103**——**这正是旧常量 `StoolCenterZ = −0.104` 的出处**（XZ 根位移被丢弃时的"就地坐"落点）。
  - 起身段回到 `(0.0369, 0, 0.0129)`（往返残差 **39 mm**，含 Sit 段 `RootQ` 的 +7.08° 偏航）→ 每次就座都经对齐段重新定位，误差不累积。
- **实心椅子的阻挡距离 = 0.522 m**（`cc.radius 0.3117` + 坐面半深 0.21 = 0.5217；实测角色撞 0.42×0.42 实心块停在 **0.5222**，差 0.5 mm）。
  - → 角色压到椅子上时与锚点的残差 = **0.099 m**；若被**前腿**（±0.165）先挡，残差 **0.038 m**。故 `interactRadius = 0.25 m`：既容得下贴椅站立，又把**对齐位移上界**钉在 0.25 m。
- **锚点为何不能是 0.104**：0.104 是"就地坐"口径——角色须站进坐面 footprint 内（半深 0.21、胶囊半径 0.312），**实心椅子下物理不可能**。两条出路：椅子对角色不阻挡（人从椅子中间穿过去），或锚点外移到 0.423。取后者——椅子是真实障碍，"走到椅子前"这件事才看得见。

**🔧 被就座交互暴露的既有缺陷：角色整体悬浮 80 mm（已修，2026-09-13）**

- **症状（owner 目视）**：「椅子本身好像不够高」——不是椅子矮，是**人高**。
- **真因**：`CharacterController.skinWidth` 默认 **0.08**（Unity 取半径的 10%），而 CC 静止时 `transform.y ≈ skinWidth` → 整个角色被抬到地面上方 **80 mm**。实测（X Bot · Idle · Play）：站姿蒙皮足底 **+45.8 mm**、坐姿髋 **0.6790**（按 transform 在原点应为 0.5990）。而坐面高 0.4449 正是"transform 在原点"时测的 → 臀部比坐面高 **80 mm**，于是看着像椅子矮了一截。
- **为何此前没暴露**：§四·乙 的足 IK 假定 `groundY = 0` 且**只上抬不下压**——transform 被抬高后足底本就"在地面之上"，IK 判「需要量 ≤ 0」而不介入（旧读数"逐位一致"正是这条规则的结果，不等于没问题）。
- **修法**：`ActionLabDriver.SizeControllerToModel()` 把 `skinWidth` 收到 **0.005**（必须在 Awake 里、CC 落定前设；**中途改无效**——CC 只把穿插排开，不会自己往下坐，实测改到 0.02 后 3 s 仍停 0.08）。修后实测：站姿蒙皮足底 **+4.9 mm**、站姿髋高 **1.025**、坐姿臀↔坐面 **+4.8 mm**、坐姿足底 **+1.6 mm**。
- **口径提醒**：§七 的坐面高 0.4449 隐含前提 = **角色 transform 贴地**；换载体、改 CC 参数、换地面高度都要重测这两条。

**朝向判定为何从"面向"改为"前侧"**：`SitPoint.cs`（WalkerLab）的 `facingDotMin`（角色 forward ≈ 椅子 forward）在 ActionLab **不可达**——`ActionLabDriver` 每帧把角色转向**移动方向**，而锚点在椅子正面一侧，玩家走到那里必然是"面朝椅子"（点积 ≈ −1）。故判据改为**角色在椅子前侧**（半球），朝向由对齐段转过去（0.25 s 内转身就位，即"转身坐下"）。

**🔧 两个 API 陷阱（2026-09-12 实测定位，均已修；改 `ActionPlayer.cs` 前必读）**

1. **`Animator.CrossFade(name, fade)` 的第二参不是秒，是「源状态归一化时长的比例」。**
   官方参数名即 `normalizedTransitionDuration`；Manual「Fixed Duration」条逐字：不勾选时过渡时长按「**a fraction of the normalized time of the source state**」解释。
   实测（确定性 5 ms 步进量 `IsInTransition` 持续时长，`fade` 一律传 0.10）：

   | 源状态 | 源 clip 长 | `CrossFade(0.10)` | `0.10 × 源长` | `CrossFadeInFixedTime(0.10)` |
   |---|---|---|---|---|
   | Defend | 0.800 | 0.085 | 0.080 | **0.100** |
   | Jump | 1.533 | 0.155 | 0.153 | **0.100** |
   | Sit | 1.800 | 0.180 | 0.180 | **0.100** |
   | Idle | 2.700 | 0.275 | 0.270 | **0.100** |
   | SitIdle | 4.300 | **0.430** | 0.430 | **0.100** |

   → **必须用秒制的 `Animator.CrossFadeInFixedTime(name, fadeSeconds)`**。修前 `SitIdle → Stand` 实际过渡 0.52 s（本意 0.12），是"起身看着黏"的来源。修后词表 fade 就是秒。
2. **一次性动作的 `clip.length` 必须读「目标态」的长度，且不能回退读当前态。**
   `CrossFade` 发起的当帧过渡尚未注册，此时 `GetNextAnimatorStateInfo(0).length == 0`（无过渡），而 `GetCurrentAnimatorStateInfo(0)` **仍是源状态**。原实现回退读它，于是锁时长变成**源 clip** 的长度：从 `Idle`(2.7 s) 坐 → 锁 2.75 s（应 1.85）；从 `SitIdle`(4.3 s) 起身 → 锁 **4.35 s**（应 1.85）——**人已站起却多锁 2.5 s**。
   → 修法：长度读取**逐帧重试**，且**只接受 `shortNameHash` 与目标状态一致的读数**（三面对一：状态名 = 词表 id），`_activeTime` 照常累计；0.5 s 仍读不到才用兜底时长。

## 八、工程约束

- **资产区单机所有权**：`code/unity/Assets/**` 的资产（`.meta` / `.controller` / `.asset` / 场景）**由 Windows 工作区独占生成与手调**。手调成果入库要求 `.meta` GUID 两侧一致；两台机器都改资产区，合并必然 GUID 冲突。文本（`design/` `data/` C# 源码/断言）不受此限。
- **素材体积**：FBX 均重 ≈ 0.51 MB，当前 7 个 ≈ 3.5 MB。词表若扩到 30+ 条（T2/T3），需先决定 Git LFS 或改下载脚本——**当前不做**（`.gitattributes` 不存在，仓库无 LFS）。
