## 三、渲染方案

### 3.1 脑壳（几何层）

| 项 | 方案 |
|---|---|
| 来源 | **由 `code/tools/bake_brain_shell.py` 从受控载体烘焙**——`brain_regions.json` 里带 `obj_file` 的条目按**文件去重后 40 个解剖载体**（58 个 functional_id 共享这 40 份几何；来源：正典"功能变体共享同一解剖载体的坐标和 OBJ"）。⚠️ 不是把 `pial_DK/` 70 个文件全导进去 |
| **坐标空间** | **MNI 毫米**（烘焙件原尺度，实测世界包围盒 72.5 × 169.3 × 121.6）——**不在烘焙侧换算**；视图根部施加单一等比变换（≈1/90）。口径见 §8.5 |
| 形态 | **40 个区域对象挂在一个父节点下 + ≤13 个共享材质**（每个对象带 `functional_ids` / `lobe` 属性；高亮 = 换该对象的材质或 MaterialPropertyBlock）<br>实测：387,510 → **199,966 三角面**（预算 20 万）· **8 个**材质 · `.fbx` **6.4 MB** |
| 材质 | **共享材质球**（≤ 12 组，按脑叶/结构分组），透明度走同一套 shader |
| 交互 | 悬停/选中脑区 → 该区高亮（emission +），其余区半透明化（沿用层级模型 §14.4 的相机拉近规则） |
| ⚠️ 反例 | v2 世代 `.blend` 把材质**逐对象复制**成 238 个（74 节点 + 152 连线 + 12 组），**明文违反**旧规范 §6.1 与 Instanced 要求——Unity 侧不得照搬 |

### 3.2 技能节点（上下文层）

- **实例化**：71 个节点用 `Graphics.DrawMeshInstanced` / `MaterialPropertyBlock` 传 per-instance 颜色，**共享一个材质球**
- **形状/大小**：按层级 L0–L5（层级模型 §16.1 的形状列）——L0 小八面体 → L5 十二面体
- **位置**：由正典坐标管线产出（§14.1 公式；脑干核团按 §14.2 方案 A 用文献 MNI 点状放置，`mni_xyz_source: "literature_mni"`）
- **布局断言**：节点必须落在其脑区 OBJ 网格内（§14.1 硬要求）。⚠️ 旧 `.blend` 的 `verify_result.json` 实测 **44 个节点落在自身脑区之外**——这正是"没有机械断言"的代价，见 §六

### 3.3 连线（三体边）

| 原语 | 条数 | 视觉 |
|---|---|---|
| 皮层-皮层（CC） | 776 | Bezier 弧线，双向互惠体现为双线或端点双向箭头 |
| CSTC 环路 | 47 | 显式环路路径（皮层→纹状体→苍白球→丘脑→皮层） |
| 脑干广播 | 114 | 中性色系（灰蓝，按 GREEN/PINK/YELLOW 社区微调明度，D29） |
| 特权通路（PP） | 112 | 高亮管道（privileged） |
| **合计** | **1049** | 全量走**单 mesh + instancing**，不做 1049 个 GameObject |

连线样式继承层级模型 §15.2：已解锁 = 发光管道；未解锁 = 暗灰虚线（opacity≈0.2）；激活中 = 沿管道移动的光点。

### 3.4 染色（✅ 已裁，owner 2026-09-13）

```
色相     = primary_network（14 Kroell 网络 → 14 色相带，环绕色环均分）   ← D23
明度/饱和 = primary_role（8 行为角色 → 同色相内明度偏移）              ← D19
多网络    = 主色 + 次色渐变（跨色相 = 桥接）
脑干链路  = 独立中性色系（灰蓝）                                      ← D29
抽象节点  = 灰色 + 虚线（`is_design_node`）——⚠️ 实测当前 `is_design_node` **全为 0**，该规则暂时无对象
左右链路  = 同色相 + 侧向标识（L 实线 / R 虚线）
```
**红线**：颜色**只**用于区分链路上下文，不得表示情绪/态度（颜色表示情绪已废弃）。

## 四、资产形态

> 决定"仓库里放什么"与"Unity 工程里放什么"——这是本次讨论的原始问题。

| 资产 | 形态 | 来源 | 进 git？ | 进 Unity 工程？ |
|---|---|---|---|---|
| 脑壳 mesh | **烘焙后的 `.fbx`**（减面 + 共享材质；40 区域对象 + ≤13 材质） | `code/tools/bake_brain_shell.py`（✅ 已落地，实测 **6.4 MB**） | ✅ 入库时随 `.meta` 一起（见下行） | ✅ 放 `Assets/SkillTree/Models/` |

**烘焙 → 入工程的动线**（顺序不能颠倒，否则违反资产身份契约）：
```
bake_brain_shell.py --out <gitignored 的 build 目录>     ← Linux/WSL 侧，产物不入库
  → Windows Editor 导入 code/unity/Assets/SkillTree/Models/   ← 由 Editor 生成 .meta（GUID 由这台机定）
  → 提交 .fbx + .meta                                        ← 干净检出才拿得到壳且 GUID 不漂移
```
| 建模中间件 | 890 个 OBJ（278 MB） | brain-for-blender（外部可重下） | ❌ | ❌ |
| Blender 工程 | `.blend`（21 MB 正典源） | 见[脑模型资产登记](脑模型资产登记.md) | ✅ 正典源 + 冻结快照 | ❌ **不导入**——Unity 导入 `.blend` 要求 Editor 所在机装 Blender，且会给资产身份引入第三个面 |
| 节点几何 | Unity 程序化（Primitive + 共享材质） | 无资产 | — | 运行时生成 |
| 连线 | 由 `tripartite_model.json` 运行时生成 | 数据驱动 | — | 无资产 |
| 拓扑/染色数据 | JSON 直读 `data/` | 正典 | ✅（已受控） | ✅ 运行时加载，**不烘焙进场景** |

**要点**：Unity 工程只收**一份烘焙壳 + 数据**。742 MB 建模产物、74 节点旧模型、glb 快照都不进工程——快照的用途是"人看 3D 效果"与归档，不是运行时资产。

## 五、技术选型

Unity 侧实测现状（2026-09-13，[code/unity/README.md](../../../code/unity/README.md)）：**Unity 6000.5.2f1** · `Packages/manifest.json` **无 glTF 导入包** · `Assets/` 共约 9.5 MB · 唯一受控场景 `ActionLab.unity` · **资产区单机所有权**（[ARCHITECTURE.md §五](../../../ARCHITECTURE.md)）。

| 选项 | 判据 | 结论 |
|---|---|---|
| **`.fbx`（原生支持）** | 无需新包；与现有 Mixamo 管线同源；Blender 侧导出成熟 | ✅ **推荐**——脑壳走这条 |
| glTF/`.glb` + `com.unity.cloud.gltfast` | 需新增包依赖；Draco 压缩对"壳"这一步没有额外价值 | 🔶 仅在需要保留完整建模产物时考虑 |
| 直接导入 `.blend` | 要求 Editor 机装 Blender 5.x，且 `.blend` 每次保存都可能改内部结构 → 资产身份不稳 | ❌ 不用 |

导出参数（已由 `code/tools/bake_brain_shell.py` 固定）：减面目标 20 万三角面（`--tris` 可调）· 共享材质按脑叶分组 · 无动画 · **Y-up + `-Z` forward** · **保持 MNI 毫米原尺度**（见 §8.5——原写"单位 m"是错的，实测资产高 169 "单位"）· 不烘焙光照贴图 · 材质透明度走透明混合（`use_transparent_shadow=False`）。

**本次烘焙实测**（2026-09-13，Blender 5.1.2，输出到 `.scratch`，未进工程）：

| 项 | 值 |
|---|---|
| 解剖载体 / functional_id | 40 / 58 |
| 缺失文件 | **0** |
| 三角面 | 387,510 → **199,966**（预算达成率 100%） |
| 共享材质 | **8**（实际用到的脑叶组：frontal·temporal·parietal·occipital·cingulate·basal_ganglia·diencephalon·brainstem） |
| `.fbx` 体积 | **6.4 MB** |
| 核对报告 | `bake_report.json`（随产物写出） |

## 六、验收判据

> 全部**读数据**推导，不写死数字（数字会随正典演进）——写死的断言会把"数据变了"报成"实现坏了"。

| # | 判据 | 判据形式 |
|---|---|---|
| A1 | 脑壳区域对象数与受控载体一致 | 区域对象数 == `obj_file` **按文件去重**后的载体数（当前 **40**）；每个对象须带其 `functional_ids`（覆盖 58 个 id） |

| A3 | 连线数 == 三体边数（按原语分组核对） | == CC 776 + PP 112 + 脑干 114 + CSTC 47 |
| A4 | **无 per-object 材质** | 脑壳材质数 == 实际用到的脑叶组数（当前 **8**，全集 13）· 节点/连线/状态另外 ≤ 3——直接对冲 v2 世代的 238 个 |
| A5 | 节点落在自身脑区网格内 | 复用 §14.1 的空间断言（已有 [`validate_spatial.py`](../../../code/tools/validate_spatial.py) 一条先例） |

## 八、已裁定项（owner 2026-09-13）

> 四项均按本文建议裁定。**裁定即口径**——实现不得再按旧的备选走。

### 8.1 节点颜色：形状按层级、颜色按网络 × 角色

| 维度 | 依据 | 说明 |
|---|---|---|
| **形状 / 大小** | 层级模型 §16.1 | L0 小八面体 → L5 十二面体，radius 0.025 → 0.05 |
| **颜色** | **D23 的 `primary_network`（14 网络 → 14 色相带）× D19 的角色明度（8 角色）** | 层级模型 §16.1 的**颜色列视为被 D23 取代** |

理由：两条不冲突的维度各取一半——§16.1 的形状/大小列（L0–L5）与网络染色互不干涉；而 D19 明写"**3D 染色实现 → 延迟：Unity 渲染层**"，颜色本就是留给渲染层定的，D23 则是后出的染色主色决策。

⚠️ **落地时需要做的同步**：[脑功能层级模型](../../rules/skill-tree/%E8%84%91%E5%8A%9F%E8%83%BD%E5%B1%82%E7%BA%A7%E6%A8%A1%E5%9E%8B.md) §16.1 的"节点颜色"列要在该文档里就地标注"已由 D23 取代"——**本文不做跨文件改写**，避免同一事实出现两个改写者（登记在 §九 待办）。

### 8.2 视图是**两个界面**，不是一个视图的两层

> 🔧 **2026-09-13 修正**：本条原写"解剖实体层常显 + 技能上下文层按聚焦展开"。读过 [战斗界面布局](../%E6%88%98%E6%96%97%E7%95%8C%E9%9D%A2%E5%B8%83%E5%B1%80.md) §五 后按正典改写——正典把"看"与"配"分在**两个界面**上，不是同一视图的两层。

### 8.5 坐标空间口径：视图内部统一用 MNI 毫米

> 裁定：owner 2026-09-13 接受建议。**触发**：[#143](https://github.com/verystrongdog/game/issues/143) 入库时实测资产是 MNI 毫米（世界包围盒 72.5 × 169.3 × 121.6），而本文 §五 原写"单位 m"——文档与产物矛盾，且**网格与节点该用哪套坐标从未写清**。

| 项 | 口径 |
|---|---|
| 脑壳资产 | **保持烘焙时的 MNI 毫米**（不在烘焙侧换算）——等比、零形变 |
| 节点位置 | 直接取 `brain_regions.json` 的 **`mni_xyz`**（既有受控数据，与网格同空间） |
| 变换 | 视图根节点上施加**一次性等比缩放**（≈ 1/90，使大脑约 2 单位宽，与 §14.1 的游戏空间量级一致）+ 轴对齐（FBX 导出侧已做 Z-up→Y-up）。**网格与节点共用同一变换** |
| `game_xyz` / §14.1 | 明确为**点位映射**：`game_X = mni_X/90` · `game_Y = mni_Z/90 + 0.55` · `game_Z = mni_Y/126 × 0.85`（即 Z 除以 **148.2**，**非等比**）。它服务"需要在游戏世界坐标里定位的点"，**不得**当作对解剖网格的变换 |

**为什么必须写这条**：§14.1 的三轴归一化系数不同（X/Y ÷90 vs Z ÷148.2，比值 **1.65**）。若网格等比缩放而节点走 §14.1，节点与脑壳在 Z 轴**必然错位 65%**；若把 §14.1 施加到网格上，脑会被压扁 65%。两条路只有一条对：**等比变换 + 同一空间**。

### 8.4 脑壳：**不保留**全半球外壳

| 理由 | 判据（实测） |
|---|---|
| ① **零信息** | 外壳（`lh.pial`/`rh.pial`）**不在** `brain_regions.json` 的 58 条 `obj_file` 里——没有 functional_id、没有 level、报不出任何脑区，无法参与染色与高亮 |
| ② **几何代价是"契约所用那部分脑"的 1.5 倍** | 外壳 = 2 个 mesh · 289,561 顶点 · **579,114 三角面**（`lh.pial` 288,976 + `rh.pial` 290,138）。对照：契约真正引用的 **40 个载体 = 387,510 面**（外壳是其 **149%**）· 正典源全部脑 mesh（Cortex 70 + Subcortical 32）= 923,667 面（外壳占 63%）· 节点 74 个仅 15,412 面 |
| ③ **快照代价实证** | 含外壳的冻结快照 20.9 MB vs 无外壳 **13.6 MB**（+54%），换来的信息增量为 0 |
| ④ **遮挡** | 节点与 1049 条三体边分布在全脑体积内（含深部边缘系统、脑干）；再叠一层半透明壳＝双层半透明叠加，对比度下降 |
| ⑤ **v2 世代本来就没有** | 07-19 那一代已改为**逐脑区半透明着色**（`ctx_*` / `sub_*`），外壳在那时就被移除了——本次裁定是**跟随已发生的取舍**，不是新砍功能 |
| ⑥ **需要轮廓时有更便宜的等价手段** | 可再下（`pial_Full` 2 个 OBJ，21 MB，可重下）· 可再烘；Unity 侧用 **fresnel 边缘光/轮廓 shader**，或另烘一份**2 万面级减面外壳**作独立展示层 |

**边界条件（不是否决轮廓）**：若最终美术方向是"玻璃罩里的脑"（外壳在前、内部链路透出），外壳就承担视觉主体——那时走**减面外壳 + 单材质**路线，**仍不要把 58 万面塞进工程**。
