## 一、为什么要这份文档

- `design/presentation/visualization-3d/blender_assets/` 共 **742 MB，主体未受控**（`.gitignore:36` 一节 `blender_assets/`）。[REFACTOR-PLAN](../../../REFACTOR-PLAN.md) §7.3 把它判为"**本次勘察中唯一的数据丢失风险**"——无生成脚本能完整重建当前状态。

- 起因是一次提问（"之前的大脑 3D 建模哪里去了"）。答案是：**东西没丢，但它没有身份**——既没有入库范围，也没有正典指定，也没有产出核对。**当天就为此付了一次代价**（§九）。

## 三、两代视觉方案

产物分属**两代不同的视觉方案**，这是"哪份为准"必须先讲清的前提：

| 世代 | 生成器 | 材质方案 | 外壳 | 特征 |
|---|---|---|---|---|
| **v1**（07-11） | [build_brain_skill_tree.py](../../../code/tools/build_brain_skill_tree.py) | `brain_glass` + `brain_wireframe` + `node_{分支}` + `tract_unlocked`（**8 个共享材质**） | 有（`lh.pial`/`rh.pial`） | 半透明玻璃外壳 + 线框叠加，符合设计规范 §2.1 的原始形态 |
| **v2**（07-19，当前） | [build_brain_skill_tree_windows.py](../../../code/tools/build_brain_skill_tree_windows.py) | `ctx_{脑叶}` + `sub_{群组}` + 逐节点 `n_{分支}` + 逐连线 `tr_{t,f}`（**238 个**） | 无 | 改为**逐脑区半透明上色**，故不再需要单独外壳；节点与连线各自复制材质 |

## 四、正典裁定

> owner 裁定，2026-09-13。裁定口径为"**改动最少、内容最全**"——后期若有额外设计，正源不得因缺内容而不支持。

| 项 | 裁定 |
|---|---|
| **正典源** | `blender_assets/brain_skill_tree_backup_20260719_0158.blend`——74 节点 + 152 连线，是生成器产出的完整态，未做任何人工改动 |
| **权威 = 生成器** | [build_brain_skill_tree_windows.py](../../../code/tools/build_brain_skill_tree_windows.py)：2026-09-13 两次独立重建，**内容逐项一致**（顶点 533,066 · 三角面 939,079 · 节点 74 = 25/15/21/13 · 连线 152 = 89+63；GLB 侧 328 节点 · 2,800,489 顶点 · 1,026,631 三角面 · 238 材质）→ 重建链条成立，`git` 里存"源 + 一条命令"即可再生。<br>⚠️ **内容一致 ≠ 字节一致**：两次跑出的 `.blend`/`.glb` sha256 不同（Blender 写入路径等元信息），所以 §六 的 sha256 只用于辨认**磁盘上那一份**，不能当"可再产值"比对 |
| **冻结快照** | `blender_assets/brain_skill_tree.glb`（**13.6 MB**，Draco；328 节点 · 238 材质） |
| 事故件 | `brain_skill_tree_degraded_20260719_0201.blend` 保留作对照（**勿当正源**） |
| 外壳 | v2 世代**不需要**外壳（逐脑区半透明替代）；补回外壳的对照实验为 20.9 MB，本次不采用 |

**Draco 压缩实测**（同一内容集，Blender 5.1.2，几何零损失——三角面数不变）：

| 导出 | 体积 | 相对被覆盖的 187 MB |
|---|---|---|
| 无压缩 | 74 MB | 38% |
| **Draco level 6（采用）** | **13.6 MB** | **7%** |
| Draco level 10 | 12.6 MB | 6% |
| + 全半球外壳 + Draco（对照，未采用） | 20.9 MB | 11% |

→ 结论：**入库体积不是问题**。13.6 MB 远低于 GitHub 单文件 100 MB 硬上限与 50 MB 警告线，**不需要 Git LFS、不需要外置发布**。

## 七、与正典的关系（分层）

**脑模型不是一个整体**——它的三层与正典的关系完全不同：

| 层 | 内容 | 与正典的关系 |
|---|---|---|
| **几何层** | 皮层 70（DK 分区）+ 皮层下 32 + 全半球 2 个 OBJ | ✅ **就是正典的几何源**：[脑功能层级模型](../../rules/skill-tree/%E8%84%91%E5%8A%9F%E8%83%BD%E5%B1%82%E7%BA%A7%E6%A8%A1%E5%9E%8B.md) §854 明写"50 解剖实体（40 网格 + 10 脑干核团点）……完整坐标、属性数据见 brain_regions.json"，而 [brain_regions.json](../../../data/brain_regions.json) 的 obj_file 正指向这批同名 OBJ（实测 58/58 可解析） |
| **材质/灯光/相机层** | 逐脑区半透明材质、三点光、相机 | ⚪ 呈现层，中性——换一套呈现方式，机制不变 |
| **节点/连线层** | 74 个技能节点位置 + 89 功能连线 + 63 层级连线 | ⚠️ **废弃口径**：位置来自 [skill_coords.json](../../../data/skill_coords.json)（数据契约登记为 `LEGACY` / `deprecated`，见 [build_data_manifest.py](../../../code/tools/build_data_manifest.py) §LEGACY），分类是"认知/情绪/行为/终极"四分支（染色已于 2026-08-03 按 D19 改为 **Kroell 14 网络 × 8 行为角色**），且脚本的 `region_matched` 查表 **74/74 落空**（§八 缺陷 1） |

**结论**：几何/材质层**可以**按正典如实入库；节点/连线层入库时必须与本表同性质的 ⚠️ 标注，**不得作为 Unity 实现的依据**。Unity 侧实现的拓扑与染色必须来自正典（[脑功能层级模型](../../rules/skill-tree/%E8%84%91%E5%8A%9F%E8%83%BD%E5%B1%82%E7%BA%A7%E6%A8%A1%E5%9E%8B.md) + [核心机制](../../rules/%E6%A0%B8%E5%BF%83%E6%9C%BA%E5%88%B6.md) 的链路体系），不是这份 Blender 模型。

## 八、重建命令与已知缺陷

### 8.1 重建（2026-09-13 实测跑通，产出与正典源逐项一致）

```bash
blender.exe --background --factory-startup \
  --python code/tools/build_brain_skill_tree_windows.py \
  -- --out <输出目录>
```

脚本本次已修：
- 路径从重构前的 `技能树系统/` 改正为 `design/presentation/visualization-3d/`；PROJECT 由脚本位置推出（跨 WSL/Windows 通用）
- **默认输出目录改为 `blender_assets/build/`，不再指向资产目录**；写资产目录必须显式 `--out`，且开跑时打印解析后的输出目录。配置只走 `--` 之后的参数——**经 WSL interop 直驱 Windows Blender 时环境变量不会传入**（2026-09-13 实测 `os.environ.get()` 为 `None`）
- **Blender 4.2/5.x 兼容修复回植**：`bpy.ops.import_scene.obj` → `wm.obj_import`、`bsdf.inputs['Emission']` → `'Emission Color'` + `'Emission Strength'`、`shadow_method` → `use_transparent_shadow`、EEVEE Next 引擎名与 Mix Shader 真透明。**这些修复此前只存在于未入库的 `C:/Users/9527/temp_build_brain_skill_tree.py`**——重建链条断在这里
- 新增**产出核对**（`verify_scene`）：把场景内容与 `skill_coords.json` 逐分支对照并打印，不一致标 ⚠。**这正是当初能拦住 02:01 缩水的那道闸**
- `.glb` 默认走 Draco（`EXPORT_DRACO`）
