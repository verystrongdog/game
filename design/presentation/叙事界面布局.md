# 叙事界面布局

> 探索与对话共存时的屏幕分区、阅读节奏和输入反馈。本文只定义呈现层，不新增剧情状态、检定公式或正式玩家行为。

## 一、目标与边界

叙事界面需要同时保留两个注意对象：玩家正在身处的医院，以及人物此刻说出或被玩家感知到的内容。界面采用“左侧世界、右侧叙事流”的稳定结构，使对话发生时不切走场景，也不把世界降为对话框背景。

左侧是**可行走的探索层**（不是静景背景板）：玩家角色在楼层空间里移动，靠近对象才浮出交互提示。这条来自[空间与关卡设计](../space/空间与关卡设计.md) §6.4「住院楼 1F 全开放：玩家醒来的楼层全部可走」与 CP-01 的 must-prove 第 3 条（探索、接敌、解决与结束构成连续体验）——本文只定义它**怎么呈现**，不定义它有什么内容。

原型借鉴调查型 CRPG 的阅读节奏，但不复制外部作品的素材、字体、图标或具体视觉资产。《子非鱼》的识别来自医院夜景、月光、病历纸张、低饱和青灰色与意识扰动。

本文不决定：

- 对话节点的正式文本与分支；
- 检定概率、SAN 变化或关系变化数值；
- StoryEngine 的数据契约与实现；
- 战斗 HUD 如何与叙事栏同时出现；
- 探索层的移动手感数值（移动速度、交互距离、角色尺寸等一律是**原型呈现常量**，不是规则参数）。

## 二、屏幕结构

### 2.1 宽屏

宽屏由两个永久区域组成：

```text
┌──────────────────────────────┬──────────────────┐
│                              │ 地点 / 时段 / 状态 │
│                              ├──────────────────┤
│        可行走的游戏画面        │                  │
│      （角色 / 对象 / 交互提示）  │    叙事历史流      │
│                              │                  │
│                              ├──────────────────┤
│ 场景目标 / 交互提示 / 玩家状态 │    回应选项       │
└──────────────────────────────┴──────────────────┘
```

- 左侧占主要面积，承担空间、角色移动、人物站位、环境变化和可交互物提示。
- 右侧是独立滚动容器，新内容追加到底部，旧内容保留以支持回读。
- 选择区固定在右侧底部，**历史增长不得把当前选项推出屏幕**。⚠️ 这条是硬判据：叙述栏高度必须由视口锁死（`minmax(0, 1fr)` + `min-height: 0`），**不得按内容长高**——长高会让本该滚动的区域改成改变自身高度，选项随之落到视口外且不可滚动到。
- 分栏可拖动调整，但原型阶段只验证固定比例。
- 左栏内容超出视口时由相机跟随角色，而不是让角色离屏。

### 2.2 窄屏

窄屏改为上下布局：场景在上、叙事在下。对话选项仍固定在叙事区域底部；不使用覆盖全屏的模态框。

窄屏下浮层元素需避让文字：原型角标与操作提示不得压住地点标题、时段读数或「当前承诺」。

## 三、叙事信息层级

右侧叙事流只使用以下类型：

| 类型 | 作用 | 呈现 |
|---|---|---|
| 说话者 | 建立当前社会关系 | 姓名、小型身份描述、可选肖像占位 |
| 客观描述 | 对应剧情节点 `text` | 常规正文 |
| 感知文本 | 对应 `perceptions` | 与客观描述分层，标明感知来源 |
| 内在反应 | 玩家角色内部的竞争性解释 | 独立标签与边线，不伪装成客观事实 |
| 系统回声 | 线索、承诺、自问变化 | 短句提示，可进入笔记本复查 |
| 玩家回应 | 当前可选行动 | 编号、回应正文、已知前提；未知后果不预告 |

感知文本必须遵守[剧情系统设计 §3.11](../events/剧情系统设计.md)的客观层与呈现层分离；界面可以让两层看起来不同，但不得把感知版本写成世界真相。

**分层靠形状与边线，不靠颜色**（颜色只作辅助）：客观描述为常规正文；感知文本带独立框与来源标签；内在反应为虚线左边线、无框，与感知文本在形状上分开；系统回声为短提示；玩家回应为带编号的锁定条目。

## 四、交互规则

1. **探索层输入**：点击地面移动，或用键盘走动。角色靠近对象（进入交互距离）后浮出交互提示，确认键或直接点击该对象触发交互；点击对象时角色先走到该对象再触发。
2. **对话与移动互斥**：对话期间移动锁定；会话结束后恢复走动，但已发生的会话不回滚（[剧情系统设计 §3.7](../events/剧情系统设计.md)）。
3. **键盘分区**：探索态方向键驱动移动；对话态、或焦点在叙事栏内时，方向键与翻页键用于回读叙事流，不再驱动移动。
4. 点击回应后，该回应进入历史流并锁定，随后追加 NPC 或环境反馈。
5. 当前选项支持数字键选择；焦点状态必须同时具有形状、边线或位移反馈，不能只依赖颜色。
6. 对话与场景不互相遮挡。对话期间左侧允许发生灯光、站位、人物注视等呈现变化。
7. 叙事栏支持三种回读输入：滚轮 · 方向键/翻页键（对话态）· 按住上下拖拽；滚动条本身必须可见可抓。
8. “对话 / 笔记”页签只切换右栏内容，不暂停或回滚世界状态。
9. 笔记页直接复用[任务目标系统 §二](../events/任务目标系统.md)的承诺、线索、自问三层，不新增第四种任务分类。
10. 离开会话后状态不回滚，符合[剧情系统设计 §3.7](../events/剧情系统设计.md)的会话语义。

## 五、原型场景

原型使用住院楼 1F 夜间走廊与护士站作为无正典效力的演示内容：

- 左侧是**可行走**的走廊（点击移动 / 键盘走动，相机跟随），带病房门、储物间、窗、护士站台面与走廊尽头没有编号的门；门与台面、治疗车等占地物件有碰撞，角色不能穿过；点击被障碍挡住的物件时角色会绕过障碍（直线路径被占地矩形截断则取一个外角绕行）；
- 靠近对象浮出交互提示；观察结果写进右侧叙事流，并可记入笔记本；
- 可观察对象不止门与台面：治疗车、墙上排班表、地上半干的水印各自带独立文案与线索；与值班护士的对话为**三层决策**（第一层 4 个回应，第二层各 3 个，其中两条主线再进第三层各 2 个），共 12 个不同结局；对话结果改写场景底部的「当前承诺」；
- 右侧实现 [§三](#三叙事信息层级) 的**全部六种**叙事类型；
- 「笔记」页演示承诺、线索、自问三层，条目由实际观察与对话结果驱动，而非写死的示例；
- 原型为**单文件自包含 HTML**：无外部资源、无网络依赖、无构建步骤；
- 「重看这一段」可重置演示，用于逐条比较不同回应的后果；
- 所有文案只用于验证阅读与交互，不进入故事正典。

## 六、验证问题

原型评审只回答以下问题：

1. 玩家能否在阅读对话时仍持续感知自己身处医院空间？
2. 右侧长文本是否具有清晰的说话者、感知层与选择层级？
3. 选择后的反馈是否同时作用于叙事流和左侧场景？
4. 对话与笔记切换是否足够直接，且不让玩家误以为世界暂停或回滚？
5. 在桌面宽屏与手机窄屏上，当前选项是否始终可达？
6. **玩家能否在不看说明的情况下知道角色可以走动、以及哪些对象可以交互？**

其中第 5 条的「选项始终可达」与浮层是否遮挡文字，可在无头浏览器里机械判定（判据示例：选项底边 ≤ 视口高、浮层与文字墨迹矩形不相交、可交互对象在屏幕中心点的命中测试通过）。**机械判定只覆盖几何与可达性，不等于目视通过**——文风、节奏与观感仍由 owner 判断，本文不把机械读数当审美结论。

本原型通过不代表玩家行为已准入，也不替代 Slice must-prove 或绑定 build 的试玩证据。
