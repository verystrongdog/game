# 叙事界面布局

> 探索与对话共存时的屏幕分区、阅读节奏和输入反馈。本文只定义呈现层，不新增剧情状态、检定公式或正式玩家行为。

## 一、目标与边界

叙事界面需要同时保留两个注意对象：玩家正在身处的医院，以及人物此刻说出或被玩家感知到的内容。界面采用“左侧世界、右侧叙事流”的稳定结构，使对话发生时不切走场景，也不把世界降为对话框背景。

原型借鉴调查型 CRPG 的阅读节奏，但不复制外部作品的素材、字体、图标或具体视觉资产。《子非鱼》的识别来自医院夜景、月光、病历纸张、低饱和青灰色与意识扰动。

本文不决定：

- 对话节点的正式文本与分支；
- 检定概率、SAN 变化或关系变化数值；
- StoryEngine 的数据契约与实现；
- 战斗 HUD 如何与叙事栏同时出现。

## 二、屏幕结构

### 2.1 宽屏

宽屏由两个永久区域组成：

```text
┌──────────────────────────────┬──────────────────┐
│                              │ 地点 / 时段 / 状态 │
│                              ├──────────────────┤
│          游戏画面             │                  │
│                              │    叙事历史流      │
│                              │                  │
│                              ├──────────────────┤
│ 场景目标 / 交互提示 / 玩家状态 │    回应选项       │
└──────────────────────────────┴──────────────────┘
```

- 左侧占主要面积，承担空间、人物站位、环境变化和可交互物提示。
- 右侧是独立滚动容器，新内容追加到底部，旧内容保留以支持回读。
- 选择区固定在右侧底部，历史增长不得把当前选项推出屏幕。
- 分栏可拖动调整，但原型阶段只验证固定比例。

### 2.2 窄屏

窄屏改为上下布局：场景在上、叙事在下。对话选项仍固定在叙事区域底部；不使用覆盖全屏的模态框。

## 三、叙事信息层级

右侧叙事流只使用以下类型：

| 类型 | 作用 | 呈现 |
|---|---|---|
| 说话者 | 建立当前社会关系 | 姓名、小型身份描述、可选肖像占位 |
| 客观描述 | 对应剧情节点 `text` | 常规正文 |
| 感知文本 | 对应 `perceptions` | 与客观描述分层，标明感知来源 |
| 内在反应 | 玩家角色内部的竞争性解释 | 独立标签与边线，不伪装成客观事实 |
| 系统回声 | 线索、承诺、自问变化 | 短句提示，可进入笔记本复查 |
| 玩家回应 | 当前可选行动 | 编号、回应正文、已知前提；未知后果不预告 |

感知文本必须遵守[剧情系统设计 §3.11](../events/剧情系统设计.md)的客观层与呈现层分离；界面可以让两层看起来不同，但不得把感知版本写成世界真相。

## 四、交互规则

1. 点击回应后，该回应进入历史流并锁定，随后追加 NPC 或环境反馈。
2. 当前选项支持数字键选择；焦点状态必须同时具有形状、边线或位移反馈，不能只依赖颜色。
3. 对话与场景不互相遮挡。对话期间左侧允许发生灯光、站位、人物注视等呈现变化。
4. “对话 / 笔记”页签只切换右栏内容，不暂停或回滚世界状态。
5. 笔记页直接复用[任务目标系统 §二](../events/任务目标系统.md)的承诺、线索、自问三层，不新增第四种任务分类。
6. 离开会话后状态不回滚，符合[剧情系统设计 §3.7](../events/剧情系统设计.md)的会话语义。

## 五、原型场景

原型使用一处可连续探索的三层医院作为无正典效力的演示内容：

- 左侧三维环境采用 AWS RoboMaker Hospital World 的两套建筑平面、护士站、电梯和病房隔帘；CC0 套装不再以整间房的原始坐标自动混入，而是由素材目录按 GLB 节点实例拆成可独立布置的家具与设备；
- 玩家可打开“布置医院”，在当前楼层放置、选中、平移、旋转或删除单件素材；选中后可直接按住物体沿楼层平面拖动，也可使用变换轴、旋转按钮或方向键微调，并可在关闭吸附与 0.1/0.25/0.5/1 米网格间切换；布置器用轴对齐包围盒检查越界、角色当前站位、墙体冲突和家具互相重叠，冲突的变换不能落下；已放置物的包围盒同时注册到角色移动碰撞，角色不能穿过家具；合法布局按楼层保存到本地浏览器；
- 三层功能目标为：一层门诊与接待大厅，二层住院病区，三层手术与检查区；二、三层采用不同于一层的 `floor_02` 墙体和走廊平面，具体设备布局由布置结果决定；
- 等距视角的墙体剖切以角色可见性为准：只处理摄像机与角色之间实际命中的墙面，在遮挡点周围生成具有柔和边缘和时间过渡的局部透视窗，并将渐变连续传递到相邻墙段，不暴露网格切分边界；未遮挡角色的墙、窗框、楼梯和扶手保持不透明；
- 医院布置功能通过 `web/src/hospital/placement-editor.js` 的小接口接入页面；素材解析、碰撞算法和样式分属独立模块，不再继续堆入单个 HTML 实现；
- 每层的功能区、走廊与电梯厅位于连续坐标空间；玩家必须走到电梯厅或楼梯区域并使用世界交互上下楼，不设置房间或楼层界面按钮；
- 建筑布局是无正典效力的呈现资产，用于验证整层探索和叙事界面的关系，不反向定义正式医院平面、功能分区或故事事实；
- 右侧演示客观描述、NPC 台词、感知插话、玩家回应与线索提示；
- 点击不同回应产生不同的局部文本和场景光线变化；
- “笔记”页演示承诺、线索、自问三层；
- 所有文案只用于验证阅读与交互，不进入故事正典。
- 左上角“开局人物”入口按[疾病特长 §六·待办 8](../entities/%E7%96%BE%E7%97%85%E7%89%B9%E9%95%BF.md)的五屏结构，验证经历选择、属性结算、疾病候选、疾病选择与镜子总结；每段经历的原始属性净值固定为 +2，并支持 +3/−1 取舍。属性页按 0–10 结算，每张属性卡顶部保留插画空位，下方显示当前程度对应的能力描述。疾病可选数量等未决项在页面中明确标为原型口径，不写入 StoryEngine 或存档。镜子中整理疾病外观面具的设计已记录在[疾病特长 §4.5](../entities/%E7%96%BE%E7%97%85%E7%89%B9%E9%95%BF.md)，因低优先级且无既定美术/物理依赖，本原型暂不实现编辑器。
- “显示设置”提供 70%–140% 的本地亮度调节并记住选择；它只对浏览器呈现做后处理，不修改 Three/Unity 场景灯光、叙事状态或正典参数。

## 六、验证问题

原型评审只回答以下问题：

1. 玩家能否在阅读对话时仍持续感知自己身处医院空间？
2. 右侧长文本是否具有清晰的说话者、感知层与选择层级？
3. 选择后的反馈是否同时作用于叙事流和左侧场景？
4. 对话与笔记切换是否足够直接，且不让玩家误以为世界暂停或回滚？
5. 在桌面宽屏与手机窄屏上，当前选项是否始终可达？

本原型通过不代表玩家行为已准入，也不替代 Slice must-prove 或绑定 build 的试玩证据。

## 七、Unity 展示壳（先看页面）

2026-09-17 起，`ActionLab` 在 Play 时会自动挂载 UI Toolkit 展示壳：

- `Assets/Resources/NarrativeUI/NarrativeHud.uxml` 固定页面语义与层级；
- `NarrativeHud.uss` 实现宽屏左右分栏、窄屏上下布局和视觉状态；
- `Assets/Scripts/NarrativeUiPreview.cs` 只负责展示壳挂载、响应式 class 与“对话 / 笔记”切换。

这一阶段刻意不接 StoryEngine。UXML 内的地点、人物、台词、感知、线索和回应均为非正典预览内容；回应按钮不推进节点，也不写回 Q/R/F/W。后续接入真实逻辑时，应保留 UXML/USS 作为视图，把静态内容替换为 Unity 适配层提供的只读视图模型。

浏览器版不再依赖临时 Python 静态服务器。本地执行 `cd web && bun install && bun run dev` 后访问 `http://localhost:5174/`；Vite 直接托管本文件同目录下的 `叙事界面原型.html`，页面内容仍只有一个权威副本。端口与电车项目的 `5173` 分开，允许两个前端同时运行。

Unity Web 的长期集成采用“左侧 Unity 世界、右侧 HTML 叙事”的单一消息接缝；状态所有权、消息信封、生成物目录与迁移阶段见 [Unity Web 集成设计](Unity%20Web%E9%9B%86%E6%88%90%E8%AE%BE%E8%AE%A1.md)。
