# NPC 对话插件

> 一份可完成的设计契约。一场用六格围住，每一轮走面子结构，产出写好的台词。场景六格仍以 [场景化对话与任务写作方法](场景化对话与任务写作方法.md) §二为准，节点长什么样仍以 [剧情系统设计](../events/剧情系统设计.md) §3.4–§3.5 为准。本文拥有插件契约，不搬那两篇的正文。
>
> 这一步的对话对应**身份**，不对应某一个已经个性化的人。本文**不确立正式对白**。验收例不使用现有人物稿。

## 一、这一步的输入

不用现有 NPC，也不先写性格、履历或一生。一次调用只给三样：

1. **场景六格**，一场只填一次：现场变化、人物眼前目标、摩擦、隐藏欲望、玩家立场、离场余波。轮次不许改这六格。
2. **身份**：谁在问，谁在答，这一场各要保住什么。这是角色，不是履历。
3. **一条事实**：会改变这一场动作或说法的那一件，写成闭集。眼前目标和隐藏欲望是它落脚的地方。

`fact_ref` 指回这条事实，或指回当场身份。闭集之外的童年、家事、诊断、语言指纹，不许进入台词。没有这条事实时，输出会变成与这一场无关的职位套话。有了它，对话仍然对应身份，不对应某一个独特的人。

哪些经历塑造性格，仍由人判断（剧情系统 §4.1）。试跑结果不是定稿。

## 二、一场里的多轮

一场是六格围起来的若干轮。每一轮走 Goffman 的互动秩序（Erving Goffman, *On Face-Work*, 1955）：

```text
互动秩序
├─ 1 前提：工作共识、情境、双方身份、相互给面子的期待
├─ 2 A 的言行
│  ├─ 给予          → 节点 text
│  ├─ 流露          → 这一场已经写下的动作、语气、停顿；不另造一句
│  ├─ 自我面子
│  └─ 对 B 面子的取向
├─ 3 B 的接收
│  ├─ 收到给予、捕捉流露
│  ├─ 一致 → 常规回应
│  └─ 不一致 → 口径和流露（或和那条事实）对不上
├─ 4 B 的选择        → options 里的一个叶子
│  ├─ 保护：不拆穿、换话题、给台阶、圆场
│  └─ 挑战：追问、点破、质疑
├─ 5 A 的回应        → next 的 text，仍要有 fact_ref
│  ├─ 接受台阶
│  ├─ 防御：解释、否认、道歉、反击
│  └─ 保护 B
└─ 6 结果：共识继续，或尴尬、关系变紧、互动停下
```

上一轮的结果是下一轮的前提。分叉只在第 4 步，一轮最多三个选项。一致的一轮不写点破和追问。6 不写成 `effect`，不改 `m` / SAN / HP（剧情系统 §3.1.1）。

一条分支结束，是离场余波能用一句话说死。余波相同的分支只留一条。一场停在余波写得出来的地方。

## 三、节点

节点沿用剧情系统 §3.4 已有字段：`id`、`type`、`speaker`、`depth`、`text`、`options`。`text` 是给予。`options` 是第 4 步的叶子。`perceptions` 与 `effect` 留空。`fact_ref` 不上屏，只供核对。

`surface` / `familiar` / `core` 仍只是作者组织内容的三档深度（剧情系统 §3.5）。条件未满足时，不创建该层会话，也不提前展示选项文本。

插件交付一场的节点包，将来放在 `data/story/npcs/<说话人>.json`。StoryEngine 尚未实现（剧情系统 §六），`data/story/` 也不存在。节点包可以先算做完。

## 四、薄宿主

宿主读这一场的节点包。调用时给出六格、双方身份、那条事实。它按轮显示给予和当前选项。玩家选中一项后，按 `next` 进入下一轮。

宿主不做的事：不调用 `YouAreNotTheFish.Core`，不读 `m` / SAN，不在闭集之外现写人生，不把试跑结果写成定稿。单步播出在 `web/src/dialogue-plugin/index.js`：`validateCall`、`validatePack`、`present`、`choose`。多轮怎么串不在这个模块里。

开局门诊那一屏仍是玩家闭集（[开局经历疾病接回](开局经历疾病接回.md)），不是这个插件。

## 五、这一步留下什么

人来删。留下只看三件：

1. 六格没有被改写。
2. 每句指得回那条事实，或指回当场身份。
3. 一轮走完面子树，且没有闭集之外的新人生。

**删名测试这一步不用。** 拿掉姓名之后，换一个同身份的人也能说，在只有身份和一条事实的时候是对的。个性化、语言指纹、以及「换一个同身份的人说不出这句」，等到有个人化材料之后再用（场景化方法 §十的删名测试留到那一步）。

## 六、验收例

不用现有人物稿，不改 `design/spec/material/drafts/`，不改 `.gen.json`。下面这一场是新写的，**不确立正式对白**，也不写成某个已有 NPC 的定稿。对话对应身份。

身份：接诊医师；来诊的人。事实只有一条：近两周，醒了就再也睡不着。

六格：

| 格 | 这一场 |
|---|---|
| 现场变化 | 病历摊开，主诉栏空着，笔还没落下 |
| 人物眼前目标 | 医师要先问清最压着的那一件 |
| 摩擦 | 来诊的人可以只给一句，医师不能自己把格子填满 |
| 隐藏欲望 | 把这一栏记清楚 |
| 玩家立场 | 答这一件，或说不愿说 |
| 离场余波 | 主诉栏写下睡眠，或仍空着 |

第一轮，一致。给予：「今天主要是哪里不舒服？」流露：笔还没碰到纸。选项是常规回应「睡不好。有两个星期了。醒了就再也睡不着。」`fact_ref` 指那条事实。结果：共识继续，主诉可以写下这句。

第二轮仍用同一条事实。给予：「一夜大概能睡几个小时？」选项最多三个，其中挑战只有在口径和事实对不上时才出现。来诊的人若答「两三个小时」，余波就是主诉栏写下睡眠。若选「不愿说」，余波是主诉栏仍空着。两条余波不同，才算两条分支。

## 七、边界

- 人生因素不进入输入。#117 的结论是不能从零生成一生（[记忆生成器理论](../../reference/记忆生成器理论-可行性评审-v1.md)，该文自己标明不进游戏正典）。
- 7 参数性格、β / k / g、连接组不作为对白接口。开局与 Web 演示不得依赖这些（`AGENTS.md` §二）。
- 轨道一完成度 A1–A3（剧情系统 §4.2.1）是人物稿的标准，不是这一步的输入。这一步不提高它，也不用它筛试跑结果。
