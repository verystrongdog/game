# 一层二维门窗布置工具

> 在已确认的一层墙线与几何闭环上放置门窗组件，产出后续通行、遮挡、房间关系和三维搭建可复用的毫米坐标数据。

## 一、边界

门窗编辑器只在开发者选项中出现，不是玩家能力。它消费 `data/hospital_ref/floor-one-enclosures.json` 的平面化墙段，以墙段为吸附对象；不得重新解释、移动或删除墙线，也不得直接把几何闭环命名为房间。各建筑上传的门窗 JSON 保留在 `reference/`，经几何校验后合并生成 `data/hospital_ref/floor-one-openings.json`，作为 Web 地图的已确认基线。

已完成复核的一度端点继续保留在数据诊断中，但不再作为蓝、绿、紫色点显示在地图上。它们已经具有门洞边、开放边界或隔断墙收头语义，不再需要持续占用校图画面。

尺寸依据与规范/项目预设的区别见[医院一层二维地图门窗组件尺寸规范调研](../space/treatment-center-modeling/docs/%E9%97%A8%E7%AA%97%E7%BB%84%E4%BB%B6%E5%B0%BA%E5%AF%B8%E8%A7%84%E8%8C%83%E8%B0%83%E7%A0%94.md) §一—§四。编辑器不是施工图工具，不得显示“自动符合国标”等结论。

## 二、组件目录

`data/hospital_ref/floor-one-opening-catalog.json` 是开发期组件目录。`spanMillimetres` 是二维墙线上占用的洞口跨度，`clearWidthMillimetres` 是将来参与通行判断的有效净宽；缺少门框构造资料时，两者即使暂用同一数值也必须分字段保存。

| 组件 | 洞口跨度 | 有效净宽 | 高度 | 用途 | 性质 |
|---|---:|---:|---:|---|---|
| 普通单开门 | 900 mm | 900 mm | 2100 mm | 办公室、小房间、储物间 | 项目预设；净宽取无障碍通行下限 |
| 病房单开门 | 1100 mm | 1100 mm | 2100 mm | 病房、病室 | 医院病房门净宽下限预设 |
| 小双开／子母门 | 1300 mm | 1300 mm | 2100 mm | 病房、诊疗室、宽通行小房间 | 项目预设，活动扇 900 mm |
| 大双开门 | 1800 mm | 1800 mm | 2100 mm | 走廊、楼梯间隔断、主通道 | 项目预设，两扇各 900 mm |
| 抢救／推床宽门 | 1400 mm | 1400 mm | 2100 mm | 抢救室或明确推床通行处 | 抢救室净宽下限预设 |
| 窄／标准／宽外窗 | 1200 / 1800 / 2400 mm | — | 1500 mm | 按外墙房间开间选择 | 项目预设，规范没有统一窗宽高 |
| 室内观察窗 | 1200 mm | — | 900 mm | 护士站、观察室、走廊隔墙 | 项目预设，固定内窗 |

门扇观察窗是门的子部件，不作为独立墙洞放置；目录通过 `observationPanel` 标记需要观察窗的门。

现阶段四类窗的窗台高度均暂设为 `900 mm`，只用于保留未来三维替换需要的字段，不代表规范要求或已经从原设计图量得的尺寸；实测后应覆盖实例值。

## 三、交互

开发者选项提供互斥的“拖动画布 / 吸附描墙 / 放置门窗”模式。进入门窗模式后：

1. 先选择一个目录预设，再点击墙附近；编辑器把点击投影到最近的正交平面化墙段。
2. 最大吸附距离为 `750 mm`。组件必须完整容纳在该墙段内，不能越过墙端或与同一墙段上的已有门窗重叠。
3. 门窗中心、所属墙段、方向和实际尺寸立即显示在地图上；门用棕橙色门扇符号，窗用蓝绿色双线符号，线宽保持固定屏幕尺寸。窗的第二根识别线相对洞口线偏移 `80 mm`，仅是二维符号间距，不代表窗框或墙体厚度。
4. 点击既有组件可选中。门可“翻转开启侧”；窗不响应此动作。选中组件可删除。
5. 每次修改保存为浏览器本地草稿；“复制门窗 JSON”导出完整 `hospital-opening-layout/v1` 数据。浏览器草稿不自动取得设计正典地位，上传并通过生成脚本校验后才成为已确认基线。“恢复已上传基线”只清除浏览器草稿，不得清空已上传数据。
6. 门窗模式禁用轴网交点复制和房间闭环选择，避免一次点击执行两个动作；切回拖动画布后恢复原交互。

## 四、数据契约

每个放置实例至少保存：

```text
id
componentId
kind: door | window
wall / wallKey
orientation: horizontal | vertical
center
spanMillimetres
clearWidthMillimetres?       # 门
heightMillimetres
sillHeightMillimetres        # 窗；门为 0
openingType
activeLeafWidthMillimetres?
side                         # 门扇开启侧，+1 / -1
interiorExterior?            # 窗
openable?
accessible?
fireRated: boolean | null          # 未核定时必须为 null，不得由门型猜测
observationPanel
source: project-preset | owner-measured
```

目录预设只负责创建默认实例；实例字段必须完整落盘，使后续门的可通行关系、窗的视线/声音传播和三维替换不再依赖预设名称反推。

## 五、Module 与 seam

`opening-editor.js` 是深 Module。其 Interface 只暴露目录选择、放置、选择、翻转、删除、清空、快照与序列化；最近墙投影、容纳检查、重叠检查、稳定 ID 和草稿恢复全部隐藏在 Implementation 内。Web 地图是呈现 Adapter，只把鼠标坐标交给该 Interface 并渲染返回状态，不自行复制几何规则。

`web/scripts/build-floor-one-openings.mjs` 是 reference 到运行时数据的导入边界。它必须拒绝未知组件、重复 ID、非正交墙、脱离现有平面墙段、越过墙端、字段与目录不一致以及同墙重叠；原始上传文件保持不变。
