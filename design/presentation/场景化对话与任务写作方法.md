# 场景化对话与任务写作方法

> 把人物素材转成可探索、可中断、可回访的场景，而不是把履历拆成问答。本方法吸收《极乐迪斯科》创作资料中的可复用部分，但只服务《子非鱼》已经确立的主线、时段、地点、经历与疾病接口。

## 一、学习对象

本项目学习的不是《极乐迪斯科》的句式、怪诞比喻或技能名称，而是它把五类内容放进同一个交互场景的办法：

1. 人物正在处理的现实事务；
2. 地点中持续发生的声音、气味、光线和动作；
3. 玩家此刻采取的立场，而不只是索取信息的问题；
4. 世界对玩家过去行为的小范围记忆；
5. 一个能继续失败、回访和变形的任务结构。

这些内容在本项目已有对应接口：会话入口读取地点、时段和当前活动，见[剧情系统设计](../events/%E5%89%A7%E6%83%85%E7%B3%BB%E7%BB%9F%E8%AE%BE%E8%AE%A1.md) §3.8.1；承诺、线索、自问的分工见[任务目标系统](../events/%E4%BB%BB%E5%8A%A1%E7%9B%AE%E6%A0%87%E7%B3%BB%E7%BB%9F.md) §二；0527 案与人物的关系见[全院主线逻辑原型](%E5%85%A8%E9%99%A2%E4%B8%BB%E7%BA%BF%E9%80%BB%E8%BE%91%E5%8E%9F%E5%9E%8B.md) §四—§五。

**示范顺序必须从主角开始。** 第一份场景示范应直接拆解 owner 已写的开头原文，先确定苟智空的观察距离、感官语言、行动节奏以及《无法离开医院》如何第一次显现；这些基准稳定后，才用已经审定的人物材料扩写 NPC。不得为了演示方法，替尚未审定的 NPC 补写具体场景。

第一份实际示范见[主角开场场景示范](%E4%B8%BB%E8%A7%92%E5%BC%80%E5%9C%BA%E5%9C%BA%E6%99%AF%E7%A4%BA%E8%8C%83.md)：它保留 owner 原稿的固定事件，把月相、黑暗、绕行、昼夜切换和手环拆成可观察、可行动的连续场景。

## 二、最小创作单位是场景

一段可玩内容的最小单位不是一句台词，也不是一个话题，而是：

```text
场景 = 地点状态 + 人物当前活动 + 一处摩擦 + 玩家立场 + 状态余波
```

开始写作前先填六格，任何一格为空都暂不写对白：

| 输入 | 要回答的问题 | 反例 |
|---|---|---|
| 现场变化 | 玩家到来前，这里正在发生什么？ | “NPC站在球场等待交谈” |
| 人物眼前目标 | 他此刻想完成、避免或维持什么？ | “向玩家讲述自己的病” |
| 摩擦 | 玩家为什么不能直接取得想要的东西？ | “把所有问题逐项问完即可” |
| 隐藏欲望 | 哪个愿望影响行动，但人物不会直接说明？ | “我因童年控制而患病” |
| 玩家立场 | 玩家能做、忍住不做或误做什么？ | 只有“继续询问” |
| 离场余波 | 这次见面改变了哪项关系、线索、承诺或下次入口？ | 对话结束后一切复原 |

人物稿提供事实边界，不直接提供场景顺序。家庭史、创伤史和诊断只有在它们改变人物眼前的动作、措辞或回避时，才进入场景。

## 三、七个场景节拍

每个短场景优先使用以下节拍；可以删减，不要求机械齐全：

1. **到达**：先让地点发声，不立即弹出人物简介。
2. **识别动作**：玩家看见人物如何占用空间、重复动作或保护某件东西。
3. **第一次摩擦**：NPC 回应眼前事务，不配合作者想讲的主题。
4. **玩家表态**：说话、行动、沉默、冒犯、装懂或承认不知道。
5. **外部打断**：球滚来、广播响起、推车经过、门被打开；环境继续存在。
6. **微反应**：NPC 记住玩家刚才的具体做法，后续一句话、站位或入口因此变化。
7. **残留**：场景结束时留下可回访的问题，而不是总结人物。

环境不能只在开场描写一次。它至少应在中段改变一次谈话：让两个人共同接球、让广播盖住一句话、让气味触发回避，或者迫使 NPC 暂停正在做的事。

## 四、信息边界

每条内容写作时标记来源，避免作者真相直接落进 NPC 嘴里：

| 层级 | 玩家实际得到什么 | 可以证明什么 |
|---|---|---|
| 可观察事实 | 动作、物件、空间、声音、气味 | “现在发生了什么” |
| 玩家推断 | 经历或疾病带来的联想 | 只能证明主角这样理解 |
| 人物陈述 | NPC 愿意说出的版本 | 证明他说过，不证明内容为真 |
| 记录 | 病历、登记簿、交接本 | 证明制度留下了这种记载 |
| 不可证实解释 | 月光、身份断层、他人内心 | 只保持为解释之一 |

初见场景原则上只使用前三层。人物陈述也先围绕当下动作，不主动交代家庭与创伤。深入层不是“解锁完整真相”，而是人物允许玩家靠近一个仍然说不完整的问题。

## 五、选择写成立场

一组选项至少覆盖两种不同立场，不要求每个选项都打开新资料：

- **介入**：帮忙、制止、接住、替人完成；
- **尊重边界**：停下、不追问、把决定还给对方；
- **工具化**：把人物当证人、病例或主线捷径；
- **误读**：顺从主角经历或疾病带来的错误确信；
- **自我暴露**：承认自己也不知道、也害怕或也在撒谎。

所谓“无关紧要的选择”仍应产生质地差异：一句回访称呼、NPC 是否让出位置、是否纠正玩家、是否愿意把一个物件交到玩家手上。只有改变主线大分支的选择才被记住，会让人物显得只是一台任务机器。

## 六、检定与失败

主动检定放在场景积累出的戏剧节点，而不是放在第一句作为内容门票。玩家必须先知道自己正试图做什么、为什么困难，再面对成功或失败。

失败至少选择一种继续方式：

- 得到错误但可追查的解释；
- 事情办成了，但关系受损；
- 没有得到信息，却看见人物新的动作；
- 关闭眼前入口，打开另一个时间或地点的入口；
- 玩家说出无法收回的话，后续场景承认它发生过。

失败不得只返回“条件不足”，成功也不得等同于 NPC 交出完整背景。

## 七、任务从欲望冲突生长

任务写作先分开四件事：

| 项 | 含义 |
|---|---|
| 表面请求 | NPC 实际说出口、玩家可以承诺的事情 |
| 当下需要 | 不解决就会妨碍人物眼前生活的事情 |
| 深层欲望 | 人物未必承认，也未必能够满足的东西 |
| 主线接口 | 任务如何接触 0527 案、登记异常或“无法离开医院” |

四者不必相同。一个好任务允许玩家完成表面请求，却没有满足深层欲望；也允许玩家拒绝请求，却在另一个场景中回应了真正的需要。

每项任务建立一页路径记录：

```text
预期路径：玩家最自然会怎样发现、承诺、执行、回访
变体路径：不同时段、地点、证据顺序下怎样进入
失败路径：错过、拒绝、误解、关系受损后怎样继续
反应点：哪些旧行为只需得到一句或一个动作的回应
收束状态：承诺 / 线索 / 自问 / 关系 / 见证分别改变什么
```

“主线任务”和“人物任务”不应是两张互不相干的网。人物可以不是关键证人，却通过一次关系后果改变玩家以后如何对待记录、证词或合法程序；这正是当前主线给吴桐、周卫国、唐念安的定位。

## 八、时间、地点与回访

同一 NPC 不按“话题完成度”推进，而按世界状态重新进入。首轮只检查以下七个维度中真正相关的两到四个，不做全组合穷举：

```text
地点 / 时段 / 当前活动 / 关系层 / 已见证事件 / 玩家经历 / 玩家疾病
```

回访必须至少改变一项可见内容：人物正在做的事、开场称呼、允许靠近的距离、对旧行为的回应或可采取的行动。若只有一句“还有什么事”，该回访没有创作价值。

会话内部使用连续记录：短节点只控制阅读节奏，后续节点追加在已有内容之后；玩家选择后不应清空上一轮文本。玩家主动离开时，已经发生的微反应照常保留，下次交互重新求值入口。该行为沿用[剧情系统设计](../events/%E5%89%A7%E6%83%85%E7%B3%BB%E7%BB%9F%E8%AE%BE%E8%AE%A1.md) §3.7—§3.8.2。

## 九、从人物稿到运行时节点

一次扩写按以下顺序进行：

1. 从人物稿摘出五项可见材料：日常动作、随身物、语言习惯、回避点、未完成关系。
2. 选择一个主线需要玩家真实到访的地点，不为展示背景另造房间。
3. 填写 §二的六格场景表。
4. 先写无对白版本，确认只靠动作和环境也能看出摩擦。
5. 再写普通入口；不得使用诊断名和作者总结。
6. 加一个经历接口或疾病接口，并明确它可能误导玩家的边界。
7. 写至少一种失败继续和一种主动离开后的回访。
8. 最后检查任务状态与信息来源，才拆成运行时短节点。

每名人物“至少十二个节点”只是原型覆盖量，不是质量目标。十二个节点若只构成十二问，仍然是一段人物百科；六个能相互作用的节拍可能更接近完整场景。

## 十、审稿问题

交付前逐项回答：

1. 删除人物姓名后，这段对白还能被另一个病种的人直接使用吗？能则声音不足。
2. NPC 是否在前三轮内主动解释家庭、创伤或诊断？是则入口过深。
3. 玩家是否除了提问还能采取行动、沉默或退出？不能则不是可玩场景。
4. 环境是否在开场以后再次影响谈话？没有则环境只是布景说明。
5. 失败是否产生内容？没有则检定只是锁。
6. 玩家过去的一个小行为是否得到回应？没有则世界缺少记忆。
7. 任务完成后是否还剩一个人物无法被满足的欲望？没有则人物被任务耗尽。
8. 回访是否由世界状态改变，而非“对话次数”解锁？不是则违背当前会话模型。
9. 玩家所得信息属于观察、推断、陈述、记录还是解释？分不清则信息越界。
10. 这段内容是否让玩家更想继续行动，而不只是知道更多设定？否则应改成场景摩擦。
