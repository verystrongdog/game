### 2.2 取帧规则（三条线必须落在同一帧）

| 项 | 规则 | 来源 |
|---|---|---|
| **接触帧** `t_c` | 全段均匀采样 **41 点**，求 `argmax_t [ (右手骨位置 − 髋骨位置) 在角色 forward 方向上的投影 ]`（= 右拳相对髋最前伸的一帧），再在相邻两采样点之间**逐帧细化到整帧** | 采样点数与"曲线极值定帧 + 留痕可读"的方法沿用 [动作库规格.md](%E5%8A%A8%E4%BD%9C%E5%BA%93%E8%A7%84%E6%A0%BC.md) §四·戊 #10（「手到位帧」= 距离曲线最低点） |
| 求值方式 | 逐帧求值用该引擎的**动画采样**接口（Unity：`AnimationClip.SampleAnimation`；实测与人形采样参考 `AnimationMode` 逐位一致、差 0.000 mm） | 同上 #10 读数表 |
| 辅助帧 | `t_c − 1 帧` 与 `t_c + 1 帧`（仅用于 §三 M5 的脚滑代理量与 M6 的屈曲角） | 本文新增口径 |
| 留痕 | **整条曲线 + `argmax` + 最终帧号**必须写入证据（不得只留结论） | 同 #10 的 `LastArrival` / `LastAttachReport` 先例 |
| 轴与朝向 | 偏移与投影一律在**角色自身坐标系**里表达：`forward`（面朝）/ `right`（角色右手侧）/ `up`；**不使用全局轴名**（各引擎轴约定不同） | 本文新增口径——目的是让三份读数不因引擎轴制不同而不可比 |

### 2.3 共同目标（接触修正的靶子）

| 目标 | 定义 | 为什么是这个 |
|---|---|---|
| **右手命中目标** | 位置 = 接触帧上右手骨位置 + 角色局部 `right 0.15 m / up 0.10 m / forward 0.05 m`（模长 0.187 m） | 来源：`code/unity/README.md` §二·O 实测所用偏移 `(0.15, 0.10, 0.05) m`（该处自述**演示常量、非正典、非规格参数**）。本文把它**升为共同样本的固定项**——⚠️ 待 owner 确认（§七.1）。不固定靶子，"修正后手↔靶距离"在引擎之间没有可比性 |
| **双脚目标** | 左/右各一个：接触帧上把该脚足底最低点抬到 `地面 y + soleMargin`（只上抬；已在基准之上则不动） | 口径沿用 `code/unity/Assets/Scripts/FootGroundingIK.cs` 的"只上抬不下压"（2026-09-12 实测：需要量为 0 仍给权重 1 会把腿拉弯 14.6°、脚反而扎入地面 9.5 mm） |
| **根目标** | 见 §3.3（**首帧不变量口径**，不引入外部落点坐标） | ⚠️ 与 [#157](https://github.com/verystrongdog/game/issues/157) 原文"根落点/朝向目标"的措辞有差，待 owner 在 §七.2 裁定 |

### 2.4 场景最小构成

地面 · X Bot 载体（Animator + 该 clip）· 右手命中目标 · 左/右脚目标 · 根/髋参考 · **约束权重可切（0 ↔ 1）**——最后一条是"同帧对照"的前提（关/开两次读数必须落在同一帧）。

> ⚠️ Unity 侧硬约束（实测，代价 4 轮测试）：约束**只认已序列化进场景的 Rig**，运行时"先 `AddComponent`、后 `Add layer`"的合成搭建**静默不生效**（`Build()` 返回 `true`、层 `IsValid()`、`constraints = 1`，行为却不动）。故 lab 必须是**仓库内的场景资产**并按名加载。完整判据见 [危险点表](../engineering/危险点表.md) §六 与 [code/unity/README.md](../../code/unity/README.md) §二·O 未闭合 2。

## 三、共同观测口径

**总原则：本文只固定"量怎么取"，不设任何阈值。** 判据是"原始读数写进证据"，不是"读数小于某个数"——本仓不允许无来源的阈值（[项目规约 §二](../conventions/README.md)）。三份证据横向比较时，由路线裁定读完整读数再判断。

| id | 观测量 | 定义 | 单位 / 精度 | 取值时刻 | 现状锚点（Unity） |
|---|---|---|---|---|---|
| **M1** | 右手 ↔ 目标距离 | 右手骨位置与目标位置的欧氏距离 | mm / 0.1 | 接触帧；**约束关与开各一次** | 开 **0.0 mm** / 关对照 **187.1 mm**（§二·O 实测，目标偏移模长 187 mm） |
| **M2** | 足底相对地面高度（左 / 右） | 该脚「足骨 y」与「趾骨 y」的**较小者** − 地面 y；负 = 陷入 | mm / 0.1 | 接触帧 + 逐帧全序列 | 坐姿 **−62.8 / −11.9 mm**（`FootGroundingIK.cs` 头注，2026-09-12 探针） |
| **M3a** | 根水平漂移 | 接触帧髋骨水平位置 − **首帧**髋骨水平位置 | mm / 0.1 | 接触帧 | 未取到（本条首次取） |
| **M3b** | 根朝向偏差 | 接触帧髋骨 forward 与**首帧**髋骨 forward 的夹角 | deg / 0.01 | 接触帧 | 未取到（本条首次取） |
| **M4** | 骨长不变量 | 上臂 / 前臂 / 大腿 / 小腿各骨在父空间中的骨长；取**约束关、开两次之差**（约束不应改变骨长） | mm / 0.1 | 接触帧 | 未取到（本条首次取） |
| **M5** | 脚滑代理量 | 接触帧 → `t_c + 1 帧` 之间，足底最低点的水平位移 | mm / 0.1 | 相邻两帧 | 未取到（本条首次取） |
| **M6** | 肘 / 膝屈曲角 | 有符号屈曲角（符号约定：与源 clip 同号为正）；反关节即记录并报符号 | deg / 0.1 | 逐帧 | 未取到（本条首次取） |
| **M7** | 重开可复现性 | 重开工程 / 项目后，同一帧的 M1–M6 与关前读数是否在**该工具显示精度内**一致 | 与各量同 | 重开后 | 一致（§二·O 实测） |

### 3.1 读数纪律

- 每个量在**约束关**与**约束开**两种状态下各取一次，两次必须**同一帧**（这就是 §2.4 要有权重开关的原因）。
- 约束开的那一次，Unity 侧须在改权重后**重建约束图**（`RigBuilder.Build()`）——只设权重不重建**不生效**（§二·O 实测 3）。其余引擎记录各自的等价动作。
- **不要用冻结时间换确定性**：M1 这类距离读数对动画本身不敏感，冻结反而多一个自变量（§二·O 实测 2）。
- 报错与警告原文（不是条数摘要）一并入证据。

### 3.2 为什么不用"手位移量"当判据

手的位移量同时被动画与约束影响，分不出"约束有没有生效"；手↔目标距离不受动画本身影响，对照项（约束关时至少差多少）一眼可判。这是 Unity 侧已经踩过的坑（§二·O 实测 2），三条线统一沿用。

### 3.3 根对齐偏差的定义（首帧不变量口径）

以**源 clip 首帧**为基准，而不是以一个外部"根落点坐标"为基准：

- M3a = 接触帧髋骨相对首帧髋骨的水平位移；
- M3b = 两者 forward 的夹角。

这样"根对齐"变成一个**不变量判据**（修正不该移动根），不需要引入"根落点目标"这个新坐标，也就不需要为它造一个新常量。⚠️ [#157](https://github.com/verystrongdog/game/issues/157) 原文写的是"根落点/朝向目标"，属外部目标口径——两种口径的取舍见 §七.2。

## 六、共同禁止事项

从三条 issue 的「明确排除」收敛（任一条线违反，横向对照即失效）：

1. **不覆盖 / 不回写源 FBX**；派生件只新增（不覆盖 `Assets/Animations/Mixamo/` 下的下载件）。
2. **不套用无来源阈值**：读数进证据，不写"小于 X 即通过"。
3. **不用运行时合成搭建代替场景**（Unity 实测静默不生效），**不靠冻结帧换确定性**。
4. **不改** [动作库规格.md](%E5%8A%A8%E4%BD%9C%E5%BA%93%E8%A7%84%E6%A0%BC.md) 的词表与引用契约；**不新增动作词条**。
5. **不新增正式玩家行为、不新增 CP-01 playable**（[PLAYABLE.md](../../PLAYABLE.md) 当前 `NO_AUTHORIZED_PLAYABLE`）。
6. **不以 lab 宣称持椅交互（[#152](https://github.com/verystrongdog/game/issues/152) 暂停线）问题已解决**；不恢复或修改该暂停线的实现。
7. **不承诺"自动生成自然动作"**，也不把本线扩成跨引擎运行时抽象。
