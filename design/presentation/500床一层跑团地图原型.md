# 500 床一层跑团地图原型

> 用既有医院图纸验证二维移动、房间关系与 NPC 交谈是否足以承载开局任务。本文与对应 Web 页面都是可丢弃原型；图纸来源不是正式可玩区域清单。

## 一、来源与口径

- 原始参考页：`design/space/treatment-center-modeling/references/raw/doc7497.pdf` 第 26 页。该页经检查由矢量路径与嵌入字体组成，不是低分辨率位图。
- Web 呈现底图：从上述页面直接导出的 `data/hospital_ref/vector/page-26.svg`；放大时保持墙线与文字清晰。
- Web 交互缓存：由上述 SVG 直接栅格化生成的 `data/hospital_ref/cache/page-26-web.png`，尺寸与参考原图一致（4963×3509），并保留 SVG 的透明背景；它只用于连续缩放或平移期间替代矢量重绘。
- 原 PNG `data/hospital_ref/full/page-26.png` 保留为栅格参考，不移动、不覆盖，也不再承担 Web 地图底图职责。
- 图纸标题栏：精神卫生专科医院参考图集，500 床规模设计方案一，一层平面图，图纸页次 25。
- 仓库清单：`data/hospital_ref/manifest.json` 将该文件登记为 500 床方案一“一层平面图”。
- 原图保持不改；Web 构建时作为呈现资产引用，在其上叠加活动点。

“扫描”在本轮表示人工辨认主要功能区、建立少量逻辑地点、粗略可点区域与连通关系，不表示已经完成 CAD 级房间轮廓、门洞或尺度复刻。活动点及区域边界可在后续评审中校正。

矢量 SVG 只是图纸呈现适配器；游戏可移动地点、连通边与人物位置集中在 `web/src/hospital-map-prototype/floor-one-map.js`。移动运行时只向界面提供“读取当前视图、尝试移动”两个动作，避免将任务状态写进 SVG 路径，未来替换底图时不改移动规则。

### 校图坐标系

- 图纸坐标系跟随原始图纸，不跟随玩家对画面的旋转；旋转只改变观察方向。
- 坐标轴位置以图纸外围尺寸标尺为准：将目标柱对应的横、纵尺寸轴线向图内延长，交点才是原点 O；黑色柱截面只用于目视复核。
- 目标纵轴在 4963×3509 原图上的中心为 `x = 2302.5 px`，目标横轴为 `y = 1981.5 px`，因此原点归一化坐标为 `(46.3933%, 56.4691%)`。图纸指北针朝图面左侧，因此沿墙向南对应图面右侧。
- X 轴是通过 O 的水平线，Y 轴是通过 O 的垂直线；不再提供人工定轴流程。
- 原图的 A3 与 `1:600` 只用于校验总体比例，不直接生成游戏坐标。每条总体准线记录从原点逐段累加的图纸标注毫米值（如 `7500`、`6900`、`3000`）；轴网交点直接读取该整数毫米值，只有鼠标落在两条准线之间时才按相邻标尺段插值。X 向图面右侧为正，Y 向图面上方为正。
- X 正方向在 `+100800 mm` 之后还有一个 `2000 mm` 的末段，最末准线坐标为 `+102800 mm`，不得在 `+100800 mm` 提前截断。
- Owner 补充两条东西方向总体准线：`X = -40700 mm` 与 `X = +20500 mm`。它们分别按所在的既有分段标尺 `-51700→-38700 mm`、`+15000→+22500 mm` 做段内插值，图纸归一化位置为 `30.2492%` 与 `54.5269%`；两条线与其他总体准线一样参与交点显示和墙线采集。
- Owner 补充东西方向总体准线 `X = +82125 mm`；它位于 `+76500→+84000 mm` 标尺段的四分之三处，图纸归一化位置为 `78.9744%`，与其他东西走向准线一样全图贯通。
- Owner 补充两条南北走向总体准线：`Y = +3450 mm` 与 `Y = +51750 mm`。它们分别是既有分段标尺 `+6900→0 mm`、`+55200→+48300 mm` 的中线，图纸归一化位置为 `54.5312%` 与 `27.4366%`；两条线与其他总体准线一样参与交点显示和墙线采集。
- `X = -57700 mm` 是主体建筑与北侧供应中心的轴网接缝。该线以北（`X < -57700 mm`）不得继续套用主体建筑的南北走向准线；供应中心改用图纸最北端标尺向内延长得到的 9 条局部准线：`Y = +19500、+12000、+4500、-3000、-10500、-18000、-25500、-33000、-40500 mm`，图纸归一化位置依次为 `45.5258%、49.7435%、53.9470%、58.1505%、62.3682%、66.5717%、70.7751%、74.9929%、79.1821%`。其中 `Y = -3000 mm` 与主体轴网同线，作为两套标尺的共同锚点；主体 Y 线与供应中心局部 Y 线都在 `X = -57700 mm` 接缝处终止。东西走向准线不分区，仍可贯穿供应中心。
- 页面持续显示鼠标所在位置的 `(X, Y)`。讨论区域错误时优先使用该坐标，而不是“左边一点”“靠近某房间”等相对描述。
- Web 地图以淡色虚线延长外围标尺的主要轴线，形成校图轴网；原点轴使用较强颜色与普通轴网区分。图纸北向为图面左侧：东西走向准线按外围总体标尺贯通；南北走向准线按 `X = -57700 mm` 分区，主体建筑使用总体标尺，北侧供应中心使用最北端局部标尺，两套线不得互相穿入对方区域。
- 每个当前分区内有效的轴网交点显示小型可点击标记。悬停时显示米制 `(X, Y)`，点击或键盘确认后复制 `地图交点 X … m, Y … m`；只突出最后选中的交点，不把全部坐标文字常驻铺在图纸上。
- 内墙端点不要求落在总体轴网交点。Web 地图从现有毫米坐标轴分段插值生成一层 SVG 吸附网格；细格随倍率逐级细分：`<2× = 1000 mm`、`2–4× = 500 mm`、`4–8× = 250 mm`、`8–16× = 100 mm`、`16–32× = 50 mm`、`≥32× = 25 mm`，每 10 个细格显示一条较强网格线。细格在屏幕上的线宽恒为 `0.3 CSS px`，强调线恒为 `0.55 CSS px`；线宽必须反向补偿地图倍率，不得随放大变粗或盖住底图墙体。主体建筑与北侧供应中心分别使用各自的 Y 标尺投影，仍在 `X = -57700 mm` 接缝处分区。总体轴网继续叠在细网格上，并保留其非整格坐标（例如 `X = +82125 mm`）作为可直接点击的精确吸附点。
- 开发者选项提供互斥的“拖动画布”和“吸附描墙”工具，默认使用拖动。吸附工具启用时才显示细网格并允许点击生成墙点；普通位置点击先换算为当前分区毫米坐标，再吸附到当前倍率的最近网格点，复制为 `地图吸附点 X … m, Y … m`，并交给同一套连续描墙流程。拖动工具启用时禁止生成墙点；从吸附切回拖动时自动结束当前连续墙线，避免平移后误连。坐标文本最多保留三位米制小数，并去掉末尾无意义的零。
- 吸附光标、已选点与原点统一使用固定屏幕尺寸的细十字，不得随地图放大成圆盘或椭圆；总体准线交点的鼠标命中区固定为约 `6 CSS px` 直径，不得使用包含相邻空白的大范围 SVG group 命中。吸附模式在落点前显示“当前锚点 → 候选点”的预览线。
- 描墙方向提供“自由 / 水平 / 垂直”三种互斥约束。水平约束固定候选点的 Y 为当前锚点 Y，垂直约束固定候选点的 X 为当前锚点 X；预览线与提交后的提示都必须明确显示方向。约束只作用于第二个及后续点，第一个点仍按网格正常吸附。
- 吸附模式已有描墙锚点时，鼠标进入地图视口四边 `48 CSS px` 的边缘区会自动平移视角，越靠近边缘速度越高，边界处最高为 `720 CSS px/s`；鼠标离开边缘区、离开地图、结束描墙或切回拖动模式时立即停止。帧间隔按最多 `50 ms` 计，避免页面恢复前台时视角跳跃。连续平移期间临时隐藏候选预览并暂停地点脉冲动画，避免每帧同步重算 SVG；鼠标离开边缘区时按新视角立即恢复预览。
- 轴网交点同时承担开发期描墙输入：第一次点击设为墙线起点，之后每次点击生成“上一交点 → 当前交点”的墙段并从当前点继续；重复点击当前点或按 `Esc` 结束当前连续墙线。不得生成零长度墙段；同一对端点无论顺序只保留一段。
- Owner 提供的整体外墙原始记录保留在 `reference/墙线.json`，经检查为 152 段、单连通、闭合、无分叉、无重复及无零长度段的正交轮廓；正式数据副本为 `data/hospital_ref/floor-one-exterior-walls.json`。Web 地图启动时先加载这 152 段外墙作为只读编辑基线，开发者选项中的撤销与清空只影响本次页面新增的墙段，刷新页面恢复基线；复制 JSON 时导出基线与本次新增墙段组成的完整拓扑。
- 墙拓扑的权威坐标使用当前分区轴网标尺的整数毫米值，显示层按毫米值和所在 X 分区反查图纸百分比；不得把缩放、旋转、平移后的屏幕像素写入墙数据。已描墙线的屏幕主体线宽为 `1 CSS px`，暗色底描为 `2.5 CSS px`，并且都不随地图缩放改变。导出的每段墙只包含两个毫米坐标端点，供后续视线遮挡、房间闭环与相邻关系推导复用；本轮只负责采集和显示，不提前声称已实现这些推导。
- 所有活动区域仍标记为“粗校”；只有逐区对照图纸标注并由 owner 确认后，才能改为“已校准”。

## 二、验证问题

1. 玩家是否能通过相邻点移动理解门诊、住院翼、护士站、活动空间与庭院的关系？
2. NPC 棋子是否比三维模型更清楚地表达“谁在哪里、为什么现在能交谈”？
3. 地图移动与右侧对话能否保持同屏，不制造第二套任务状态？
4. 原始图纸细节、跑团棋盘可读性、路线关系三种目标中，哪一种应成为最终二维表现？

### 已校准房间

- `phone_bay`：owner 提供的检索锚点为 `X +69.00 m, Y -9.00 m`。沿锚点附近墙体与房间文字核对后，活动点放入门诊建筑明确标注的“探视”房间内部，约为 `X +74.6 m, Y -9.7 m`；锚点本身不作为活动点。
- `nurse_station`：owner 提供的检索锚点为 `X +22.50 m, Y -3.00 m`。沿锚点附近墙体与房间文字核对后，活动点放入南病房公共端明确标注的弧形“护士”工作区内部，约为 `X +29.3 m, Y -7.7 m`；本轮使用该护士站，不把它泛称为整层唯一护士站。
- 上述坐标是房间级人工校图结果，不表示已完成 CAD 轮廓复刻；活动区域多边形沿可辨认的墙体外接范围绘制。

### 第二轮区域纠错

图纸指北针朝图面左侧，因此旧原型以屏幕左右命名的 `east_ward` / `west_ward` 作废，分别由 `south_ward` / `north_ward` 取代；旧 `courtyard` 落在有明确球场线的区域，由 `basketball_court` 取代；旧 `garden` 由相对方位正确的 `south_courtyard` 取代。门诊、急诊、活动室、职工食堂与洗衣房均重新落入对应文字标注和墙体围合范围，旧多边形不得继续作为点击区。

本轮仍是轴网级人工校图：建筑块与具名房间可以作为移动节点，未逐门洞复刻真实步行距离。人物归属随地点 ID 改名同步迁移：吴桐位于北病房楼，周卫国位于南病房楼，郑晓敏与谭丽娟使用已校准的南病房护士站。

## 四、交互

- 玩家棋子始终显示当前位置；当前位置与相邻地点以粗略区域高亮，相邻区域可以直接点击，非相邻地点保留在地图上但不可跳转。地图支持滚轮缩放、拖拽平移，以及每次 90° 的左右旋转；缩放、旋转与复位按钮统一放入右栏“开发者选项”，不覆盖图纸。
- 地图旋转、缩放和平移只属于视图状态，不得修改地点坐标、连通关系或任务状态。
- 滚轮缩放使用鼠标所在位置作为锚点，并按浏览器动画帧合并高频输入。目标倍率按滚轮实际幅度指数变化（每像素系数 `0.0032`），当前倍率每帧追近目标的 `42%`，差值小于 `0.002` 时吸附到目标；范围限制为 `0.65×–64×`。高倍率用于内墙描点并驱动 §一的网格细分；这些数值只控制 Web 原型手感，不是游戏规则参数。
- 矢量图纸包含大量路径，连续缩放或平移时不得要求浏览器逐帧重新栅格化。静止画面使用 `data/hospital_ref/vector/page-26.svg` 保持文字与墙线清晰；缩放动画、拖拽平移和描墙边缘平移期间临时切换到由该 SVG 直接生成、同为 4963×3509 且保留透明通道的 `data/hospital_ref/cache/page-26-web.png`，并将相机提升到合成层，动画结束立即恢复矢量图。连续移动期间只更新相机平移，不同步反算 SVG 坐标或重建坐标反馈；移动停止后再按鼠标当前位置恢复反馈。缓存 PNG 不重新取得地图底图的权威地位，也不用于静止校图。
- 时段滤镜固定在地图视口层，静止 SVG 与缩放缓存共同经过这一层；不得把色调或暗角烘进缓存，也不得在缩放时隐藏滤镜层。这样暗角相对视口保持不动，切换底图时也不会改变当前时段的颜色。
- NPC 棋子显示人物姓名与位置。玩家抵达同一地点后，棋子才提供“开始对话”；右侧对话栏不再重复陈列人物卡，不能从侧栏远程发起交谈。
- NPC 棋子的圆点以图纸中单个病床的屏幕占用为参考，不得遮住整间病房；同地点的多名 NPC 只做小幅错位。姓名默认隐藏，只在悬浮或键盘焦点时出现，且只显示玩家当前已知称呼。姓名属于地图旋转层，地图旋转时与圆点、底图保持相同方向，不单独固定在屏幕方向。
- 点击 NPC 圆点先在右侧打开人物档案；同地点且对话入口可用时，档案提供“开始交谈”。档案只显示已通过见面、对话或院内记录得知的事实，未知字段完全不占位。知识准入遵循 [剧情系统设计 §3.11·人物知识与档案](../events/%E5%89%A7%E6%83%85%E7%B3%BB%E7%BB%9F%E8%AE%BE%E8%AE%A1.md)。
- 左侧地图不放地点说明、任务说明或人物详情卡；点击活动点后的文字统一进入右侧叙事栏，避免说明遮挡图纸。
- 开始对话复用人物自己的对话文件与运行时，不在地图模块内保存台词。
- 地图状态仅保存在页面内存；刷新后回到门诊入口。
- 页面保留“二维地图 / 3D 实验”切换。3D 内容不删除，但本轮默认进入二维地图；切换入口与三个呈现变体入口均放入右栏“开发者选项”。地图表面只保留一条对齐的坐标读数，持续显示鼠标所在位置或最近复制的轴网交点。

## 五、三个呈现变体

- `?variant=atlas`：原图图集。突出图纸证据与活动点校位。
- `?variant=tabletop`：跑团桌面。突出棋子、相邻移动与同地点互动。
- `?variant=route`：路线关系。隐藏大部分图纸细节，突出任务动线与房间拓扑。

变体只改变呈现，不复制移动或对话状态。评审确定方向后，保留胜出的结构，删除其余原型变体。
