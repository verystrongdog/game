## 三、诊断：为什么存量设计必须改（owner 已授权，但你要拿出证据）

存量口径（[经历结构 §十](经历结构.md) · [疾病结构 §五](疾病结构.md)）：

| 存量 | 事实 |
|---|---|
| 一局的经历 = 十段 | 玩家逐条核对「以上属实」，认满十段（`quota.total: 10`） |
| 池子由三问筛 | 只有 `event` · `relation` · `agency` 参与匹配（`matches === true`） |
| 病由并集诱发 | 每段经历指向 1–2 张病，候选 = 池子里所有病的并集（`pool_rule` 2–4 张），上界 `c·k = 2×10 = 20 < 26` |
| 结局 | 本局**至少 22 张病结构上不可能出现**——即「哪张病」很大程度上由十段的组合决定 |

**实测证据（`.scratch/阶段7-侦察-存量数据与接线可行性.md` 已替你跑过，你要能复现）**：

```
bun web/scripts/pool-census.mjs
→ 30225 分支 / 24741 需放宽 / 最坏池子 10 段 / 最坏地方跨度 4 / 池病并集 4–4 / 撑不起一局的分支 0
→ ⚠️ 反直觉：未答任何题时池子就已达标（12 段 / 5 地方 / 病并集 4）——「接上但不过滤」在机器上完全合法，代价是筛选力归零
→ ⚠️ 114 问里严格同构的筛选问 = 0 个；可归并 2 问；弱映射 4 问；**`agency`（那时你能决定多少）在现行题库里一问都没有**——这是硬缺口
```

⇒ **结论**：存量口径下，玩家答的话与「哪张病」之间隔着一层十段并集的运气；owner 要的是**那件事直接指向那张病**。改设计。

### 7.2 新概念：**那件事**（`events`）

在 `data/opening.json` 里新增 `events` 块。每条 = **一件事**，schema 至少含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `^evt_\d{4}$` | 主键，不透明、不复用 |
| `title` / `summary` | string | 那件事本身（纯叙事；受文本 lint，与经历侧同规矩） |
| `claim` | string | **一句话说清「这件事打乱了他人生轨迹的哪一段」**——「经得起扩展」的第一判据 |
| `spine` | 对象 | 那件事的**主轴**：`onset`（从什么时候）· `duration_span` / `duration_pattern` · `agency`（那时他能决定多少）· `event`（发生了什么，多值）。**取值复用现有 facet 词表，不新建词表** |
| `expansions` | array ≥N | **扩展位**：每一档一个 `{ facet, value, label, clause, ... }`——`label` 是患者嘴上那一句、`clause` 是纸上的字（与 `opening_clinic.json` 的 `compose` 同一套语义，**不要造第二套拼句引擎**） |
| `activates` | `string[]` 1–4 | **那件事激活的病 id**（`data/diseases.json` 的 `items[].id`）。这是 owner 第 2 条裁定的落点 |
| `effects.attributes` | `{attr: int}` 1–2 项 | 属性结算的来源（替代「十段和 = +2」） |
| `source_experiences` | `string[]` | 这件事由哪几段存量经历**扩写**而来（`exp_####`）。**用途写清「调用方拿它查什么」**：审计素材覆盖 + 找出永不被用的素材。这不是反查键（方向是 事件 → 素材） |

**机核判据（缺一即失败）**：
- 一局恰好**一件事**（不是 0、不是多）——`one_event_per_run`；
- 每件事 `expansions` 位数 ≥ 阈值（阈值写进数据的 `event_rule`，并给依据或标 ⏳）；
- 每件事 `activates` 非空且 1–4 张：上界小会把患者意见掏空，下界大则失去筛选力——**取值要像 `pool_rule` 那样带理由**；
- **病覆盖**：26 张病每张至少被一件事激活（否则就是死病）；
- 每件事必须能撑起病历的那几句（见 §7.4 的落笔判据）；
- `expansions` 的 facet 引用**必须来自现有 11 facet 词表**，不许新增轴（`unknown_facet`）。

### 7.3 `data/opening_clinic.json` 的增补

1. **定位那件事**：一局里，哪些问的答案参与定位（`event_wiring.locate`）。⚠️ 侦察结论：现行 114 问里**严格同构的筛选问 = 0 个**，且 **`agency` 一问都没有**。所以你要么①新增必要的问（按门诊初诊口径写，问法要有临床出处），要么②明确改用哪几问、并说清「为什么这几问对应得上」——**不许含糊过去**。若新增问，一局问数上限 40 的约束（[开局门诊问诊 §11.1 第 4 条](开局门诊问诊.md)）要重新报。
2. **扩展那件事**：哪些问是围绕那件事的扩展追问（`event_wiring.expand`），答完以后**既写纸**（`compose` 已有栏目）**又收敛病**。
3. **收敛病**：候选 = 那件事的 `activates` ∩ 已被玩家的扩展答案**排除掉的**（如果有排除规则，规则要写在数据里并给依据）；**候选 ≤ 4**，一局结束时玩家认下的那张必须与「他怎么说话」收敛到的病**一致**——冲突即报错（`voice_disease_conflict`）。
4. **诊断栏落笔**：`record.columns` 里 `diagnosis` 的 `fill` 从 `blank` 改为 `derived`，`who` 仍是 `hospital`（**医师的笔，不是玩家的**；玩家只做「认」这个动作）。`treatment` **默认仍留白**（§十三 待裁 3）。
5. **`voices` 改挂在病上**：`voices.items[].disease` 指向病 id。阶段 6 的四套（沉下去 / 往上冲 / 有人在盯 / 要数清楚）**必须**分别对到 4 张病（默认见 §十三 待裁 5），并沿用 `min_tagged` 阈值与「并列取最后出现」的规则。

### 7.4 存量 288 段怎么处置（**不许一删了事，也不许照抄沿用**）

- **内容一字不改，变的是结构**——这是本仓库处理同类问题的既有做法（[疾病结构 §一](疾病结构.md)）。288 条记录**原样留在 `data/opening.json` 的 `experiences` 里当素材**，`meta` 加一行说明它自阶段 7 起**不再是一局的可选项来源**。
- 事件的 `source_experiences` 指回被扩写的素材。**未被任何事件用到的素材要报出条数**（这是内容批的待办台账，不是错误）。
- `interview`（八问）· `pool`（匹配与放宽阶梯）· `quota.total: 10`：**标退役**，就地加退役说明，**不删键**（旧测试要全绿）；在 `meta` 里写清 `stage7_retired`。
- `attributes` / `tiers` / `base_attributes` 保留；新增事件的属性结算函数，**不许打破 `settleAttributes` 的现有签名与 288 契约**（`opening.test.js` 钉着它）。
- **样板批规模（默认，见 §十三 待裁 2）**：**≥ 8 件事 · 覆盖 ≥ 6 张病**，且**必须含**这四张（已有语言指纹、特征明显）：`dis_0009` 重度抑郁症 · `dis_0005` 偏执型精神分裂症 · `dis_0012` 强迫症 · `dis_0017` 双相障碍I型。**先把通路打通、可玩、可核**，全量 26 张病是后续内容批的事，不要在这一轮假装做完。

### 7.5 `data/diseases.json` 的小改

- `pool_rule`（病并集 2–4）**改名/退役**为与「一件事」匹配的口径（例如 `event_rule`），**不留第二份权威**。
- ⚠️ **`items` 是 27 条不是 26 条**：`dis_0027`《无法离开医院》是**固有项**，`doors: []`、不占额度、**不进候选、不算名册**（[疾病结构 §八 反例 14](疾病结构.md)）。按 `items.length` 遍历名册是错的。
- 病卡的开门 / 关门 / 加成 / 代价**一个字不改**。

## 八、第四交付：契约层（纯函数 + 校验判据）

实现落在 `web/src/opening-clinic/opening-clinic.js`（**纯函数、无状态**，`db` 由调用方传入；命名带前缀避免与 `opening.js` / `diseases.js` 互相遮蔽）。函数名可调整，但**必须在文档里给出最终清单**。至少要有：

| 组 | 职责 |
|---|---|
| 定位 | 由问诊答案定出**那件事**（`eventOf` / `seedEvent`）；一局恰一件 |
| 扩展 | 那件事的扩展位与已答状态（`eventExpansions` / `expansionAnswered`） |
| 候选 | 那件事激活的病 ∩ 排除规则 → 候选（`eventDiseaseCandidates`，≤4）；「因为你有那件事：…」的来源说明 |
| 认 | 玩家从候选里认下一张（`confirmDisease`），可反悔 |
| 落笔 | 诊断栏那一笔（`diagnosisEntry`，医师笔迹） |
| 言语 | 由病定言语指纹（`voiceOfDisease`），以及调子与候选的一致性检查 |
| 结算 | 那件事（及其已答扩展）→ 属性（替代十段并集），**不破坏** `settleAttributes` 现有契约 |
| 出口 | `profileOf()` 的 `experiences` / `diseases` **非空**（§六 的验收硬标准） |

**`validateClinic(db)` 新增判据**（沿用「一条判据一个 id，报错要能指到数据行」的写法）：

| 判据 id（示意） | 要求 |
|---|---|
| `one_event_per_run` | 任何答案组合下，定位到的事件恰好一件 |
| `event_activates_empty` | 每件事的 `activates` 非空且 1–4 张 |
| `event_coverage` | 26 张病每张至少被一件事激活（样板批阶段按已做批次的子集核） |
| `event_expansion_thin` | 每件事扩展位数 ≥ `event_rule.expansions_min` |
| `event_material_dead` | `source_experiences` 指的素材必须存在（反向：「永不被用的素材」只报数、不报错） |
| `candidate_over_limit` | 候选 > 4 即报错 |
| `voice_disease_conflict` | 一局认下的病与调子收敛到的病不一致即报错 |
| `diagnosis_pen_not_hospital` | 诊断栏的 `who` 必须是 `hospital`；`fill` 必须是 `derived` |
| `prose_reads_like_a_form`（已有） | 拼出来的病史里出现冒号即报错 |
| `prose_without_full_stop`（已有） | 整段没有以句号收尾即报错 |
| `expand_not_on_paper` | 已答的扩展位必须出现在纸上（**不许「对话里说了、纸上没写」**） |

**测试**（照现有三个测试文件的写法：契约 / 反例形变 / 端到端冒烟）：每件事至少一条；一局走完的非空 profile 一条；`voice_disease_conflict` 的反例一条；拒答组合下仍能定位事件并写完病历一条。
