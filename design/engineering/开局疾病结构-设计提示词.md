# 开局「疾病」数据结构与接口 · 设计提示词

> **用法**：把本文件**全文**作为提示词交给设计 agent。
> 允许它读的文件只有 §一 第 2 条列出的那几个——清单之外一律不读。

---

## 你的任务

为《子非鱼》的**开局**设计「疾病」的**数据结构**与**接口调用方式**，并让它与已经落地的新经历契约**咬合**。

产出可直接落地的契约：**受控词表 + 疾病记录 schema + 查询接口 + 校验规则 + 26 病逐条迁移映射**。

**不是**产出分类学讨论，**不是**产出设计哲学，**不要**写文献综述。

---

## 一、硬约束（违反即作废）

1. **只在开局 / Web 演示侧工作。** 禁止引用或依赖 C# 引擎与**神经模拟系统**：脑区 · 连接组与链路 · 主导网络 × 主导角色 · W 矩阵 · 意识结构 · 情境原语 · 认知评价（`AppraisalProfile`）· α 模式 · 环境基调 · 数值化阈值与 β/k/g 参数——**一律不得作为先例、字段、接口或依赖出现**。
   理由：该系统**过于复杂，不能立刻实现**。当前目标是**先把开局跑通**。

2. **只许读这几个文件，别的一律不读：**

   | 允许读 | 为什么 |
   |---|---|
   | 本提示词 | 你的任务 |
   | `data/opening.json` | 邻居契约（经历数据 + 疾病名册占位） |
   | `web/src/character-creation/opening.js` | 邻居接口 |
   | `design/entities/经历结构.md` | 邻居的口径 / 不变量 / 反例清单——**它的教训你要继承** |
   | `design/entities/疾病特长.md` §四–§五 | 26 病的**现存内容**与效果三层（这是 canon 内容，你要重新组织它） |

   **禁止读**：`code/**` · `data/connectivity/**` · `design/entities/diseases/_parent-classes/**` · `design/archive/**` · `reference/**` · `web/src/character-creation/character-data.js`（旧的经历结构，别继承它）。

3. **不得增删改名 26 个病，也不得改它们的开门 / 关门 / 代价 / 风味内容**——那些是 canon。**你改的是结构，不是内容。**

4. **禁止层级归属。** 疾病记录里不得有"父类 / 类别 / 主题 / 主型"这类**单值归属键**；不得有"一种病是另一种病的子类"。
   ⚠️ **8 个疾病父类是按机制分组的外部轴，而"拿父类当轴"正是旧经历结构失败的原因**——留、降级为视图、还是删，必须给出论证，不许默认沿用。

5. **组合 + 接口**：扁平记录（字段即 facet）+ 闭集词表（取值是指向词表的引用）+ 查询式接口。调用方**按字段查询**，不按路径寻址、不靠字符串匹配。

6. **立刻可实现**：纯 JSON + 浏览器 JS。无后端、无数据库、无构建期代码生成。

7. **一份权威数据**：同一批记录不得出现两份手写副本。

8. **数值不硬编码在代码里**；每个含数值的配置块带 `source` 字符串。

9. **玩家可见的字段名一律用人话。** 上一轮把 `relation` 叫成「对手方」（金融术语 counterparty，且中文"对手"含敌意）被 owner 抓过。
   **黑名单**（出现在 facet 名 / 取值标签里即失败）：对手方 · 场域 · 权位 · 照护位 · 归属状态 · 控制权 · 后果出口 · 输出槽 · 跨度 · 维度 · 字段 · 槽位 · 权重 · 参数矩阵 · 元数据。

10. **没有通配符，没有 `unknown` / `unspecified` / `待定` 取值。** "不适用"必须显式；**空值怎么念（`empty_label`）必须写在数据里**，不许写死在代码里。

11. **角色标记写在数据里**（例如"这个是输出槽"），不许在代码里硬编码某个 facet 的名字。

## 二、你要咬合的邻居（这些是现成事实，已落地）

- `data/opening.json`：11 个 facet 的闭集词表 + 16 条**扁平**经历记录 + 6 个视图 selector + 互斥 pair 列表 + 配额/档位/起始值/净值配置 + **`disease_roster`（5 条占位 `dis_0001…dis_0005`，标签是 ⏳）** + 非法组合登记。
- 每条经历记录有一个 `diseases` 字段：**引用名册 id 的多值数组**。
- `web/src/character-creation/opening.js` 已有两个疾病相关接口：
  - `diseaseCandidates(db, sel)` —— 求并集，并带 `from`（哪些已选经历指向它）。
  - `diseaseCoverage(db)` —— 报每条病被几条经历指向 + **前 10 条经历的候选并集大小**。
- 已立的不变量：**加一条经历 = 改 1 个文件** · 删任一视图 = 记录零改动 · 记录禁止未知键 · 语义不许藏在文案里（文本 lint）· 每个 facet 必须能回答"调用方拿它查什么"。

---

## 三、已测出来的硬伤（你必须解决）

`diseaseCoverage()` 实测：名册 5 条，**前 10 条经历的候选并集 = 5/5 = 全集**。
也就是说**"你只能在候选里选"现在等于没有约束**——玩家选满 10 段经历后，几乎总能选到任何一种病。

你的契约必须让候选成为**真约束**：

- 给出**可算的判据**（例如"任意合法选择下，候选并集的下界 < 名册规模"）；
- 明确参数：**名册要多大**、**每条病最多被几条经历指向**；
- 用 `diseaseCoverage()` 的实测数字验证你的方案（写出你算出的数）。

## 四、必须处理的三处既有分组（每处都要论证，不许默认沿用）

| 既有 | 你必须回答 |
|---|---|
| **8 个疾病父类**（按机制分组） | 它是不是又一根"拿分组当身份"的轴？若保留，以什么形式保留才不构成单值归属键？若降级/删除，疾病名录的浏览靠什么？ |
| **四种表现形态**：闯入式 · 信念式 · 接管式 · 摆荡式 | 它是**内容分组**，还是可以从字段**派生出来的视图**？⚠️ **不得**用机制参数（表征数值、脑区、阈值）来支撑它——判据只能是"玩家能看见的表现"。 |
| **四类门**：对话门 · 调查门 · 空间门 · 遭遇门 | ⚠️ 「遭遇门」对应战斗层，owner 已裁定**战斗层暂停**。这一格在新结构里怎么处理？ |
| **临时加成**（+1；重档 +2 待定）及其"触发情境" | 触发条件若写成**自由文本**就不可查询——那正是经历那轮修掉的错。用词表还是结构化子句？ |

另有一条内容生产约束必须能被表达：**「关掉的门必须可见」**——玩家要走到一间进不去的房、看到一个不出现的选项，才知道自己丢了什么。疾病记录要能指出**这道关着的门会在哪里被撞到**。

## 五、你要交付的

### 1. 受控词表
每个 facet / 枚举给出：**id · 人话名 · 取值（id + 玩家可读标签）· 单值还是多值 · 空单元与非法组合登记**。

### 2. 疾病记录 schema
JSON 级字段描述 + **至少 3 条完整示例**（取自真实的 26 病）+ **禁止出现的字段**清单。

### 3. 接口
- **函数签名**：按字段查询 · 视图求值 · 候选求并集 · **反查**（"这条病能从哪些经历来"）· 门的查询（开哪道 / 关哪道）· 校验。
- **屏 3（疾病候选）/ 屏 4（选疾病）/ 屏 5（镜子）** 分别调哪个接口、拿什么参数、得到什么。
- **增删改口径**：加一条病 / 加一条经历各改几个文件——**必须给数字**。

### 4. 与经历契约的接缝
`diseases` 引用谁（名册 id？还是病记录 id？）· 反查怎么算而**不存第二份数据** · 候选筛选力的判据 + 实测数字。

### 5. 26 病逐条迁移映射
一行一条：旧字段 → 新字段（重命名 / 拆分 / 新写）。标明哪些内容是**原样搬**、哪些**必须重写**、哪些**没有落点**（后者要说明是删还是变成展示专用）。

### 6. 校验与不变量
可机械检查的不变量清单（词表收口 · 取值可达 · 门的枚举合法 · 名册与记录的引用完整 · 数值可追溯 · 空值有念法 …），并对每条给出**没有工具强制时人肉怎么核**。

### 7. 反例清单
什么算**失败**：单值归属键 · 语义藏在文案里 · 两份手写副本 · 字段不可查询 · 依赖机制层概念 · 数值硬编码 · 加一条记录要先决定它"属于哪一类"。

### 8. 自检
逐条给数字：加一条病改几个文件？加一条经历改几个文件？候选并集下界是多少？每个词表取值都有记录用到吗（列死值）？有没有哪个字段只存在于人类可读文本里？有没有哪个 facet 答不出"调用方拿它查什么"？

### 9. 文件放哪
从中选一个并说明它对「加一条经历 = 改 1 个文件」这条不变量的影响：
(a) 并进 `data/opening.json` · (b) 独立 `data/diseases.json` · (c) 暂留旧文件。

### 10. 待裁项
每项给**选项 + 各自影响 + 你的默认**。不确定的标 ⏳ 并说明卡在哪。

## 六、表达要求

- **中文**；结论先行；表格优于散文。
- 给出**可复制的 JSON / JS 片段**，不要只给描述。
- 不确定就标 `⏳` 并说明卡在哪，**不要编造**。
- 不要写"建议进一步研究"这类空话。要么给结论，要么标为待裁项并给出选项与影响。
