## ★ 「生成两次结果一致」判据抓到 3 个真 bug

这条判据不是形式主义——它在本阶段直接暴露了三个**非确定来源**：

| # | bug | 后果 |
|---|---|---|
| 1 | manifest 自身是 `data/*.json` → 把自己也收纳为被盘点对象 | 文件数在两次运行间漂移 |
| 2 | 引用统计**先剥 `./` 再做 `startswith('./.refactor-backup')` 过滤** → 过滤条件永不成立 | 备份目录 11 个 + `data/` 下 3 个文件被误算为设计文档引用 → **全部数据文件的 lifecycle 判定失真** |
| 3 | 引用统计含 `.py`/`.json` → 任何提到数据文件名的**工具**都抬高其计数 | 新增一个校验器就改变某个数据文件的 lifecycle → 改为只统计 `.md` |

**bug 2 尤其值得记**：若无这条判据，它会静默产出错误的 lifecycle 分类，而所有校验器仍"全绿"。

### ★ 由 bug 3 引出的设计修正：manifest 定为「声明式契约」

修掉 bug 3 后仍有一个结构性脆弱：**任何新增 `.md` 提到某数据文件名，都会抬高它的引用计数**。
实测：本阶段新增一份证据文档，立即改变了 \`data/hospital_ref/manifest.json\` 与
\`data/skills-lock.json\` 的 \`active_docs\`，使 \`--check\` 失败。

若 \`--check\` 比对"重新推导的属性值"，则**每写一份文档都要重生成 manifest**——契约不可用。

因此定案（2026-09-12）：

| 命令 | 语义 |
|---|---|
| \`build_data_manifest.py --check\` | **契约校验**：文件集与磁盘一致（无遗漏/无幽灵）+ 属性合法。**不重新推导** |
| \`build_data_manifest.py --refresh\` | **人工动作**：从证据重新推导并覆盖（分类需要更新时才用） |
| \`build_data_manifest.py\`（无参） | 若已存在则**拒绝覆盖**，提示用 \`--refresh\` |
| \`validate_data_manifest.py\` | 三条判据：D1 契约成立 / D2 runtime allowlist 双向 / D3 属性正交 |

引用计数（\`refs\`）保留在 manifest 中作为**分类时的证据留档**，不参与 \`--check\`。

## 未闭合项（不得当作通过）

1. **`data/skills-lock.json` 是 AI agent 的 skill 锁文件（41 项），非游戏数据**，误放于 `data/`，零设计文档引用。
   已在 manifest 中标 `note` 建议迁出，但**尚未迁**——需 owner 决定去向（`.agents/` 还是移出版本控制）。
2. **schema 层未建立**：§9.3 要求 Schema 与"跨文件语义检查"分工；现状只有"清单 + 属性"。
   `validate_params` / `validate_disease` 等承担了部分语义检查，但**没有 JSON Schema**。
   列入 P4c 后续或 P4d。
3. **`generator-input` 角色无实例**：四轴里 `role=generator-input` 是合法值，但实测 0 个文件被标为此角色
   （生成链未系统梳理）。当前 39 个非 runtime 全为 `reference`。
4. **archived 的 6 个文件未清理**：仅标记，未移动。按 §12.1 应进 archive。
