## 一、收录什么（入库门）

**三条全满足才进表**：

| # | 条件 | 不满足时去哪 |
|---|---|---|
| ① | **症状可复现**：给得出观测命令或读数 | 只有结论没有观测面 → 不进表 |
| ② | **根因不可由代码局部读出**：读那段代码看不出来 | 读得出来 → **写代码注释**，不进文档 |
| ③ | **有代价**：本条能写出至少一条具体代价 | 纯知识补充 → 不进表 |

**③ 的代价分三种形态，须指名是哪一种**（"重要"不算代价）：

- **时间**——在错误方向上花掉的时间（例：每条命令 30 s 超时、测试挂住后重跑）
- **错误结论**——导致你判断错了对象或方向（例：把"人悬浮"判成"椅子太矮"）
- **错误修复方向**——导致你去改不该改的东西（例：把 API 语义问题归因成动画资产问题）

**最贵的一类是错误结论**：时间花了就花了，但错误结论会**写进仓库继续误导下游**（实例见 §八 干净检出一致性的 `#139` 归因污染）。

**不收录**：可在代码里局部读出的 · 能机械拦住的（→ §十）· 一次性历史事实（提交范围、迁移记录、两份拷贝合并等，留在各自 README 的叙述里）。

## 二、怎么用

| 入口 | 用法 |
|---|---|
| **A. 按位置（预防）** | 你**即将改动**某处 → 在下方找到对应阶段与位置键 → 先读该行。这个入口保证"动手前能看到" |
| **B. 按症状（排障）** | 你**已经踩了**，只知道现象 → 直接 `grep` 症状词（如「画面不动」「悬浮」「看着黏」「多锁」）→ 命中行即该症状的根因家族。同一行**可挂多个症状**，因此同族根因不会被拆散 |

**位置键的定义**：**稳定标识符**（Unity 子系统 / 资产契约层 / 工具面），**不是文件路径、不是行号**。理由：文件会改名会搬会拆（`ActionCatalog.cs` 的 KI 路径已整条作废、§二·G 已警告日后拆 asmdef 会改命名空间），行号随编辑漂移——项目规约 §四 已因同一理由禁用行号引用。

### 为什么是校验器而不是文档

**A3 报的 4 处 KI 悬空是已经手工查出过一次的**——`ActionLab.controller` 中 `m_Motion` 为空的四个状态，状态名逐一读出为 **Idle / Walk / Jump / Run**，正是 `code/unity/README.md` §二·H 残留缺口 ① 手写的那句「4 条 locomotion 态仍引用不入库的 KI 包」。当时用一次性脚本核完就没了，结论只留在散文里。

⇒ 校验器的职责就是这个：**把「已经手工发现过一次的东西」变成「每次自动发现」。** 现在这 4 条被登记在 `known_dangling` 里、各带 #139 编号——`#139` 关闭时必须删掉这 4 条（否则允许清单会从"例外登记"长成"永久豁免名单"）。

另 2 处是 Unity 内置资源 guid（`0000…f000…` / `0000…e000…`，出现在 `ActionLab.unity`、`GraphicsSettings.asset`、`PackageManagerSettings.asset`）——**A3 必须有内置允许清单，否则全是假阳性**。

### 它能进 CI，而 `unity` 门禁不能

本脚本是纯 `git ls-files` + 文本解析，**无 Editor 依赖**，故可进 `docs-integrity` CI job 强制；而 `unity` 门禁在 CI（ubuntu runner）上是 `NOT_AVAILABLE`（见 [gates.json](gates.json)）。⇒ 它把一条**只有开着 Editor 的机器才查得到**的纪律，变成**每次 CI 都拦**。

依赖关系与门禁登记见 [gates.json](gates.json)、[build-and-test.md](build-and-test.md) §五。

## 十一、维护规则

1. **写在哪**：一条新记录必须落进**已有的位置键行**或**新增一行**；不得另起一份文件、不得在别处留副本——**副本的指针会烂，而且烂得无声**。项目内可复核的实例（两处都曾是可解析的真实路径）：
   - `code/unity/README.md` §二·E 引用的 `Assets/Kevin Iglesias/...`，2026-09-12 来源整条切 Mixamo 后**已作废**（该节 🔧 修正块自述）；
   - `ActionCatalog.cs` 的 KI 路径随之成为**已知作废项**，待 #138 生成表取代。
   这也是 §二「位置键不得用文件路径」的同一条理由：**路径会被迁移作废，位置键不会。**
2. **同族合并**：症状相同、根因不同 → **合并成一行**（症状列写多个），不要拆成多条。拆开的后果已有实例：冻结三兄弟曾被记成三条独立条目，文件自己都写着「症状与坑 1 逐项相同」。
3. **准入**：三条全满足（§一）；③ 必须指名代价形态。
4. **不许复制参数**：数值正本在 [动作库规格.md](../presentation/动作库规格.md) §七 与 `data/`；本表只写判据样本。
5. **改这条规则**：改本表的结构（阶段、位置键定义、入库门）前先读 `design/engineering/` 的既有约定，不要在表内私自扩张。
6. **证据必须可在干净检出复核**：引用的路径要能被 `git ls-files` 命中。**本机临时态里的观察不得当判据**——`.scratch/`（`.gitignore:62`）、`.claude/`（`.gitignore:110`）、仓库外绝对路径，引它的人**无法验证**，表就退化成传闻。（本规则来自一次实际失手：本表初稿曾用 `~/.claude/projects/.../memory/` 里一份断掉的副本指针当实例，被 owner 当场指出——不可复核的证据不成立。）
7. **来源优先指「正本」，不指易变的叙述节**：工具面的坑指 `code/tools/*/README.md` 的坑表、参数的坑指 [动作库规格.md](../presentation/动作库规格.md) §七——**不要**把 `code/unity/README.md` 里按轮次增删的 `§二·X` 当作唯一来源。**教训来源**：本表 §七 两行初稿曾引用 `code/unity/README.md` §二·F（按轮次组织的"花海 lab"一节）——那类节会随轮次下线而**整节消失**，正本（`code/tools/unity-cli/README.md` §四 坑 1/3）不会。同一事实若有多处记载，**指最稳定的那处**。
