## 一、收录什么（入库门）

**三条全满足才进表**：

| # | 条件 | 不满足时去哪 |
|---|---|---|
| ① | **症状可复现**：给得出观测命令或读数 | 只有结论没有观测面 → 不进表 |
| ② | **根因不可由代码局部读出**：读那段代码看不出来 | 读得出来 → **写代码注释**，不进文档 |
| ③ | **有代价**：本条能写出至少一条具体代价 | 纯知识补充 → 不进表 |

**③ 的代价分三种形态，须指名是哪一种**（"重要"不算代价）：

- **时间**——在错误方向上花掉的时间（例：每条命令 30 s 超时、测试挂住后重跑）
- **错误结论**——导致你判断错了对象或方向（例：把"人悬浮"判成"椅子太矮"）
- **错误修复方向**——导致你去改不该改的东西（例：把 API 语义问题归因成动画资产问题）

**最贵的一类是错误结论**：时间花了就花了，但错误结论会**写进仓库继续误导下游**（实例见 §八 干净检出一致性的 `#139` 归因污染）。

**不收录**：可在代码里局部读出的 · 能机械拦住的（→ §十）· 一次性历史事实（提交范围、迁移记录、两份拷贝合并等，留在各自 README 的叙述里）。

## 二、怎么用

| 入口 | 用法 |
|---|---|
| **A. 按位置（预防）** | 你**即将改动**某处 → 在下方找到对应阶段与位置键 → 先读该行。这个入口保证"动手前能看到" |
| **B. 按症状（排障）** | 你**已经踩了**，只知道现象 → 直接 `grep` 症状词（如「画面不动」「悬浮」「看着黏」「多锁」）→ 命中行即该症状的根因家族。同一行**可挂多个症状**，因此同族根因不会被拆散 |

**位置键的定义**：**稳定标识符**（Unity 子系统 / 资产契约层 / 工具面），**不是文件路径、不是行号**。理由：文件会改名会搬会拆（`ActionCatalog.cs` 的 KI 路径已整条作废、§二·G 已警告日后拆 asmdef 会改命名空间），行号随编辑漂移——项目规约 §四 已因同一理由禁用行号引用。

## 五、场景装配

| 位置键 | 症状（可多个） | 根因 | 判据（可观测） | 规避 / 修法 | 来源 |
|---|---|---|---|---|---|
| `CharacterController.skinWidth` | **角色整体悬浮** · 目视表现为「**椅子好像不够高**」 · 足 IK 完全不介入（读数"逐位一致"，看似没问题） | CC 静止时 `transform.y ≈ skinWidth` → 整体抬到地面上方 **80 mm**；而足 IK 假定 `groundY = 0` 且**只上抬不下压** → 需要量 ≤ 0 时不介入，**掩盖了悬浮** | 站姿蒙皮足底 **+45.8 mm**（应为 ~0）；坐姿髋高偏离 | `SizeControllerToModel()` 里收到 **0.005**，**必须在 Awake / CC 落定前设**——中途改**无效**（实测改到 0.02 后 3 s 仍停在 0.08；CC 只排开穿插、不会自己往下坐） | `code/unity/README.md` §二·J 🔧 悬浮 80 mm；[动作库规格.md](../presentation/动作库规格.md) §七 |
| CC 顶住障碍时的速度归零 | 「**被挡住**」与「**没输入**」在动画上**不可区分**（都播 Idle） | 动画档位按**水平速度**取；撞墙时 `CharacterController.velocity ≈ 0` | `velocity ≈ 0` 而输入非零 | 知道即可；若将来要区分，需另立信号（当前不区分） | `code/unity/README.md` §二·I 副产品读数 |
| 场景夹具会毁掉复现 | **bug 不复现** → 误判「已经修好了」 | 参照柱挡路 → `spd01 = 0` → 动画选 Idle → **起跳前缓存变成 Idle** → 落地目标与之不同 → 守卫反而正常发切态 | 复现时先确认起点前方空旷 | 复现走 **`-z`**（参照柱只在 `(0,0,3)` / `(3,0,0)`，起点后方空旷） | `code/unity/README.md` §二·I 复现 / 复核方法 |
| 体位改变时的姿势混合 | 坐 / 站接缝处**下陷、跳动** | 坐下 clip 与起身 clip 的**坐姿基准不匹配**（根位基准差 ≈ **0.31 m**） | 接缝处逐帧读髋高 | **纯姿势混合不够**——凡涉及体位改变（坐/站/倒地）的衔接须另想办法。这是「姿态切换自然」在本项目里第一个被证据否定的假设 | [动作库规格.md](../presentation/动作库规格.md) §四·乙 |
| 坐下段的 `cc.Move` | 坐姿**沉不下去**、双脚离地 | 默认 root motion 走 `cc.Move` **会被地面碰撞挡住** | 坐姿足底高度、髋高 | 坐下段**临时禁用 CC**，由 `OnAnimatorMove` 手动把 `animator.deltaPosition` 施加到 transform | [动作库规格.md](../presentation/动作库规格.md) §四·乙 |
| `Animator.applyRootMotion` 逐帧切换 | 根位移**完全不动** | `applyRootMotion = false` 时 `Animator.deltaPosition` **逐位为 0**（实测 `(0,0,0)`，而此时 `norm = 2.13` 正在播 Sit——**看起来像 clip 没有位移**） | 读 `animator.deltaPosition` | 驱动层按词条标志 `RootMotionXZ` **逐帧切换** `Animator.applyRootMotion`；不得"场景侧一律 false" | [动作库规格.md](../presentation/动作库规格.md) §四·乙 再修正 |
| clip 根旋转 `RootQ` | 坐下后**朝向偏了**（实测偏航 **+7.08°**），并带来 **19 mm** 横向漂移 | clip 自带根旋转 | 就座后读角色 yaw 与横向落点 | **旋转不施加**；`OnAnimatorMove` **只取 XZ 分量**，Y 丢弃（仍由姿势承载）；朝向由对齐段锁在椅子 forward | [动作库规格.md](../presentation/动作库规格.md) §四·乙 再修正 |
| 坐面 footprint 碰撞 | 根位移被**自己的椅子**挡住 | 就座后角色整体在坐面 footprint 内：胶囊半径 **0.3117** vs 坐面半深 **0.21** → 重叠**必然** | 就座期间读 `cc` 是否被挡 | 占用期间**忽略与椅子的碰撞**；`Stand` 播完复原 | [动作库规格.md](../presentation/动作库规格.md) §四·乙 再修正 |

## 六、播放期

| 位置键 | 症状（可多个） | 根因 | 判据（可观测） | 规避 / 修法 | 来源 |
|---|---|---|---|---|---|
| `Animator.CrossFade` 时间语义 | 过渡时长**随源 clip 长度变化** · 「**起身看着黏**」 | 第二参**不是秒**，是「源状态归一化时长的比例」（官方参数名 `normalizedTransitionDuration`） | 确定性 5 ms 步进量 `IsInTransition` 持续时长：`fade = 0.10` 时 Defend(0.800) → **0.085**、Jump(1.533) → 0.155、SitIdle(4.300) → **0.430**；而 `CrossFadeInFixedTime(0.10)` 恒为 **0.100** | **一律用秒制的 `Animator.CrossFadeInFixedTime(name, fadeSeconds)`**。修前 `SitIdle → Stand` 实际过渡 0.52 s（本意 0.12） | [动作库规格.md](../presentation/动作库规格.md) §六 陷阱 1 |
| Animator 状态读数（`GetNextAnimatorStateInfo`） | 「**人已站起却多锁 2.5 s**」· 一次性动作锁时长错 | `CrossFade` 发起的**当帧过渡尚未注册**：此时 `GetNextAnimatorStateInfo(0).length == 0`（无过渡），而 `GetCurrentAnimatorStateInfo(0)` **仍是源状态** → 回退读它就把锁时长变成**源 clip** 长度 | 从 `Idle`(2.7) 坐 → 锁 2.75 s（应 1.85）；从 `SitIdle`(4.3) 起身 → 锁 **4.35 s**（应 1.85） | 长度读取**逐帧重试**，且**只接受 `shortNameHash` 与目标状态一致的读数**（三面对一：状态名 = 词表 id）；0.5 s 仍读不到才用兜底时长 | [动作库规格.md](../presentation/动作库规格.md) §六 陷阱 2 |
| controller transition 归属 | 落地后**动画停在 `Jump`、身体继续平移**（"平移"现象） | 契约 A 下 controller **零参数、零手动 transition** → Animator **无法自行离开状态**；`Jump` clip `loopTime: 0` → 状态时间继续走、**姿势定格末帧** | 落地帧 `GetNextAnimatorStateInfo(0)` 的 `shortNameHash == 0`（无过渡在途）；`Animator.GetCurrentAnimatorStateInfo(0)` 恒为 Jump | 落地边沿**强制补发一次回切**（补发后清零、不逐帧刷）；决策层不得因缺 `Animator` 提前 return——状态选择始终成立并留痕（`LastRequestedState` / `StateRequestCount`），使行为**无 controller 资产也能断言** | `code/unity/README.md` §二·I |
| 足 IK 求值路径 | 从外部设一次 IK 目标**无效**（跨真实帧读数**逐位不变**） | `OnAnimatorIK` 由**玩家循环**驱动，且 `Animator.SetIKPosition` **不是持久状态**（Unity 每帧重置） | 跨帧读骨骼几何量 | 必须由真实 `MonoBehaviour` 在 `OnAnimatorIK` 里**逐帧设置**。⇒ 也因此，**确定性姿势求值路径上 IK 不在场**，验 IK 必须开 Play 循环逐帧读 | [动作库规格.md](../presentation/动作库规格.md) §四·乙；`code/tools/unity-cli/README.md` §五 |
| 足 IK 权重 | 起身末帧**膝角被拉弯 14.6°**、脚反而**扎入地面 9.5 mm** | 需要量为 0 时若仍给权重 1，求解器会为「够到脚当前位置」这个目标**把腿拉弯** | 膝角（髋–膝–踝三点夹角）、足底最低点 | 需要量 ≤ 0（已贴地或悬空）时**权重归 0**、完全不介入；> 0 时按 `blendDistance`（20 mm）爬升。口径 = **只上抬不下压**，故可常开 | [动作库规格.md](../presentation/动作库规格.md) §四·乙 |
| `AnimatorControllerLayer.iKPass` | `OnAnimatorIK` **根本不被调用** | 层上 `iKPass` 为 0（`ActionLab.controller` 当前 `m_IKPass: 0`） | 埋一个 `OnAnimatorIK` 计数 | 接入足 IK 时须一并把 `iKPass = true` | [动作库规格.md](../presentation/动作库规格.md) §四·乙 |
| 浮点精度（float ↔ double） | 一次性动作计时「**到点却判未到点**」→ 该切的态不切 | C# 允许浮点运算使用**高于结果类型的精度**：`elapsed >= clipLength + 0.05f` 的**右侧**可能以 double 中间值参与比较，与外部按 float 落回的同一个和**差 1 ulp** | 实测：`a = clipLen + 0.05f` 与函数内的和**同为 bits `1065772646`**，函数却返回 `False` | **显式落回 float 再比**。此计时正是 `Sit` 播完切 `SitIdle` 的依据。跨域第二端见 §九 | `code/unity/README.md` §二·H 残留缺口 2① |
| 状态重置面 | 重置后仍留旧值 → 凡靠它做**输入守卫**的路径被误导（例：起身守卫要求"当前是 `SitIdle`"） | `ResetToIdle()` **不清** `CurrentActionId` | 重置后读 `CurrentActionId` | 重置时一并清 | `code/unity/README.md` §二·H 残留缺口 2② |

## 八、提交期

| 位置键 | 症状（可多个） | 根因 | 判据（可观测） | 规避 / 修法 | 来源 |
|---|---|---|---|---|---|
| git 工作树状态 | `git pull` 被拒：「untracked working tree files would be overwritten by merge」——**即使字节完全相同** | 那些文件在另一侧**未跟踪但已存在**（本次入库把它们变成了跟踪文件） | `git status` 看 untracked 是否与目标文件同名 | 只对齐 HEAD 与索引、**不碰工作树**：`git fetch origin` + `git reset --mixed origin/main`。⚠️ **不得用 `reset --hard` / `checkout -f`**——会覆盖未提交的分叉实现 | `code/unity/README.md` §二·H |
| 干净检出一致性 | **本地模拟全绿、真实 CI 全失败** | 依赖未入库文件 / 机器绝对路径 / 生成物被多次提交 / gitlink 悬空（`.gitignore` 与强制入库相互矛盾） | `code/tools/check_clean_checkout.py`；CI 首跑 | 见 [evidence/P4a](evidence/P4a-2026-09-12.md) 的四类缺陷与修复。⚠️ **代价样本（最贵的一类：错误结论污染权威载体）**：`#139` 的验收标准写在错误归因上——实测「那两条常红断言的真因与 #139 的归因不符」→ 结论「**#139 按现文写达不到自己的验收标准**」 | [evidence/P4a-2026-09-12.md](evidence/P4a-2026-09-12.md)；`code/unity/README.md` §二·H 残留缺口 2 |

## 九、引擎 / 语言层（跨域）

> 本节的条目**在 Unity 侧也中过一次**，故两端都记录（跨域键不合并）。这样做是为了让读 Unity 的人不会以为"这是 Unity 的事，跟我无关"，反之亦然。

| 位置键 | 症状（可多个） | 根因 | 判据（可观测） | 规避 / 修法 | 来源 |
|---|---|---|---|---|---|
| 浮点精度（float ↔ double，1 ulp） | 阈值比较**在同一数值上给出相反结果** | C# 规范允许中间运算保持**高于结果类型的精度** → 一侧以 double 中间值参与比较 | 同一表达式两边 `BitConverter` 取 bits **相等**、比较结果却相反 | 比较前**显式落回 float**。Unity 侧实例见 §六 同名条目（`OneShotElapsed` 计时） | `code/unity/README.md` §二·H 残留缺口 2① |

以下条目**已经可静态判**（**不需要 Unity Editor**），因此不再靠人记、也不进上表——归宿是 **`code/tools/validate_unity_assets.py`（1 个脚本 / 4 条规则）**：

| 规则 | 扫描面 | 判据 | 状态（原型实测，2026-09-13） |

**内置 guid 允许清单外置为 JSON**（同 `validate_params_exceptions.json` 的形态），便于日后增补而不改代码。

### 为什么是校验器而不是文档

**A3 报的 6 处悬空里，有 4 处是已经手工查出过一次的**——`ActionLab.controller` 中 `m_Motion` 为空的四个状态，状态名逐一读出为 **Idle / Walk / Jump / Run**，正是 `code/unity/README.md` §二·H 残留缺口 ① 手写的那句「4 条 locomotion 态仍引用不入库的 KI 包」。当时用一次性脚本核完就没了，结论只留在散文里。

⇒ 校验器的职责就是这个：**把「已经手工发现过一次的东西」变成「每次自动发现」。**

另 2 处是 Unity 内置资源 guid（`0000000000000000f000000000000000`，出现在 `ActionLab.unity` 与 `ProjectSettings/GraphicsSettings.asset`）——**A3 必须有内置允许清单，否则全是假阳性**。

### 它能进 CI，而 `unity` 门禁不能

本脚本是纯 `git ls-files` + 文本解析，**无 Editor 依赖**，故可进 `docs-integrity` CI job 强制；而 `unity` 门禁在 CI（ubuntu runner）上是 `NOT_AVAILABLE`（见 [gates.json](gates.json)）。⇒ 它把一条**只有开着 Editor 的机器才查得到**的纪律，变成**每次 CI 都拦**。

依赖关系与门禁登记见 [gates.json](gates.json)、[build-and-test.md](build-and-test.md) §五。

## 十一、维护规则

1. **写在哪**：一条新记录必须落进**已有的位置键行**或**新增一行**；不得另起一份文件、不得在别处留副本——**副本的指针会烂，而且烂得无声**。项目内可复核的实例（两处都曾是可解析的真实路径）：
   - `code/unity/README.md` §二·E 引用的 `Assets/Kevin Iglesias/...`，2026-09-12 来源整条切 Mixamo 后**已作废**（该节 🔧 修正块自述）；
   - `ActionCatalog.cs` 的 KI 路径随之成为**已知作废项**，待 #138 生成表取代。
   这也是 §二「位置键不得用文件路径」的同一条理由：**路径会被迁移作废，位置键不会。**
2. **同族合并**：症状相同、根因不同 → **合并成一行**（症状列写多个），不要拆成多条。拆开的后果已有实例：冻结三兄弟曾被记成三条独立条目，文件自己都写着「症状与坑 1 逐项相同」。
3. **准入**：三条全满足（§一）；③ 必须指名代价形态。
4. **不许复制参数**：数值正本在 [动作库规格.md](../presentation/动作库规格.md) §七 与 `data/`；本表只写判据样本。
5. **改这条规则**：改本表的结构（阶段、位置键定义、入库门）前先读 `design/engineering/` 的既有约定，不要在表内私自扩张。
6. **证据必须可在干净检出复核**：引用的路径要能被 `git ls-files` 命中。**本机临时态里的观察不得当判据**——`.scratch/`（`.gitignore:62`）、`.claude/`（`.gitignore:110`）、仓库外绝对路径，引它的人**无法验证**，表就退化成传闻。（本规则来自一次实际失手：本表初稿曾用 `~/.claude/projects/.../memory/` 里一份断掉的副本指针当实例，被 owner 当场指出——不可复核的证据不成立。）
7. **来源优先指「正本」，不指易变的叙述节**：工具面的坑指 `code/tools/*/README.md` 的坑表、参数的坑指 [动作库规格.md](../presentation/动作库规格.md) §七——**不要**把 `code/unity/README.md` 里按轮次增删的 `§二·X` 当作唯一来源。**教训来源**：本表 §七 两行初稿曾引用 `code/unity/README.md` §二·F（按轮次组织的"花海 lab"一节）——那类节会随轮次下线而**整节消失**，正本（`code/tools/unity-cli/README.md` §四 坑 1/3）不会。同一事实若有多处记载，**指最稳定的那处**。
