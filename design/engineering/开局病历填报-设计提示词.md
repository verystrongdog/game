# 开局「病历填报」· 设计提示词（阶段 2：可填写的病历 + 双人物来源）

> **用法**：把本文件**全文**作为提示词交给设计/实现 agent。
> 允许它读的文件只有 §一 第 3 条列出的那几个——清单之外一律不读。
> **阶段 1（病历外壳）已落地**，本文件是第二阶段：让这张病历**真的可以填**，并支持**默认人物 / 自建人物**两条入口。

## 你的任务

让 Web 开局表现为**在一张入院记录上填写自己的患病史**：

- **默认开局人物 = 苟智空**（正典，`疾病特长.md` §4.6.4 的蓝色手环：自述「苟智空」/ 院方记录「苟笙 / 0527 / B 栋 147 室 4 床」）；
- **也可以自己构建人物**：玩家给出自己的姓名与一般情况，然后走同一条开局流程。

产出可直接落地的契约：**栏位落笔表 + 双人物来源的数据形状 + 自建人物的闭集词表 + 交互形态 + 校验规则 + 测试**。

**不是**产出玩法哲学，**不是**产出 UI 线框，**不是**写文献综述，**不是**重新论证已经落地的病历外壳。

6. **玩家只能落三种笔：答 · 认 · 签。** 精确判据（不要写成"不许有输入控件"那么粗）：

   | 让玩家编辑某条记录的字段值 | 对院方已写好的内容表示「以上属实」或签名 |

7. **两种笔迹必须分得开**（M2）：玩家落笔处（患者自填 / 患者陈述）与院方书写处（院方记录）在视觉与标注上分得开，沿用阶段 1 的 `cc-ink-patient` / `cc-ink-hospital`。**自建人物不许把院方记录栏也变成玩家可写的**。

8. **不许新增第 12 个 facet。** 一般情况（姓名 / 性别 / 年龄 / 职业 / 婚姻 / 出生地 / 入院时间 / 病史陈述者 / 病史可靠程度）是**文书栏位**，不是经历的 facet：不得进 `vocab`，不得参与锚点、selector、配额、疾病候选。患者自建人物所需的闭集（性别、年龄段、职业类别…）必须**另立词表块**并说清它与 `vocab` 的边界。

9. **病名口径**：屏上一律用 `data/diseases.json` 的病名（DSM-5 命名）；**不渲染任何诊断编码**（国家规范要求的 ICD-10 属院方档案层，两者混渲染即失败，见 [开局病历填报 §八.7](../presentation/开局病历填报.md)）。

10. **不许自造临床取值枚举。** 一手来源里只出现过「基本可靠」一个实际取值；「可靠程度」的法定枚举、以及「两系三代」这类措辞**均未证实**（检索记录 §十）。要么只用原文范例值，要么把未填状态显示成表单未填（阶段 1 用的就是这一手）。

11. **任何你声称的数字必须真的从 `data/*.json` 算出来**，或由你当场写出的组合恒等式推出。不许估、不许凭印象。

## 二、已定决策（不要重新论证）

1. **形态已定并已落地**：五屏的壳就是一份入院记录——页眉「一般情况」+ 步条（现病史 · 病前功能 · 待查诊断 · 拟诊讨论 · 告知）+ 逐屏笔迹标注 + 落款栏。文案收口在 `data/opening.json` 的 `record_shell`（页眉 8 笔 · `ink` 词表 · `steps` 5 栏 · `actions` 3 条 · `screens` 5 屏 · `sign` 4 条）与 `anchor_rule.screen`（屏 1 六句）。

2. **病历由经治医师书写，玩家是病史陈述者**（法规第十七条原话）。这条不是文案修辞，是形态：**玩家答、认、签，不执笔写病史正文。**

3. **「填写」= 在既成事实上落笔**，不是创作。已排除「自由拼装人生 / 自由书写病史」，理由：主题红线「**你无法选择出现什么，只能选择怎么面对**」——能写下未曾发生的事，红线即断。

4. **默认人物是苟智空，自建人物是同一套流程的另一条入口**，不是两套机制。两者只差**一般情况栏**与承载它的角色；锚点 → 池子 → 认下十段 → 疾病候选 → 认诊断 → 签名，全程共用。

5. **三个锚点问句即问诊**：`从什么时候开始` → 主诉/发病时间，`多久` → 主诉的持续时间，`怎么发生的` → 病程形式。**不要改动这三句**，它们已经是屏 1 的入口。

6. **卡片内部的门语汇（打开 / 关闭 / 代价 / 情境）本次不动**——门是 `疾病特长 §5.1` 的正典语汇，换口径属内容决定（[开局病历填报 §八.10](../presentation/开局病历填报.md) ⏳）。

## 四、必须解决的问题（每条都要可算或可机械核）

1. **栏位落笔表（本次的核心交付）。** 把病历上出现的**每一个栏位**列成一张表：`栏位名` · `谁落笔`（患者自填 / 院方书写 / 只读 / 系统定）· `玩家用什么动作`（闭集答 / 逐条认 / 逐条表态 / 签名 / 无）· `数据来源`（哪个块的哪个键）· `空白时显示什么`。表要覆盖：一般情况的 8 笔、主诉、既往与个人史（那十段）、病前功能、待查诊断、患者意见、告知、落款。**给出机械判据**：怎样从数据上判定"这一栏不是玩家能自由写的"。

2. **双人物来源的数据形状。** 默认人物苟智空放哪（`record_shell` 内？新块？`meta` 旁？）；自建人物的**闭集词表**长什么样（性别 / 年龄段 / 职业类别 / 婚姻 / 出生地——**这些取值现在数据里不存在**，是你的新建 canon）。必须回答：加一个可选项改几个文件；这套词表与 `vocab`（11 facet / 48 值）的边界怎么保证不互相污染（不得成为第 12 个 facet，不得进锚点/配额/疾病候选）。

3. **自建人物与《无法离开医院》的关系。** `dis_0027` 是恒常开的固有项，而它的症状②「身份黏着」建立在**手环上的名字与自述不一致**（苟笙 ≠ 苟智空）。自建人物怎么办？给结论 + 备选：

   - (i) 院方记录栏**永不由玩家写**：自建人物也会得到一个与自述不同的院方记录（名字 / 编号由系统给）——保住 §4.6 的四个症状；
   - (ii) 自建人物不触发身份黏着 ⇒ §4.6.2② 需要 owner 重裁（**这是 canon 改动，必须标 ⏳ 并说明影响面**）。

   **不得第三条路：既让玩家随便起名、又假装矛盾还在。**

4. **人物来源的选择发生在哪一刻、改了怎么办。** 开始界面？病历页眉？落锚之前还是之后？换人物时已经认下的十段 / 已认的诊断 / 已填的一般情况分别**保留、清空还是灰掉**——给结论与理由（提示：锚点一变池子就换，池子里的一切必须重核，见 `reconcileExperiences`）。

5. **「患病史」的落点与交互形态。** 那十段落在病历的哪一栏（现在叫「既往与个人史（患者陈述）」），形态是**勾选框**、**医生已写好你逐条按手印**、还是**逐条「以上属实」**？给结论 + 判据（§一 第 6 条）。注意：形态一旦像"自填表"，玩家就会以为自己在写病史——这是本设计最主要的自伤风险。

6. **主诉栏怎么写。** 三个锚点答案如何落成一行主诉（法规格式：**症状 + 持续时间**；省级细则另有「不超过 20 字、能导出第一诊断」的口径）。给**文案模板 + 可算判据**：生成文本不得含内部词、不得含 `text_lint` 禁字、不得把取值标签原样抄进记录文案（`title` / `summary` 仍受 lint 管，病历渲染文本不受——这条边界要写进文档）。

7. **自建人物要不要填年龄。** 与 `onset` 三档（童年 / 少年 / 成年）、与阶段 1 那一笔「年龄：自述与院方记录不一致」的关系。给结论：填 / 不填 / 只填粗档，以及是否引入一致性约束（例如自述年龄与 onset 冲突时怎么办）。⚠️ 别忘了年龄是 [开局病历填报 §八.4](../presentation/开局病历填报.md) 的待裁项，你的结论要能替它收口或明确标 ⏳。

8. **`general` 那一块要不要拆。** 现在 8 笔是写死的一串 `{label,value,ink}`；加了"玩家可填"之后它至少多了 `谁落笔` 与 `空白态` 两个维度。给出新 schema，并说明**旧 schema 怎么迁移**（不许留两份）。

- 不要碰机制、不要碰 288 段经历与 26 张病的内容、不要碰战斗相关内容。
- 不要引入任何神经模拟系统概念。
- 不要做自由文本输入、不要做"自己拼人生"的变体、不要让院方栏变成可写。
- 不要新增第 12 个 facet，不要让一般情况参与锚点 / 配额 / 疾病候选。
- 不要把「默认人物」与 `dev-default.js` 那个开发夹具合并。
- 不要自造临床取值枚举（可靠程度、两系三代之类）。
- 不要为显得完整而堆字段——每个字段都要能写出一句具体的"调用方拿它查什么"。
