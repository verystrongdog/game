## 你的任务

把开局的**问诊**从「从 facet 体系长出来的八问」换成**真实精神卫生门诊初诊的问诊流程**，
再把开局这份病历按**门诊初诊病历**的格式写出来：

1. **问什么，照真实门诊来**：开场与主诉 → 症状细节（情绪 · 睡眠食欲精力认知 · 焦虑惊恐强迫创伤解离 · 精神病性 · 躁狂）→ 风险 → 物质与躯体 → 既往与家族 → 个人史与社会心理 → 精神检查 → 结束与求诊期望。**按主诉分支追问**，不是平铺一张问卷。
2. **病历格式照门诊初诊来**：栏目、顺序、每一栏由谁落笔，都按 §四 检索到的一手规范写，不许自造栏目名。
3. **本阶段不接**项目里预设的 288 段经历与 26 张病：开局流程不再筛池子、不再出疾病候选、不再结算属性。**数据与实现一律保留原样**，只是开局不再调用它们（见 §八）。

产出可直接落地的契约：**新检索记录 + 题库与分支契约 + 门诊病历栏目与落笔表 + Web 原型 + 校验判据 + 测试**。

**不是**产出玩法哲学，**不是**给病人做诊断，**不是**把门诊流程压缩成三问，**不是**删掉现有的经历/疾病数据。

## 四、第一交付：一次新检索（门诊病历 + 门诊问诊）

**现状**：`design/spec/material/ref/精神科入院病历-书写规范-检索记录.md` 只覆盖**住院**病历（第三章 · 入院记录）。**门诊病历在第二章**，现有记录里一个字都没有。开局这一份病历要按门诊初诊格式写，所以必须先补检索。

### 4.0 已经替你核过的一手锚点（**引用前请自己再打开源页确认一次**）

来源：《病历书写基本规范》（卫医政发〔2010〕11 号）第二章 · 门（急）诊病历书写内容及要求
[郑州市基层政务公开全文](https://eq.jiceng.zhengzhou.gov.cn/021011002/6447542.jhtml)（与现有入院记录检索记录用的是同一个源）

> **第十一条** 门（急）诊病历内容包括门（急）诊病历首页（门（急）诊手册封面）、病历记录、化验单（检验报告）、医学影像检查资料等。
> **第十二条** 门（急）诊病历首页内容应当包括患者姓名、性别、出生年月日、民族、婚姻状况、职业、工作单位、住址、药物过敏史等项目。门诊手册封面内容应当包括患者姓名、性别、年龄、工作单位或住址、药物过敏史等项目。
> **第十三条** 门（急）诊病历记录分为初诊病历记录和复诊病历记录。
> **初诊病历记录书写内容应当包括就诊时间、科别、主诉、现病史、既往史，阳性体征、必要的阴性体征和辅助检查结果，诊断及治疗意见和医师签名等。**
> 复诊病历记录书写内容应当包括就诊时间、科别、主诉、病史、必要的体格检查和辅助检查结果、诊断、治疗处理意见和医师签名等。
> **第十四条** 门（急）诊病历记录应当由接诊医师在患者就诊时及时完成。

**由此得到的三条硬结论**（本阶段的设计要围着它们转）：

1. **门诊初诊栏目的法定清单就是第十三条那一串**：就诊时间 · 科别 · 主诉 · 现病史 · 既往史 · 阳性体征 · 必要的阴性体征 · 辅助检查结果 · 诊断 · 治疗意见 · 医师签名。
2. ⚠️ **个人史 / 家族史 / 精神检查都不在这一串里**——它们是**住院**病历的条目（第三章 第十八条（五）、（七））。
   但 owner 要的正是「询问病人的**过往病史**」，而精神科门诊实际也会写精神检查。所以这三样怎么办，是 §十二 待裁 #1 的核心，必须靠**检索**解决：
   找省级门诊病历规范 / 精神科门诊病历书写要求 / 教材，看精神科门诊病历里「个人史 · 家族史 · 精神检查」写在哪一栏、叫什么名字。
   **找不到出处的，不许自己加栏**——要么折进已有的法定栏（如家族史折进既往史），要么标 ⏳ 并说明。
3. 「诊断及治疗意见」这两栏在第十三条里是**接诊医师**写的：本阶段不做疾病候选（§八），所以这两栏只能留白或由院方写占位——见 §十二 待裁 #3。

**产出**：`design/spec/material/ref/精神科门诊病历-书写规范-检索记录.md`

**要求**（格式照抄现有那份检索记录：§一 检索参数 → 逐条编号 → §末 未查到/存疑 + 来源清单）：

1. **门诊病历的法定栏目**：逐字抄原文（章、条号、款项），并给出**初诊病历记录**与**复诊病历记录**的差别。★这是本阶段最硬的一条。
2. **门诊病历的书写要求**：谁写、什么时候写、要不要签名、门诊病历与住院病历在栏目上的差异（哪些栏只在住院病历里有）。
3. **精神科门诊特有的部分**：精神检查在门诊病历里落在哪一栏、风险评估（自伤/伤人）在规范里有没有位置、量表结果算不算辅助检查。
4. **问诊动作的规范依据**：能查到「问诊」的规范/教材原文就收（例如病史采集的要素、供史者与可靠程度、保密例外），查不到就写进 §未查到。
5. **每一段都要标来源与**「来源性质」（国家规范 / 省级规范 / 教材 / 教学稿 / 网络转载）——现有那份记录里对来源性质的分级要沿用。

**诚实核算**：抓取失败的链接、只有二手转述的说法、你没能证实的枚举，全部写进「未查到 / 存疑」。宁可少一条，不许编一条。

## 五、第二交付：问诊骨架（题库 · 分支 · 一局问多少 · 拒答）

**问题与答案的唯一权威 = 新数据文件**（§九 给了名字）。设计文档只写口径，不抄清单。

### 5.1 题库

1. 把 §三 归类后的**全部问题**逐条落进数据（含参照里的 113 问——一条都不许丢，丢了要说明为什么）。
2. 每题一条记录，至少带：`id` · 模块 · 医生问法（**第一人称口吻**，能直接当台词）· 答案闭集引用 · 是否必问 · 触发条件（分支）· 依据（法规/教材条目，或 ⏳）· 敏感标记与内容提示。
3. **医生口吻**，不是问卷口吻：问法要能读出口（「今天怎么想到来精神卫生门诊？」而不是「求诊原因：」）。
   参照的「通用追问」（能具体说说吗 / 一周几次 / 每次多久 / 最严重时什么样 / 当时你怎么想）要作为**可复用的一层**收进数据，别在每条问题里各写一遍。

### 5.2 答案闭集

1. **一律闭集、一律患者口吻**（「睡得着 / 入睡要很久 / 夜里总醒 / 早醒 / 整夜几乎没睡」这种，不是量表选项）。
2. **单值 / 多值**由问题决定，多值要写 `min_items` / `max_items`。
3. 答案不许把结论塞进取值里（别出现「重度抑郁」这种诊断名）——判据要机核。

### 5.3 拒答是一档合法答案（本阶段新增的红线友好设计）

**每个问题都有一档「不愿说」**（敏感问题尤其必须）。理由有二：临床上病历真的会写「患者拒答」；本作主题是**你无法选择出现什么，只能选择怎么面对**——患者能拒绝开口，但拒绝不了记录被写下去。

- 拒答时，病历上写**规范允许的写法**（去 §四 的检索里找，找不到就标 ⏳，不许自造），
- 且**拒答不会让开局走不下去**（这是硬判据，要有机核：任何拒答组合下开局都能写完并签字）。

### 5.4 分支：按主诉走，不平铺

```
开场与主诉（必问）→ 按主诉进对应的症状群（情绪 / 睡眠 / 焦虑 / 精神病性 / 躁狂 / 物质 …）
  → 风险（必问，可拒答）→ 物质与躯体 → 既往 / 个人 / 家族 → 精神检查（医方观察，玩家只读）
  → 结束与求诊期望（必问）→ 落款
```

- **必问骨架**：开场主诉 · 风险 · 既往 · 结束期望 这几块与主诉无关，任何一局都要问。
- **分支**：症状群按主诉选；同一模块内部按**已答的答案**决定要不要追问（例如答「夜里总醒」才追问「醒后还能再睡着吗」）。
- **要报数**：题库总数 · 必问骨架的问数 · 每个主诉分支的一局问数（给出最小/最大/中位）· 全部可能分支的总数。**目标：一局实际问到的 ≤ 40 问**；超出就要说明为什么删不掉。

### 5.5 不许出现的问法

- 不许把 `facet` 语汇漏回屏幕：`在哪` · `和谁` · `圈内还是圈外` · `你能决定多少` 这类**分类轴语言**一律不许出现在问题或答案里（它们正是 owner 判定「问的不对」的东西）。
- 不许问「你属于哪一类」「你想成为什么样的人」这类**让玩家拼人生**的问（[经历结构 §七 反例 15](../entities/经历结构.md)）。
- 不许出现需要玩家写字的问（没有自由文本）。

## 六、第三交付：开局病历（门诊初诊格式）

1. **栏目、顺序、每一栏的名字**全部来自 §4.0 的一手原文 + §四 的补充检索结果：每一栏都要能指到一条法规/教材出处（出处写进数据的 `basis`）。
   查不到出处的栏目 → 不许自造，标 ⏳ 并从纸上拿掉（个人史 / 家族史 / 精神检查这三样尤其要走这一步）。
2. **栏位落笔表**（沿用[开局病历填报 §十一.2](开局病历填报.md) 的三档口径）：每一栏标出
   `who`（患者陈述 / 院方记录）· `fill`（玩家能落 / 院方写 / 只读现算）· 空白态文案 · 取值从哪来。
   - **患者侧**：只由问诊答案填（`fill: patient_input` 的笔必须指到一个闭集）。
   - **精神检查**：门诊病历里它是**医师的观察**，玩家**只读**——它不许由玩家的答案现算（这是精神科文书的分工，见 [开局病历填报 §3.1](开局病历填报.md)）。
   - **诊断/处理意见**：本阶段**不由玩家落笔**（不做疾病候选）。留白 + 说明，或按门诊病历的写法由院方写一句原型口径的占位——**二者选一并在文档里说清**。
3. **纸上不许有永远填不上的栏**：属性结算、疾病候选、患者意见这些**接不上的笔一律撤掉**，不要留在纸上当摆设。
4. **主诉与现病史**：按 §四 检索到的门诊写法。主诉仍然是「主要症状（或体征）+ 持续时间」，且**症状那一半是患者自己说的**（这条没变，见 [开局病历填报 §十四](开局病历填报.md)）。
5. **两种笔迹仍然分得开**（患者陈述 / 院方记录），配色沿用现有的浅底高对比方案（正文 ≥ 4.5:1）。
6. **落款**：医师签名 + 病史陈述者（患者）签名。签名那一拍的文案要有依据（去检索）。

## 七、第四交付：Web 原型（纸 + 问诊条 + 分支）

1. **形态沿用**（owner 已裁过，不要重新设计）：**一屏一张纸 + 贴着纸的问诊条**；正在填的那一栏高亮；已填的显示文字；没填的显示自己的空白态（[开局病历填报 §十三.1](开局病历填报.md)）。
2. **一问一答**：医生问一句 → 患者从闭集里答一句 → **答案当场写成纸上的字** → 自动进下一问；「改一改」回到那一问重答。
3. **分支要看得见**：因为答了什么而多问出来的问题，界面上要说得清（例如问诊条上标这是追问），不许让玩家觉得问题凭空冒出来。
4. **敏感问题**：问之前显示数据里的内容提示；「不愿说」是按钮，不是隐藏操作。
5. **入口**：`web/src/prototype-bootstrap/index.js` 的开局入口切到新模块（仍是「开始新游戏」后的阻断式开局）。
6. **无头自检脚本**：`web/scripts/render-clinic.mjs`（照 `render-cc.mjs` 的写法）：`--check` 报形态自检（自由文本 0 · 旧 facet 语汇 0 · 栏目序列 · 问诊条在），`--all` 走完一局并逐段打印。

## 十、自检（要报数字，不许估）

```bash
cd web && bun test                      # 起点 303 pass / 0 fail；旧测试一条都不许变红
bun run build                           # 必须通过
bun web/scripts/render-clinic.mjs --check
bun web/scripts/render-clinic.mjs --all # 走完一局
```

契约校验（新写一个 `validateClinic(db)`，开发期函数，**没有任何 CI 在跑它**）：

| 判据 | 要求 |
|---|---|
| 每一问都有闭集 | 缺一档取值即报错 |
| **每一问都有「不愿说」** | 并按敏感标记分级（哪些必须、哪些可选） |
| **自由文本 0 处** | `web/src/opening-clinic/` 里搜 `textarea` / `contenteditable` / `<input` = 0 |
| **拒答不锁死** | 枚举全部拒答组合，每一种都能把病历写完并签字 |
| 栏目出处 | 每一栏都能指到 §四 检索记录里的条目；指不到的即报错 |
| 上屏文案不漏内部词 | 问诊/病历文案里不出现 `facet` · `锚点` · `字段` · `维度` · `池子` · `配额` · `selector` 等 |
| **答案里不藏诊断名** | 答案取值不得包含 `data/diseases.json` 的任何病名 |
| 一局问数 | 每个分支报出实际问数；> 40 要说明 |

**人肉核法**（没有工具时）：① 数一遍题库条数是不是 113 + 分支追问；② 抽三个主诉分支，手走一遍看会不会卡住；③ 搜界面代码有没有中文文案字面量；④ 逐栏问「这一栏的出处是哪一条」。
