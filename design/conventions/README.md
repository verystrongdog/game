## 一、架构边界

**游戏设计文档是 primary artifact；代码是验证与实现工具。**

```
design/     设计文档（正典）         ← 唯一真相源，回答"这个游戏是什么"
reference/  外部参考与已废弃子系统   ← 文献锚点，不参与正典
code/       实现与验证              ← 服务于设计验证，不反向定义设计
data/       结构化数据契约           ← 参数真值源
```

| 边界 | 规则 |
|---|---|
| design ↔ code | 代码里的数值必须与 `design/` 正典一致；不一致时以 `design/` 为准并修代码（例：`CalibrationConfig.NpcHp` 曾长期停留在 15，而权威表为 20-30） |
| design ↔ data | `data/canon/` 是引擎消费的契约；参数的权威定义在 `design/`，`data/` 是其机器可读形态 |
| code/unity | Unity 工程是**纯呈现**，不承载逻辑正典。逻辑正典在 `code/src/`（C# 类库） |
| 跨语言 | 设计文档（中文）→ `data/*.json` → 引擎消费。三者的参数必须可机械比对 |

**设计分界**：玩家交互 = 3D 技能树 + 快捷槽，技能直接走数值结算；NPC AI = 脑区链路预烘焙查表（6 性格标签 → 髓鞘化偏移 → 27 情境 × SAN 分段行为概率分布）。

## 二、内容禁令

以下是被**明确否决**的方向，不得重新引入（详见 [决策树 — 被否决的方向](../decisions/01-rejected-directions.md)）：

- ❌ 用颜色表示情绪/态度（颜色系统已废弃，用 PAD 向量）
- ❌ 离散 ±1/0 态度晶体（改用连续空间）
- ❌ 把"态度"当作独立实体或卡牌类型（态度是结算结果的组合，不是实体）
- ❌ 卡牌交互方式（已迁移至 3D 技能树）
- ❌ 把战斗简化为"削血"逻辑
- ❌ 治疗模拟框架（世界观是意识外显效应，不是治疗中心扮演）
- ❌ 在代码中使用与设计文档不一致的公式
- ❌ 凭空添加设计文档中没有的机制

**术语使用禁令**（防止旧模型回流）：

| 术语 | 现状 | 禁止 |
|---|---|---|
| 态度 | ⚠️ 已废弃 | 不要说"态度卡"、不要当作实体 |
| 7 驱动 / 5 模块 | ⚠️ 已废弃 | 技能分类当前口径是 **主导网络（Kroell 14 网络）× 主导角色（8 行为角色）** |
| CPM | ⚠️ 已废弃 | — |
| 意志力 (WP) | ⚠️ 已废弃 | 已替换为**认知负荷模型**（`design/rules/skill-tree/脑功能层级模型.md` §十三） |
| PAD | ✅ 活跃（情绪表示） | 作为**技能定位空间**已废弃（坐标已迁 MNI 解剖坐标） |
| SAN | ✅ 活跃 | 是护盾不是血条；SAN 与 HP 可互相转化但有上限 |

完整术语状态以 [`data/term_registry.json`](../../data/term_registry.json) 的 `status` 字段为准。

## 三、文档格式规范

**文件头部**

```markdown
# 文档标题

> 一两句话摘要——本文档的核心内容和定位。
```

**文件尾部**

```markdown
---
*创建: YYYY-MM-DD | 更新: YYYY-MM-DD*
*关联: [文档名](相对路径), ...*
```

| 规范 | 要求 |
|---|---|
| 目录 | 超过 200 行的文档，在摘要后加 `## 目录`（有序列表链接到各 `##` 小节） |
| 小节编号 | 用 `## 一、标题` 中文数字（便于交叉引用，如"见 §二"） |
| 一个文件一个主题 | 不要在一个文件中放多个 H1 |
| 参数速查表 | 涉及数值参数的文档，文末加表，列名统一为 `\| 参数 \| 符号 \| 默认值 \| 位置 \|` |
| 语言 | 设计文档用中文；代码注释中英皆可 |

**豁免**：`SKILL.md` 与其它**可执行指令文档**的小节标题可用描述性文字，不要求中文数字编号。

## 四、引用与参数规范

完整规范见 [写作与引用规范](writing-and-references.md)。要点：

- **路径**：仓库根相对路径或正确的相对路径；优先段引用（`§八`）而非 URL 锚点（渲染器差异）
- **参数**：所有数值参数必须有**来源注释**（文献出处或设计文档章节）。新增参数标注 `[NEW]` + 来源编号，关闭后下一次编辑该文件时摘除
- **交叉引用**：`[显示文本](相对路径)`，展示文本清晰描述目标（不只是裸文件名）
- **引用即读取**：任何事实性引用（参数、公式、已有决策、文件路径）**必须先读源文件确认**，不得凭记忆引用。这条不因工具或流程变化而豁免
- **数学语言**：能用公式/表格/受控词表表达的数值、分支、阈值、枚举，一律用数学语言。模糊量词（`较大`/`若干`/`通常`/`取决于`/`从…到…` 等）在可量化语境中不可接受。完整规范见 [数学语言书写规范](agents/math-language-writing.md)

## 五、术语注册表

[`data/term_registry.json`](../../data/term_registry.json) 记录术语的项目内定义、"已否决的默认模型"与偏离原因。

**触发更新**（三者任一）：

1. 引入注册表中没有、且项目内有自定义含义的新术语
2. 已有术语的 `definition` / `old_model` / `deviation_reason` 被实质修改
3. 两个已有术语的边界被重新划分

**覆盖范围**：设计文档的表格列头与参数名中出现的 ≤4 ASCII 字符短标识符，一并入库；**不在注册表中的短标识符默认视为未定义**。

**状态**：注册表是**术语参考**，不是准入门禁。它不阻塞任何改动，只用于核对术语是否已被否决。

## 六、归档与隔离

| 目录 | 语义 | 活跃文档可否引用 |
|---|---|---|
| `design/archive/trash/` | 垃圾箱——确实废弃、不再作为数据源 | ❌ **不得引用** |
| `design/archive/grilling/` | grilling 源记录归档（决策记录 / 任务计划 / 工作稿） | ⚠️ 仅历史叙述，不得当作设计依据 |
| `design/decisions/` | 决策树（跨轮次索引与分叉记录） | ✅ 可引用（历史层） |
| `reference/deprecated/` | 已废弃子系统，**保留为参考数据源** | ✅ 可引用（数据源） |

**隔离原则**：内容移入垃圾箱后，项目中任何活跃文档（含索引、README、规格文档、状态表）不得引用其路径。移动文件时必须 grep 全项目所有引用该路径的地方，一并更新。废弃的数字/术语同理——只允许出现在决策树历史记录与标注了 `⚠️ 已废弃` 的段落中。

机械校验：[`code/tools/validate_trash_isolation.py`](../../code/tools/validate_trash_isolation.py)

## 七、Git 工作流

**提交**

- **小步提交**：完成一个独立文档、一个可运行脚本或一批关联修改即提交，不等"全部做完"
- **按主题分批**：不同子系统的改动分开提交
- **提交信息用中文**，格式 `类型: 描述`：
  - `feat:` 新功能/新系统 · `docs:` 文档 · `sim:` 模拟脚本 · `fix:` 修正 · `refactor:` 结构重组 · `chore:` 杂项

**分支**

- `main` — 唯一真相源，永远可发布
- `feat/<功能名>` — 新子系统或大规模重构
- `exp/<实验名>` — 不确定方向的实验

**危险操作**（`git reset --hard` / `git rebase` / `git push --force`）必须先确认。
