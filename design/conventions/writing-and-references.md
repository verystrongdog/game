# 写作与引用规范

> 设计文档的**引用格式与参数定义**统一标准：文件路径怎么引、参数怎么写、决策怎么引、交叉引用怎么标。任何文档（人类或 AI 撰写）都应遵守。

## 一、文件路径引用格式

```
# 段引用（推荐，最稳健——不受行号漂移影响）
`规则/核心机制.md` §八             →  文件 §节号
`规则/核心机制.md` §5.1            →  文件 §子节

# 精确引用（需要精确到行时使用，注意行号随编辑漂移）
`规则/核心机制.md:314`             →  文件:行号
`data/canon/brain_regions.json`    →  完整相对路径（数据文件不需要行号）
```

**选择原则**：优先段引用。仅在需要精确定位某句话（如引用某个特定数值）时附加行号。行号是易碎品——每次编辑都可能导致漂移。

**路径基准**：所有路径使用**仓库根目录下的相对路径**。跨目录引用时按引用文件所在目录计算（见 §四）。

## 二、参数定义规范

所有数值参数在文档中定义时，使用统一格式：

```markdown
| 参数 | 符号 | 默认值 | 范围 | 来源 |
|------|------|--------|------|------|
| SAN 基线 | SAN₀ | 80 | 70-90 | `规则/核心机制.md` §5.1 |
| 敌人杂兵 HP | NpcHp | 25 | 20-30 | `实体/敌人与事件.md` §4.1 |
```

**来源列必填**，且必须是可核验的引用（设计文档章节 / 文献出处 / 数据文件）。违反此条即无法追溯参数依据。

### 2.1 新增参数标记

新增参数必须标注 `[NEW]` 与来源编号（design issue 或决策条目）：

```markdown
| 审核超时阈值 | T_review | 300s | 60-600 | [NEW] [#16] |
```

**`[NEW]` 标记生命周期**：在所属 issue 关闭后，**下一次涉及该文件**的编辑中摘除。超过两轮编辑仍未摘除视为过期标记，应改为 `[NEW-since-#xx]` 或移除。目的是防止标记长期残留（"下一轮"可能与参数所在文件完全无关，导致无人看到该标记）。

### 2.2 参数速查表

涉及数值参数的文档，文末加参数速查表，列名统一为 `| 参数 | 符号 | 默认值 | 位置 |`。

## 三、决策引用格式

```
# 决策树节点引用
决策树: <话题> §第N题  →  结论

# 设计归档引用（第一手决策记录）
设计归档: 设计归档/grilling/<slug>/决策记录.md §N

# Issue 引用
[#16] → https://github.com/verystrongdog/game/issues/16
```

**两层引用关系**：[决策树](%E5%86%B3%E7%AD%96%E6%A0%91/README.md) 是跨轮次的索引与分叉记录；`设计归档/grilling/<slug>/决策记录.md` 是单轮的原始结论正本。引用结论优先引决策树条目，需要完整追问过程时再引归档。

## 四、交叉引用规范

文档间的交叉引用统一格式：

```markdown
# 正确 ✅
详见 [核心机制 §八 可塑性巩固](../规则/核心机制.md) —— §八 可塑性巩固 小节

# 错误 ❌
详见 核心机制.md 的可塑性巩固部分
```

引用时确保：

1. 使用相对路径（相对于当前文件所在目录）
2. 展示文本清晰描述目标内容（不只是裸文件名）
3. 包含小节锚点（如适用）

**⚠️ 锚点兼容性说明**：Markdown 锚点生成规则因渲染器而异。GitHub 将 `## 八、可塑性巩固` 转为 `#八可塑性巩固`（去掉标点符号），但 VS Code 预览、Pandoc、或其他渲染器可能生成不同锚点。**如不确定目标渲染器，优先使用段引用格式（`§八`）而非 URL 锚点**——段引用是给人读的，不依赖渲染器行为。
