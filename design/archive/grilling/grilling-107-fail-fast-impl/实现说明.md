## 冻结设计未明示处的机械实现（解释，非越界）

1. **引擎测试临时 JSON 最小结构**：`TripartiteModel` 根对象只需含单类边数组（如 `{"brainstem": [{...}]}`），`graph_nodes`/`node_profiles` 走 init 默认空字典；边内仅 source/target 必填，其余字段有默认值。`[JsonRequired]` 在数组元素级生效（#106 Q1 实测），缺 role 即抛 JsonException。
2. **`"role":"active"` 正例单条覆盖**（brainstem 一条）：四类边共享同一 `SnakeCaseEnumConverter<EdgeRole>`，且真实数据测试（`LoadTripartiteModel_EnumFieldsAreParsed`）已覆盖四类显式 role 解析——单条正例足够，不重复四条。
3. **`FindDataDir` env 覆盖实现位置**：方法体首部首查 `Environment.GetEnvironmentVariable("YANTF_DATA_DIR")`（`is { Length: > 0 }` 判空），非空即返回；无效路径自然走 LoadAll 的 FileNotFound → 「数据目录缺失」fail-fast，符合 #106 精神。
4. **Console 夹具构造**：临时目录仅两文件——真实 `brain_regions.json`（File.Copy 自 `FindDataDir()`）+ `connectivity/tripartite_model.json`（缺 role 的 brainstem 单边）。`LoadAll` 顺序 brain_regions → tripartite（第 2 个）→ …：JsonException 先于后续文件 FileNotFound 触发。
5. **进程启动参数用 `--trace-resting 1`**（非无参默认 RunBattle）：RunBattle 读 stdin 交互输入，进程测试会阻塞；`--trace-resting` 走 WaitProvider 非交互。JsonException 在 LoadAll 阶段抛出，先于任何模式执行，模式选择不影响测试目标。
6. **新增测试数 346 → 353**：引擎 6（四类缺 role ×4 + null ×1 + active ×1）+ Console 1 = 7。
