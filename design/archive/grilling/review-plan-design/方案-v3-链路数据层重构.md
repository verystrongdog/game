## 一、背景与问题诊断

### 1.1 暴露的问题

Grilling #20 从"面具功能域数据层修正"出发，暴露了四层问题：

| 层 | 问题 | 证据 |
|----|------|------|
| **分类层** | 13 链路功能域无数据支撑，无法建模 | `角色与面具.md` §8.3 的域定义在 `link_legitimacy_matrix.json` 中无对应字段；疾病文件"功能域配置表"无法被数据验证 |
| **命名层** | 89 设计脑区名 ↔ DK 图谱名 ↔ brainstem 名三套体系混用 | 同一链路 `regions_a` 用中文设计名（`ACC`），`dk_pair` 用英文（`caudalanteriorcingulate`），`enigma_labels` 用左右前缀（`L_ACC`） |
| **粒度层** | 364 链路 = 160 组成对（L/R 各一）+ 20 组真实单侧 + 17 条自连 + 41 脑干——是"DK 左右边独立"的解剖粒度，不是 89 脑区对的抽象粒度 | `link_legitimacy_matrix.json` 成对链路差异全为 `L_`/`R_` 前缀（详见 §3.1 核查） |
| **范式层** | 技能系统基于"89 设计脑区"（含 29 个无数据抽象节点）+ 人工脑区组合，效果不可验证 | `操作层/L0-L6技能设计.md` 7 份共 37 个技能，脑区级定义，无链路数据支撑 |

### 1.2 核心范式判断

> **进化是"屎山"式积累复用，不是模块化设计**——182/364 条链路（50%）属于多个功能网络，13 功能域手工划分的边界语义破碎。分类建模应改为**无边界划分**的范式：链路上下文（网络集合归属 × 主导角色，D23）而非硬分类。

文献支撑：`reference/literature/复杂系统无边界分类-文献数据源.md`（Ahn 2010 链路社区 / Palla 2005 重叠社区 / Margulies 2016 梯度模型 / Airoldi 2008 MMSB）。

## 三、数据层重构

### 3.1 link_legitimacy_matrix.json 修正

**现状（2026-08-03 数据核查修正）**：364 条链路 = 皮层 323 + 脑干 41。皮层 = 160 组成对（L/R 各一）+ **20 组真实单侧**（L 10 / R 10）+ 17 条自连（跨半球 L↔R）。脑干 41 条中 **22 条 regions_b 为空**（只有 dk_target 英文名，无 89 脑区名）。

**修正方案**：

| 项 | 现状 | 修正 |
|----|------|------|
| 成对链路（160 组 = 320 条） | 同 dk_pair 同方向 L/R 各一条 | **保留左右为独立链路**（D10 解剖粒度）——`link_id` 增加侧向后缀：`link_000_L`、`link_000_R` |
| 真实单侧链路（20 条） | 仅 L 或仅 R（DTI 单侧通过阈值） | **保留，不补镜像**（假设对称是伪造数据）——标记 `hemisphere: "L"` 或 `"R"` |
| 自连（17 条） | `ACC ↔ ACC (L→R)` 跨半球 | 保留——胼胝体连接是真实解剖（PTSD 胼胝体异常文献支持），标记 `hemisphere_pair: "L→R"` |
| 脑干链路（41 条） | `brainstem_nucleus` 用中文（`蓝斑`） | 改为英文完整词（`LocusCoeruleus`），见 §四 |
| 脑干 regions_b 为空（22 条） | 靶区只有 dk_target（amygdala/hypothalamus…）无 89 脑区名 | 命名重构时用 `dk_target` 映射英文 ID（amygdala → Amygdala），或标注 `target_is_dk_only` |
| 多网络链路（182 条） | `coactivated_networks: [2-11 个]` | 保留原值（数据），新增 `primary_network = coactivated_networks[0]`（D23，仅染色主色/候选池标签）；上下文判定用**集合归属**（§3.3） |
| 抽象节点链路 | `regions_a/regions_b` 引用 29 个无数据脑区 | 见 §3.4 处置 |
| **关联键（D24）** | `link_behavior_roles.json` 的 `link_id: 0-363` 与 matrix **隐式对应**（数组顺序） | **`link_id` 重建为显式主键**（`link_000_L` 格式），同时写入 matrix + link_behavior_roles.json——唯一外键，消灭隐式对应 |

### 3.2 link_registry.json 统一

**现状**：`id: link_000` + `display_name: "ACC → 额中回尾部 (L)"`，`source_region/target_region` 用中文设计名。

**修正方案**：

```json
{
  "id": "link_000_L",
  "display_name_zh": "ACC → 额中回尾部 (L)",
  "source_region": "AnteriorCingulateCortex",
  "source_dk_name": "caudalanteriorcingulate",
  "target_region": "CaudalMiddleFrontal",
  "hemisphere": "L",
  "is_single_sided": false,
  "layers": [2, 5],
  "direction": "feedforward",
  "primary_network": "WorkingMemory",
  "role_scores": {"approach": 0.5, "support": 0.325},
  "data_source": "enigma",
  "enigma_strength": 2.75
}
```

- `id` 带侧向（D10）+ 显式主键（D24，与 link_behavior_roles.json 共享）
- `source_region/target_region` 用 **functional_id**（D25，英文唯一主键，如 `AnteriorCingulateCortex`）
- `source_dk_name` 保留 DK 解剖映射（D25，一对多——ACC/ACC背侧/前额叶极·SN 共享 caudalanteriorcingulate）
- `is_single_sided` 标记 20 条真实单侧链路（G5 空间断言豁免依据）
- `display_name_zh` 保留中文（显示层）
- `primary_network = coactivated_networks[0]`（D23，仅染色主色/候选池标签，非上下文判定）

### 3.3 上下文计算（D17/D18/D23 的数据基础）

**联合上下文 = 网络集合归属 × 主导角色**（D23 修复）：

```
networks(link)   = coactivated_networks（集合归属——多网络链路属多个上下文）
primary_role(link) = role_scores 中得分最高的角色
contexts(link)   = {(network, primary_role) for network in networks(link)}
primary_network(link) = coactivated_networks[0]（仅染色主色/候选池默认标签）
```

- **集合归属**：多网络链路（182 条）参与多个上下文的技能组（接口链路语义，无边界划分范式）
- `primary_role` 取最高得分者（阈值待定，见 G11）
- `primary_network` 不参与上下文判定（D23）
- 产出：`data/connectivity/link_contexts.json`（364 条 → 上下文集合映射）

## 五、技能系统范式迁移

### 5.1 新技能模型（D3-D8、D17、D21）

```
┌─────────────────────────────────────────────────┐
│  构建层（非战斗）                                 │
│  玩家操作: 髓鞘化（质量）+ 聚焦（数量）             │
│  髓鞘化: 链路使用即增长 m0→0.8→1.0（不改）          │
│  激活点: 常驻聚焦容量，随成长增长，无上限             │
│  聚焦: 把链路组配置为聚焦态（组内链路 ×2）           │
├─────────────────────────────────────────────────┤
│  战斗层（执行）                                    │
│  玩家操作: 快捷槽技能（6 个）+ 基础行动              │
│  技能 = 链路上下文（网络集合×主导角色）的链路组       │
│  技能激活 = 启用已聚焦链路组（D26: 非"聚焦"动作）     │
│  不消耗激活点（聚焦在构建时已配置）                  │
│  冷却/时机 = 技能的唯一战斗资源                     │
└─────────────────────────────────────────────────┘
```

### 5.2 技能生成机制（D21，方案 4）

```
Step 1: 规则穷举候选池（骨架）
  联合上下文 (14 网络 × 8 角色) → 每个上下文 = 候选技能
  过滤: 上下文内链路数 < 2 → 弃（无涌现基础）
  产出: 候选技能池（~80-112 个，数量由数据决定）

Step 2: 涌现触发（动态）
  候选技能 = 组内链路满足涌现条件时浮现（命名）
  涌现条件: 组内 ≥2 条链路 m ≥ 0.5 且 ≥1 条聚焦
  产出: 玩家实际可用的技能集（随构建变化）

Step 3: 设计锚点（用户灵感）
  灵感技能（忍无可忍/神经大条等）作为"钦定涌现"写入
  机制/数值/叙事 = 用户提供，数据层 = 上下文链路组
```

### 5.3 技能效果计算

```
skill_effect = Σ_{i ∈ skill_links} m_i × focus_i × rel(i, current_situation)

focus_i = 2.0  if 链路 i 被聚焦
          1.0  otherwise
```

- 技能数值**从链路数据计算**（可模拟验证），不是人工文字描述
- 调链路（髓鞘化/聚焦）→ 技能数值连续变化——"调整链路改技能数值乃至机制"（D3）

### 5.4 快捷槽与基础行动

- 快捷槽 6 个装技能（不改，`核心机制.md` §2.4 保留）
- 基础行动（物理攻击/精神攻击/防御/说话）保留为无链路要求的基础层
- 战斗中技能激活 = **启用已聚焦链路组**（D26），不消耗激活点（D7）

## 七、预烘焙管线重构

### 7.1 落后依赖（用户质疑确认）

| 依赖 | 旧成分 | 重构 |

### 7.2 重构方案

1. `situation_primitives.json` 的 `key_brain_regions` 英文化（A1）
2. **本期**：`rel(i,s)` 匹配逻辑保持"脑区命中"机制，仅英文化（`regions(link_i)` 英文 ID ∩ `key_brain_regions(situation)` 英文 ID）——最小改动、最小风险
3. **后续优化（不阻塞本期）**：情境→上下文 rel（情境映射到网络/角色，链路按 primary_network/primary_role 匹配）——预烘焙管线重构批次中评估
4. 输出链路配置中 `link_id` 加侧向（跟随 registry）
5. Softmax 公式不变（P(i) ∝ exp(β×m×rel)——本身就是链路级、全局激活的模型，与 D5 一致）
6. 技能效果验证并入管线：`skill_effect = Σ m×focus×rel` 作为管线派生输出（D4 验证载体选型）

## 八、3D 展示与染色方案

### 8.1 显示策略（结合原方案 1+4 + D19）

- 默认显示：**髓鞘化子集**（玩家拥有的链路）+ 当前激活链路
- 未髓鞘化链路：隐藏/半透明（可选"显示全部"切换）
- 链路按上下文染色（D19）：

```
色相层 = primary_network（14 网络 → 14 色相带，环绕色环均分）
明度/饱和度层 = primary_role（8 角色 → 同色相内明度偏移）
多网络链路 = 主色 + 次色渐变（视觉跨色相 = 桥接）
Hansen 脑干链路（41 条）= 独立中性色系（灰蓝，按 GREEN/PINK/YELLOW 社区微调明度）——不占 14 色相带（D29）
抽象节点（is_design_node） = 灰色 + 虚线（区别于解剖实体）
左右链路 = 同色相 + 侧向标识（L 实线 / R 虚线，或亮度微差）
```

### 8.2 组件链路区分

- 组件链路（面具激活/抑制）仍用不同颜色/材质（§8.10.2 保留）
- 病理链路不同颜色（§8.8.2 保留）

### 8.3 空间断言（D9）

- 左右镜像对成对存在（数量对称断言）——**豁免 20 条 `is_single_sided: true` 单侧链路**（G5 修复）

- mesh 缩放后节点不越界
- 抽象节点（is_design_node）跳过解剖断言
- 输出：`PASS/FAIL/WARN` 报告（符合 review-plan --pre-check 格式）
