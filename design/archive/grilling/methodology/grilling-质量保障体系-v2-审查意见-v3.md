## 🟡 重要级

### N1. 行 30-34 — §1.1 诊断表格 3 类问题仍缺举证

类型 3（决策深度不足）、类型 4（写入不完整/错位）、类型 5（跨文件矛盾）的"最近案例"列均为 `(待补充——建议...)`。作为质量保障体系的**诊断基础**，5 类退化中 3 类没有具体案例，削弱了问题诊断的说服力。

此前 S7 批改意见已要求补案例，v2 补上了类型 1、2（SAN 行号错误、subcortical_links 对抗性审核），但类型 3-5 的建议文字不是案例——是"如何去找案例"的方法论。

**建议**：从最近 3 轮 grilling（疾病系统、预烘焙管线、空间遭遇规则）中回溯至少各一例，或明确标注 `[待回溯填充]` 并给出触发条件。

---

### N2. 行 138 — Step 5.2 "运行自动化校验脚本"在阶段 2 前是空操作

§5.1 定义的 P0 脚本（`validate_cross_refs.py`、`validate_grilling_quality.py`）安排在阶段 2（"下一个工作块"）实现。但 §3.1 强化流程已将 Step 5.2 写入质量门禁——这意味着**阶段 1 完成后、阶段 2 完成前**的所有 grilling 都会在 Step 5.2 遇到"脚本不存在"的错误。

**事实核查**：`code/tools/` 下当前仅有 `validate_cards.py` 和 `validate_disease.py`，5 个新增脚本均未实现。

**建议**：在 Step 5.2 处加注：

```markdown
5.2 【新】运行自动化校验脚本（阶段 2 实现后启用；当前阶段手动执行等效检查：cross-ref grep + grilling 产物完整性目视核查）
```

或在阶段 1 checklist 中增加一项"手动等效检查清单"作为过渡方案。

## 🔵 建议级

### n1. 行 80-85 — §2.3 违规信号与合法引用边界模糊

违规信号列出 `"根据我们之前的讨论..."` 为凭记忆引用的标志。但如果 AI 在 grilling 中确实 Read 了对应的 memory 文件，然后说"根据我们之前的讨论（`memory/xxx.md` §N），…"——这是**合法的事实锚定引用**，不应标记为违规。

当前表述将特定短语 ≡ 违规，但正确逻辑是：特定短语 → **自检信号** → 验证是否有 Read 支撑 → 判定是否违规。

**建议**：在违规信号列表前加一句限定：

```markdown
出现以下短语时，AI 应触发自检（而非自动判定为违规）。自检通过（有 Read 记录支撑）则引用合法：
```

将语义从"违规信号"改为"自检触发信号"。

---

### n2. 行 179-197 — Step 0 产物模板未标注"示例"

§3.2 的"资料包完整性声明"模板使用了具体文件列表（`design/framework/dimensions/管线.md`、`design/rules/核心机制.md` 等），末尾说"共 5 个预读 + 2 个待按需读取"。这是以**管线维度 grilling** 为场景的示例，但模板中没有任何文字说明"以下为示例，实际文件取决于 grilling 话题"。

对于照着本文档执行的外部 AI/人类，可能误将这个具体文件列表当作固定模板复制。

**建议**：在模板代码块前加一句：

```markdown
> 以下为管线维度 grilling 的示例。实际文件列表取决于话题所属维度和影响范围。
```

---

### n3. 行 284-286 — `[NEW]` 标记摘除触发条件不可靠

> `[NEW]` 标记在所属 grilling issue 关闭后的**下一轮** grilling 内摘除

"下一轮 grilling"可能与该参数所在文件完全无关（如下一轮 grilling 是空间维度的关卡设计，但 `[NEW]` 参数在 `design/rules/核心机制.md` 中）。如果没有触发机制确保摘除者"看到"这个标记，`[NEW]` 将长期残留。

**建议**：改为双重条件：

```markdown
`[NEW]` 标记在所属 grilling issue 关闭后，**下一次涉及该文件**的 grilling 或文档编辑中摘除，
最迟不超过两轮 grilling。超过两轮仍未摘除视为过期标记，应改为 `[NEW-since-#xx]` 或移除。
```

## 正面评价

以下方面在 v2 中处理得很好：

1. **自指诚实**：§1.1 表格中类型 1 的案例是"本文档 v1 即犯此错"——质量保障文档用自身作为反面教材，公信力极强。

2. **段引用优先 + 行号漂移警告**（§2.3）：不满足于"修一个错误数字"，而是建立了防止同类错误的**机制**——这是 v2 最有价值的增量。

3. **双版本流程图**（§3.1）：box-drawing + 纯缩进双版本，兼顾美观和兼容性。

4. **附录 A CLI 规范**：`--format`/`--output`/`--base-dir` 标准化 + 退出码三级约定（0/1/2）——是可执行的 spec，不是模糊描述。

5. **迭代收敛轨迹**：v1 17 条 → v2 批改后 7 条残余 → v3 本轮 0 条阻塞。文档质量在迭代中持续改善，这正是质量保障体系有效的 evidence。
