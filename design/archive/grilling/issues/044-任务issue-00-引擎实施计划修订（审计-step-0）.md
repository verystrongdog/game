## 问题（这件事要解决什么）

**csharp-engine 这个 feature 的使命**：游戏的战斗核心是神经动力学——WC 动力学 → 脑干 tone → 基底节门控 → 速度排序 → 行动选择 → 伤害结算，敌我同构（双方都是"会算账的大脑"）。这些公式分散在设计文档（运行时状态模型 / 回合战斗流程 / 核心机制）里，**从未被拼起来执行过一次**——它们能不能组成一场合理战斗，零实验证据。Unity 实装之前必须先在 C# 里端到端验证。

**为什么现在是这一步**：2026-08-06 五层架构规划后代码暂停（阻塞于 #25 链路缺位）；#25 解剖基座重构、#26 三体神经模型、#32 运行时状态模型已补齐 → 阻塞解除，可以写引擎。

**为什么必须先修计划**：2026-08-12 四专家审计发现原计划照做会产出坏引擎——Euler 数值振荡永不收敛（F1）、无 HP/SAN 字段（F2）、大门算完没人用（F10：战斗沦为固定 4 伤害对砍，与"神经动力学产生合理战斗"的设计目标矛盾）。这些问题如果在 Unity 阶段才暴露，修复成本是 C# 阶段的 100 倍。
