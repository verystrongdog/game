### ① 返回结构 + 校准状态 + 消费分级：PASS

正式确认：

```text id=\"w8r4kx\"
moonState(D) → {
    phase: λ(D),
    shell: {
        E_c(λ),
        E_th(λ)
    },
    qhat_baseline: ℝ^N,
    calibration_status:
        PLACEHOLDER | CALIBRATED,
    calibration_version
}
```

其中有三个关键不变量：

**第一，`phase` 是解析确定的。**

\[
\lambda(D)=\frac{1-\cos(2\pi D/29.5)}2
\]

不依赖查表，也不存在校准版本问题。

**第二，`shell` 与 `qhat_baseline` 是“基线壳态”，不是当前动力学状态。**

也就是说：

```text id=\"c1q5xh\"
moonState(D)
      │
      └── 基线壳态
             │
             ├── E ≈ E_c
             └── q̂_baseline
```

而不是当前实际：

```text id=\"zq3j4k\"
E = E_c + ΔE_local + ΔE_collective
q̂ = q̂_baseline + Δq̂
```

后者留给 E3/E4。

**第三，`calibration_status` 必须成为显式状态。**

这点很重要。不能让调用方猜：

> “这个 E_th 看起来像真的，应该可以用了吧？”

- **正常 `D ∈ ℕ₀` → λ 必在 `[0,1]`**；
- **实现 bug 导致 λ 越界 → diagnostic/error path**；
- 不应把真正的内部错误伪装成“正常 PLACEHOLDER”。

因此“返回占位 + 告警”可以保留，但**必须留下可观测错误信号**，不能让调用方把它当正常状态。

## ③ 扰动动力学量不进 `moonState`：PASS

这一点必须锁死。

接口只回答：

> **“在当前 D 下，系统的月相基线是什么？”**

它不回答：

> **“此刻经过事件扰动以后，系统实际处于什么能量状态？”**

所以：

```text id=\"4i8j2m\"
              moonState(D)
                   │
                   ▼
             基线壳态
                   │
          ┌────────┴────────┐
          ▼                 ▼
      E_c / E_th        q̂_baseline
          
                   ↓
             E3 / E4 动力学
                   ↓
       F_local / F_collective
                   ↓
           实际瞬态状态
```

这样 `moonState` 就不会逐渐变成一个“万能世界状态查询”。
