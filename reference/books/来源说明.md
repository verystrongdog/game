## `a-philosophy-of-software-design-zh` — 为什么它不在仓库里

2026-09-12 从 CI 日志里发现：该路径自 `b74ff98`（`data: 参考书籍（APOSD/TDD/GPP）`）
起以 **gitlink**（子模块提交指针，mode `160000` → `ca89b238…`）形式入库，
但本仓**从未有过 `.gitmodules`**（`git log --all --diff-filter=AD -- .gitmodules` 为空）。

后果是「本地有、远端没有、**且不报错**」：

| 环境 | 表现 |
|---|---|
| 作者本机 | 嵌套仓库的 `.git` 还在 → 目录非空、一切正常，**看不出问题**（该副本已于 2026-09-12 随工作区清理删除） |
| 干净检出 / CI | 该路径**不进任何内容**（checkout 只记 gitlink、不 clone 内容）；`git submodule` 操作因缺 URL 报 `fatal: No url found for submodule path` → exit 128 |
| 报错位置 | checkout 的 **post 步骤**——不影响 job 结论，只在 annotation 里以 warning 出现，极易被当噪声略过 |

**处置**（2026-09-12，两步）：① `git rm --cached` 去掉悬空 gitlink；
② 本机那份纯上游副本（无任何本地改动、remote = yingang/aposd2e-zh）一并删除，
使工作区不留未受控残留。并给
[`check_clean_checkout.py`](../../code/tools/check_clean_checkout.py) 补了第 3 条检查
（**悬空 gitlink = 硬错误**），使这类缺陷既不再复发、也不再静默。

## 维护规则

1. 新增大部头参考书：**优先纯外部引用**（本文件登记来源）或**普通文件入库**，
   **不要留 gitlink**——除非确实要建子模块，那就必须同时提交 `.gitmodules`
2. 每本书登记：来源 URL、版本或提交、许可、入库形态
3. `check_clean_checkout.py` 会拦住悬空 gitlink；它红了不要绕过
