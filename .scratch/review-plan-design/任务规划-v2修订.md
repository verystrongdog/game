---

### 10.2 --pre-check 推荐格式 — 来源: #2, #3

**位置**: §十 "--pre-check 参数" 段末尾追加

**修改前**:
```
通用机制，不绑定特定领域（不是只能传 `validate_disease.py` 输出）。调用方自行决定跑什么脚本、传什么输出。审查引擎将其标记为"已验证基础层"，trace 时跳过已验证项。不传则 AI 从头 trace（包括格式/引用/参数层），退化风险较高。
```

**修改后**:
```
通用机制，不绑定特定领域（不是只能传 `validate_disease.py` 输出）。调用方自行决定跑什么脚本、传什么输出。审查引擎将其标记为"已验证基础层"，trace 时跳过已验证项。不传则 AI 从头 trace（包括格式/引用/参数层），退化风险较高。

### --pre-check 推荐格式

脚本输出建议遵循以下结构，便于引擎可靠解析：

```
# <脚本名> — <一句话描述>
## 检查范围
- <检查类别1>：<覆盖说明>
- <检查类别2>：<覆盖说明>

## 结果
PASS  <check_id>  <描述>  [位置]
FAIL  <check_id>  <描述>  [位置]
WARN  <check_id>  <描述>  [位置]

## 汇总
N checks: X passed, Y failed, Z warnings
```

脚本不遵循此格式时 → AI 语义解析原始输出，标注 `⚠️ 前置输入格式非标准，解析可能不完整`。
```

**理由**: 填补 #2 缺口——定义 --pre-check 输入的最低限度结构约定。两级：推荐格式 + 退化路径。同时为 #3（覆盖声明）提供了来源——"检查范围"段。
