# 术语注册表覆盖范围扩展 — 修改方案 v2

> 根因：`term_registry.json` 仅覆盖高风险语义级术语（月光/场/感染等），未覆盖项目文档中出现的**所有缩写/短标识符**。"AP"在基础行动设计表中未被注册表收录 → grilling §3.0 查询不到 → 旧 RPG 模型未被拦截。
>
> v1 方案（新增 §3.0b 缩略检查流程）→ 被否决：不需要新流程，注册表已有机制即可处理。问题是覆盖面，不是机制。

---

## 修改内容

### 一、term_registry.json — 全项目短标识符批量入库

#### 1.1 扫描范围

所有 `规则/` `实体/` `事件/` `空间/` `呈现/` `管线/` 下 .md 文件的**表格列头 + 参数速查表中参数名列**中出现的 ≤4 ASCII 字符标识符。

#### 1.2 入库标准

**全部入库**——不论是否有 RPG 冲突风险。

| 情形 | 操作 | old_model 字段 |
|------|------|---------------|
| 有 RPG 默认模型冲突 | 入库，status=active 或 deprecated（视项目语义） | 记录 old_model + deviation_reason |
| 与 RPG 默认模型一致（如 HP） | 入库，status=active | `—（与项目定义一致，无偏离）` |
| 项目独创（如 Δm） | 入库，status=active | `—（项目独创术语）` |
| 已废弃（如旧的 AP 用法） | 入库，status=deprecated | 记录 old_model + 废弃原因 |

#### 1.3 存量术语检查

已有 53 条术语逐一检查——哪些已在注册表、哪些缺失。已有术语不改动。

#### 1.4 入库执行

用户确认新增清单 → 批量追加到 `term_registry.json`。

### 二、基础行动设计.md — 去缩写

表头 `AP` → `动作`。参数速查表中 "AP" 同步修改。值是 `1` 不变。

### 三、CLAUDE.md — 规则升级

现有规则 "术语注册表即时更新" 已覆盖"新术语入库"。追加一条覆盖范围声明：

> **注册表覆盖范围（2026-08-05 新增）**：项目设计文档（`规则/` `实体/` `事件/` `空间/` `呈现/` `管线/`）表格列头和参数名中的 ≤4 ASCII 字符短标识符，**全部**纳入 `term_registry.json`。新文件引入新短标识符 → 同时入库。不在注册表中的短标识符 → 默认视为未定义。

### 四、不需要修改的部分

- grilling SKILL.md — 无需修改。已有的 §3.0 机制足以处理扩展后的注册表
- review-plan SKILL.md — 无需修改
- 其他设计文档 — 去缩写的只有 `基础行动设计.md` 中 `AP` 一处（其余短标识符如 HP/SAN/CD/m 已在项目中语义稳定）
