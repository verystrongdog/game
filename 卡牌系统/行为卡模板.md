# 行为卡模板

> **⚠️ 已废弃**：行为卡不再作为玩家交互手段。行为技能设计见 [技能树系统/行为技能设计](../技能树系统/行为技能设计.md)。21 张行为卡的驱动归属、AP、valence 等参数已映射为行为技能节点。本文档保留供设计参考。

> 行为卡的设计规格书。每张行为卡必须归属一个驱动（7 选 1），其可用性、成本和效果由当前 PAD 状态通过驱动激活函数动态决定。本文档定义行为卡的静态字段（卡面）和动态字段（运行时叠加），以及填写时需要的参数速查表。

## 一、字段规范

### 静态字段（卡面，永远不变）

| 字段 | 类型 | 说明 |
|------|------|------|
| `卡名` | string | 中文卡名，2-4 字，动词/动名词 |
| `驱动` | enum | 反射 / 惩罚机制 / 奖励机制 / 道德驱动 / 文化习俗 / 价值驱动 / 照护（7 选 1） |
| `valence` | int | 态度结算用：+1（趋近）/ 0（中性）/ -1（回避）。默认值见驱动表，价值驱动可取 ±1 |
| `基础AP` | int | 驱动激活度 α_i=1.0 时的 AP 消耗。通常 1-4 |
| `效果描述` | string | 一句话，玩家在卡面上看到的文字。不包含数值公式 |
| `基础效果` | string | 效果的机械描述，用于模拟脚本。如 "回避下次敌方攻击" / "回复 SAN 1 点" |

### 动态字段（运行时叠加到手牌显示）

| 字段 | 类型 | 说明 |
|------|------|------|
| `当前AP` | int | `max(0, round(基础AP × cost_modifier))`，`cost_modifier = 1 + β_i × (1 - α_i)`，限制在 [0.3, 2.5] |
| `标签` | enum | ★优势 / ⚠惩罚 / ‼强制 / —正常（见下方标签判定规则） |
| `意志力成本` | int | 仅 ⚠惩罚 标签时有效。`floor(C_control)` |
| `SAN磨损` | float | 仅 ⚠惩罚 标签时有效。`max(0, C_control - 1.5)` |
| `效果倍率` | float | `1 + γ_i × (α_i - θ_play_i)`，硬解锁时额外 × (1 - 0.15 × C_control) |

### 标签判定规则

| 标签 | 条件 | 显示 |
|------|------|------|
| ★ 优势 | α_i ≥ θ_play + 0.25 | AP 降低（折扣），效果增强 |
| — 正常 | θ_play ≤ α_i < θ_play + 0.25 | 正常 AP，正常效果 |
| ⚠ 惩罚 | α_i < θ_play（硬解锁） | AP 溢价 + 意志力成本 + 效果折扣 |
| ‼ 强制 | α_i ≥ θ_force（仅反射驱动有 θ_force=0.85） | 必须打出，可用意志力压制 |

### 悬停文案字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `优势悬停` | string | α_i 高时的 flavor text，如 "恐惧让你身体快过大脑——逃跑毫不费力。" |
| `正常悬停` | string | α_i 正常时的 flavor text |
| `惩罚悬停` | string | 硬解锁时的 flavor text，如 "你还没找到做这件事的信念。硬做需要意志力。" |
| `强制悬停` | string | 仅反射驱动，如 "恐惧已超出生理承受阈值。你必须打出一张反射卡。花 3 意志力可压制。" |

### 联动字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `combo_emotion` | list | 与哪些情绪卡打出时有额外加成（如 逃跑+恐惧 → AP 再 -1） |
| `combo_cognition` | list | 与哪些认知卡打出时有额外效果（如 面对+洞见 → 效果 +50%） |
| `冲突驱动` | list | 被哪些驱动压制时效果打折（如 惩罚机制被道德驱动压制） |

## 二、填写示例

### 示例 1：反射 — 逃跑

```yaml
卡名: 逃跑
驱动: 反射
valence: -1
基础AP: 1
效果描述: 避开下一次敌方攻击。
基础效果: 本回合获得"闪避"状态，下一次敌方攻击判定自动失败。

# 动态（运行时计算，此处为设计参考值）
当前AP: 见动态字段公式
标签: 见标签判定规则
意志力成本: 无（反射不可意志控制/压制）
效果倍率: 1 + 0.2 × (α_reflex - 0.15)

# 悬停文案
优势悬停: "反射驱动高度激活。恐惧让你身体快过大脑——逃跑毫不费力。"
正常悬停: "当前反射驱动未激活。你可以正常选择逃跑，但身体不推着你走。"
惩罚悬停: 无（反射不可硬解锁）
强制悬停: "恐惧已超出生理承受阈值。你必须打出一张反射卡。花 3 意志力可压制。"

# 联动
combo_emotion: [恐惧, 焦虑, 恐怖]
combo_cognition: []
冲突驱动: [道德驱动, 价值驱动]
```

### 示例 2：价值驱动 — 牺牲

```yaml
卡名: 牺牲
驱动: 价值驱动
valence: +1
基础AP: 3
效果描述: 放弃自身一项资源，对敌人造成大量心灵震慑。
基础效果: 消耗自身 SAN 2 点，对敌方造成 4 点心灵震慑。若 SAN 不足，改为消耗 HP。

# 动态
当前AP: 见动态字段公式  # cost_modifier = 1 + 1.5 × (1 - α_value)
标签: 见标签判定规则
意志力成本: floor(C_control)  # 硬解锁时
效果倍率: 1 + 1.0 × (α_value - 0.50)

# 悬停文案
优势悬停: "你清楚为什么值得。放弃不是损失——是交换。"
正常悬停: "你在掂量。有些东西比安全重要，但你需要确认。"
惩罚悬停: "信念还不够坚定。你可以硬撑，但代价很大，而且效果会打折。"

# 联动
combo_emotion: [爱, 愤怒, 希望]
combo_cognition: [推理与决策, 表象与语言]
冲突驱动: [反射, 惩罚机制]
```

## 四、参数速查表

### 4.1 7 驱动核心参数

| 驱动 | 默认 valence | θ_play | θ_force | β (成本敏感) | γ (效果增益) | C_base | φ 前置条件 |
|------|-------------|--------|---------|-------------|-------------|--------|-----------|
| 反射 | -1 | 0.15 | 0.85 | 0.5 | 0.2 | — | 无（短路通道） |
| 惩罚机制 | -1 | 0.20 | — | 1.0 | 0.5 | 见下表 | 知识表征完成 |
| 奖励机制 | +1 | 0.25 | — | 1.2 | 0.6 | 见下表 | 知识表征 ∧ 推理 |
| 道德驱动 | 0 | 0.35 | — | 0.8 | 0.7 | 见下表 | 规范性评估完成 |
| 文化习俗 | 0 | 0.15 | — | 0.3 | 0.2 | 见下表 | 知识表征完成 |
| 价值驱动 | ±1 | 0.50 | — | 1.5 | 1.0 | 见下表 | 五模块全部完成 |
| 照护 | +1 | 0.30 | — | 0.6 | 0.5 | 见下表 | 知觉与注意 + 知识表征 |

> 来源：`data/drives.json`、`行为系统/行为系统.md`

### 4.2 驱动激活公式 (sigmoid)

```
g_reflex  = σ(2.0·max(0,A-0.3) + 1.5·max(0,0.5-D) - 0.5)
g_punish  = σ(2.5·min(0,V) + 1.0·max(0,A-0.2) - 0.3)
g_reward  = σ(2.5·max(0,V) + 0.8·max(0,A-0.2) - 0.35)
g_moral   = σ(2.0·max(0,D-0.1) + 1.0·(1-|A|) - 0.4)
g_culture = σ(1.5·(1-|D|) + 2.0·C_score - 0.3)
g_value   = σ(1.5·max(0,D-0.4) + 3.0·Override_signal - 0.7)
g_care    = σ(2.5·Vuln + 1.5·Attach - 0.3)
```

### 4.3 认知门控 φ 的前置条件

| 驱动 | φ=1.0 条件 | φ fallback | 含义 |
|------|-----------|------------|------|
| 反射 | 无前置 | 1.0 | 短路通道——认知不参与 |
| 惩罚机制 | 知识表征完成 | 0.3 | 需要识别"这是什么威胁" |
| 奖励机制 | 知识表征 ∧ 推理完成 | 0.2 | 需要确认"值得追" |
| 道德驱动 | 规范性评估完成 | 0.1 | 需要确认"这是对的" |
| 文化习俗 | 知识表征完成 | 0.4 | 需要识别"这是什么场合" |
| 价值驱动 | 五模块全部完成 | 0.05 | 需要全认知链条支撑 |
| 照护 | 知觉与注意(注意到他人) + 知识表征(归为需要帮助) | — | 需要"看到"和"归类" |

### 4.4 驱动惯性（上升/衰减半衰期，回合）

| 驱动 | 上升 τ_rise | 衰减 τ_decay | 说明 |
|------|------------|-------------|------|
| 反射 | 0.3 | 0.5 | 最快激活，最快衰减 |
| 惩罚机制 | 1.0 | 1.5 | 中等——需要认知确认威胁 |
| 奖励机制 | 1.5 | 2.0 | 较慢——需要确认"值得追" |
| 道德驱动 | 2.0 | 3.0 | 慢速——规范性推演需要时间 |
| 文化习俗 | 0.5 | 0.5 | 快速——社会脚本执行成本低 |
| 价值驱动 | 3.0 | 5.0 | 最慢，最持久——信念不轻易改变 |
| 照护 | 0.3 | 随 Vulnerability_signal 消退 | 接近反射速度 |

### 4.5 CPM 步骤与驱动解锁时序

| 回合 | CPM 步骤 | 解锁的驱动 |
|------|---------|-----------|
| 1 | Relevance | 反射、文化习俗（惩罚机制可能可用，φ 只需知识表征） |
| 2 | Implications | 奖励机制（φ 需要推理模块） |
| 3 | Coping | 道德驱动（φ 需要规范性评估） |
| 4+ | Normative | 价值驱动（φ 需要全部五个模块） |

## 五、硬解锁 C_control 速查表

行为卡在 α_i < θ_play 时需硬解锁。`C_control = C_base + C_resistance`，其中 `C_resistance = 2.0 × σ(|V - V_drive| × |A| × 3.0 - 1.5)`。

下表为 ε=0 时的 C_control 值（✕ = 该情绪下此驱动不可用）：

| 情绪 | 反射 | 惩罚 | 奖励 | 道德 | 文化 | 价值 | 照护 |
|------|:----:|:----:|:----:|:----:|:----:|:----:|:----:|
| 快乐 | ✕ | ✕ | 0 | 0 | 1.2 | 0 | 1.4 |
| 爱 | ✕ | ✕ | 0 | 0 | 0.4 | 0 | 1.4 |
| 共情 | ✕ | 0.8 | 0 | 0 | 0.5 | 2.5 | 1.5 |
| 平静 | ✕ | ✕ | 0 | 0 | 0.9 | 2.7 | 1.7 |
| 希望 | ✕ | ✕ | 0 | 0 | 0.7 | 0 | 1.4 |
| 敬畏 | ✕ | 0 | 2.0 | 1.5 | 0.4 | 3.0 | 2.0 |
| 愤怒 | ✕ | 0 | 2.8 | 0 | 1.0 | 0 | 2.8 |
| 恐惧 | 0 | 0 | 2.8 | 2.4 | 1.1 | **3.8** | 2.8 |
| 焦虑 | 0 | 0 | 2.8 | 2.3 | 1.0 | **3.8** | 2.8 |
| 厌恶 | 0 | 0 | 2.7 | 2.2 | 1.0 | **3.7** | 2.7 |
| 恐怖 | ✕ | 0 | 2.8 | 0 | 1.1 | **3.8** | 2.8 |
| 绝望 | 0 | 0 | 2.7 | 2.2 | 0.9 | **3.7** | 2.7 |
| 内疚 | ✕ | 0 | 1.6 | 1.5 | 0.4 | 2.6 | 1.6 |
| 悲痛 | ✕ | 0 | 2.4 | 2.0 | 0.8 | 3.4 | 2.4 |
| 孤独 | ✕ | 0 | 2.4 | 1.9 | 0.7 | 3.4 | 2.4 |

> 最高值：恐惧/焦虑/恐怖 + 价值 C=3.8——全游戏最昂贵的行为。"赴汤蹈火"不是比喻。
> 最低非零硬解锁：爱 + 文化 C=0.4——"在爱的状态下遵循社交礼仪"几乎不费劲。

**C_control → 支付转换：**
```
AP 溢价   = floor(C_control)
SAN 磨损  = max(0, C_control - 1.5)
效果折扣  = 1 - 0.15 × C_control
```

## 六、设计约束清单

填写行为卡时必须检查以下约束：

- [ ] 驱动归属是否准确？（同一动作可以来自不同驱动，关键是"为什么做"）
- [ ] 基础 AP 是否合理？（反射/文化 ≤ 2，价值/道德可 3-4）
- [ ] valence 是否与驱动默认 valence 一致？（价值驱动除外，可取 ±1）
- [ ] C_control 是否与上表一致？（硬解锁代价不能凭空编造）
- [ ] combo 联动是否有设计依据？（不是"感觉应该有"就加）
- [ ] 悬停文案是否对应三种状态？（优势/正常/惩罚或强制）
- [ ] 是否与已有卡名重复？（每驱动 3 张示例卡名已在 `data/drives.json` 中）
- [ ] 照护驱动行为卡是否涉及 Vulnerability_signal × Attachment_strength 判定？
