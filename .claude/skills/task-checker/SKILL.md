# /task-checker — 任务 md 四维质检

对「AI 在 grilling/issue 讨论结束后总结决策产生的任务 md」（如 `.scratch/**/task-plan.md`、`grilling-NN-task-plan.md`、`summary`/`plan` 类文档）做四维质检。**只报告问题，不做设计决策，不改写文件**。

与 `/review-plan` 的分工：`review-plan` 追踪数据链路的语义断层（符号执行）；`task-checker` 检查文档本身的规范性与一致性（格式/术语/引用/语言充分性）。两者互补，可串联使用。

## 目标文件判定

| 判定 | 说明 |
|------|------|
| ✅ 是任务 md | 位于 `.scratch/` 下，文件名含 `task-plan` / `plan` / `summary` / `grilling-NN-task-plan` / `PLAN` 等，或用户显式说明「这是讨论后总结的任务 md」 |
| ⚠️ 需确认 | 文件在正式文档目录（`规则/` `实体/` 等）→ 提醒用户该文件不属于任务 md 范畴，但可做格式规范检查 |
| ⚠️ 已废弃 | 文件标记 `⚠️ 已废弃` 或位于 `参考/废弃/` `垃圾桶/` → 跳过（仅提示用户） |

## 执行流程

```
0. 目标确认 → 1. 读取 → 2. 四维扫描 → 3. 引用核验 → 4. 报告输出
```

### Step 0 — 目标确认

- [ ] 确认文件路径与类型（见「目标文件判定」表）
- [ ] 询问用户检测范围：单文件 / 目录批量（如整个 `.scratch/<feature-slug>/`）
- [ ] `--quick`：只跑 ①格式 ④语言 两维，跳过耗时引用核验

### Step 1 — 读取

- [ ] 完整读取目标 md（超长文件分段读）
- [ ] 顺带读取其**文末 `*关联:*` 列表**指向的文件（用于 Step 3 引用核验）
- [ ] 按需读取 `CLAUDE.md §md 文件格式规范`、`data/term_registry.json`（术语检查数据源）

### Step 2 — 四维扫描

#### 维度① 格式规范符合性

对照 `CLAUDE.md §md 文件格式规范` 逐条检查：

| 检查项 | 标准 | 违规示例 |
|--------|------|---------|
| F1 文件头 | 首行 `# 标题` + 紧随 `> 摘要` | 无摘要、摘要出现在正文后 |
| F2 文件尾 | 末尾 `*创建: YYYY-MM-DD | 更新: YYYY-MM-DD*` + `*关联: [...]*` | 无日期、无关联、日期格式错误 |
| F3 目录 | 超 200 行必须有 `## 目录`（有序列表链接各 `##` 小节） | 长文件无目录 |
| F4 单主题 | 全文只有一个 H1 | 出现两个 H1 |
| F5 小节编号 | 用中文数字 `## 一、` `## 二、` | 用 `## 1.` `## Section` |
| F6 废弃标记 | 废弃内容用 `> **⚠️ 已废弃**：原因。` | 用 `~~删除线~~`、`[deprecated]` 等非标格式 |
| F7 交叉引用格式 | `[显示名](相对路径)` | 裸文件名 `xxx.md` 无链接 |
| F8 参数速查表 | 涉及数值参数的文档文末有 `| 参数 | 符号 | 默认值 | 位置 |` 表 | 有数值参数但无速查表 |
| F9 行内链接 | 链接目标存在（转 Step 3 核验） | 死链 |

#### 维度② 术语与正典一致性

数据源：`data/term_registry.json`（`terms` 下每条含 `status`），以及 `CLAUDE.md §核心术语表`、`docs/决策树.md` 的已否决方向。

| 检查项 | 判定 |
|--------|------|
| T1 deprecated 术语出现 | 任务 md 中（非 `⚠️ 已废弃` 标注段）出现 `status: deprecated` 术语（`态度` `7驱动` `5模块` `CPM` `预烘焙` `认知槽` `β` `g_0` `η` `κ` `lunar` 等）→ ❌ 违规 |
| T2 术语定义误用 | 出现与注册表定义冲突的用法，如「态度卡」「SAN 是血条」「意志力=SAN」「颜色表示情绪」→ ❌ 违规 |
| T3 新符号 | 出现注册表没有的新参数符号且未标注 `[NEW]` → ⚠️ 提示 |
| T4 术语翻译/混用 | 同一概念中英混写（如同时用「SAN」和「理智值」指同一物）→ ⚠️ 提示 |
| T5 与决策树冲突 | 文档方向与 `docs/决策树.md` 已否决方向冲突 → ❌ 违规（需 Read 决策树确认） |

> 单字母参数（`β` `η` `κ`）可能误报（如希腊字母出现在公式变量中但非月光场参数）。此时以语义判断：若上下文是月光场 v2 相关 → 违规；若只是普通公式变量 → 忽略并在报告中说明。

#### 维度③ 交叉引用完整性

- [ ] 复用 Layer 1 脚本对**目标 md 引用的活跃文档**做核验：`python3 tools/validate_cross_refs.py`（死链/段引用）
- [ ] 注意：`run_all_checks.py` / `validate_*.py` 的 `collect_md_files` **排除 `.scratch/`**，因此**任务 md 自身的链接脚本不扫**，需手动核验（Step 3）
- [ ] 垃圾桶隔离：任务 md 中出现 `垃圾桶/` 路径或已移入垃圾桶的文件路径 → ❌（见 `tools/validate_trash_isolation.py` 的 `FILES_IN_TRASH` 列表）
- [ ] `*关联:*` 指向的文件必须存在且非垃圾桶文件

#### 维度④ 数学语言充分性

对照 `docs/agents/math-language-writing.md` 规范，扫描自然语言段落，找「可被公式/表格/受控词表替代却用了含糊自然语言」的地方：

| 检查项 | 触发词示例 | 判定 |
|--------|-----------|------|
| L1 模糊量词 | 「较大/少量/适当/若干/大概/往往」 | ⚠️ 建议公式化 |
| L2 无符号数值 | 出现数字但无符号/单位/范围 | ⚠️ 建议补 `symbol ∈ [min,max]` |
| L3 无来源参数 | 参数有默认值但未注明来源 | ⚠️ 建议补 `来源: xxx §N` |
| L4 阈值模糊 | 「较高才触发」「超过一定」 | ⚠️ 建议补 `>` `≤` 具体阈值 |
| L5 枚举未受控 | 「几种信号类型」未展开 | ⚠️ 建议引用 `data/*.json` 受控词表 |
| L6 无结算顺序 | 多步结算但无 `(P1)→(P2)` | ⚠️ 建议编号步骤对齐 trace |
| L7 量化未声明 | 四舍五入/截断未说明 | ⚠️ 建议标注 `round1()`/`floor()` |

> 维度④只**提示**，不强制：设计意图/动机/验收示例等自然语言段落（§四 允许保留）不报。给「公式化改写建议」时用具体示例，如：
> ✗ 「SAN 低时恢复更快」 → ✓ 「`SAN' = min(SAN + 5, SAN_max)`，当 `SAN < 30`」

### Step 3 — 引用核验

- [ ] 提取任务 md 中所有 `[text](path)` 链接与 `*关联:*` 列表
- [ ] 逐条解析相对路径（相对源文件目录），检查目标文件是否存在
- [ ] 带锚点 `#` / `§` 的 → 用 `tools/validate_cross_refs.py` 同款逻辑检查目标段是否存在（可直接调用脚本）
- [ ] 命中 `垃圾桶/`、`.trash/`、`参考/废弃/` → 检查是否在 `⚠️ 已废弃` 标注段内，否则 ❌
- [ ] 有 `--quick` 或文件数 > 20 链接 → 抽查（随机 5 条 + 所有关联列表）

### Step 4 — 报告输出

写入 `.scratch/task-check-YYYY-MM-DD-HHMM-<文件名>.md`，终端打印摘要。

## 输出格式

```markdown
# Task Check: <文件名>

> 检查日期: YYYY-MM-DD HH:MM | 检查范围: <文件列表>
> 方法: 四维质检（格式/术语/引用/语言充分性） | 复用: <脚本名+摘要 或 "无">

## 维度① 格式规范
| # | 检查项 | 位置 | 判定 | 说明 |
|---|--------|------|------|------|

## 维度② 术语与正典
| # | 检查项 | 位置 | 判定 | 说明 |
|---|--------|------|------|------|

## 维度③ 交叉引用
| # | 位置 | 判定 | 说明 |
|---|------|------|------|

## 维度④ 数学语言充分性
| # | 位置 | 判定 | 公式化建议 |
|---|------|------|-----------|

## 汇总
- ①格式: X 项 / ②术语: X 项 / ③引用: X 项 / ④语言: X 项
- ❌ 违规: N | ⚠️ 提示: M | ✅ 通过
- **阻断项**（❌）必须先修复才能作为实施依据
```

判定语义：`❌` = 违反规范必须修；`⚠️` = 建议改进不阻塞；`✅` = 通过。维度④只有 `⚠️`/`✅`，无 `❌`（语言充分性是建议性改进）。

## 阻断规则

- 维度② T1/T2/T5（术语违规/与决策树冲突）→ **阻断**：任务 md 不得传播已废弃概念
- 维度③ 垃圾桶引用 → **阻断**：违反「垃圾桶隔离原则」（CLAUDE.md 2026-08-03）
- 维度① F1/F2（无头无尾）→ **阻断**：不符合文档规范，不能作为正式任务依据
- 其余 → 提示

## 停止条件

- 已扫描全部四维且所有链接已核验 → 停止
- `--quick` 模式：跳过维度③和 F9 → 完成后提示「快速模式未核验引用」
- 目标文件为已废弃文档 → 立即停止，仅提示

## 报告存档与对比

- 报告写 `.scratch/task-check-*.md`，与 `review-trace-*.md` 并存，互不覆盖
- 修复后重跑：`glob .scratch/task-check-*` 取最新非本次文件对比，标注「上次问题已修复/未修复」

## 与 grilling 的分工

- `/grilling` = 讨论中收敛决策
- 任务 md 生成后 → `/task-checker` 四维质检（本 skill）
- 实施前 → `/review-plan` 符号执行追数据链路
- 三者按此顺序串联，形成「决策 → 质检 → 链路验证」闭环
