## 一、项目范围与建筑目录

### 1.1 设计原则

- 以 500 床方案一为**建筑类别来源**（院区多栋布局），不执着于精确 500 床位
- 以 300 床方案为**房间细节来源**（单体楼逐层平面图）
- 以 GB 51039-2014《综合医院建筑设计标准》和 GB 51058-2014《精神专科医院建筑设计规范》为**尺寸推导依据**
- 以本规范讨论过程中确认的构件标准为**强制执行标准**
- 先做真实医院，游戏功能（镜子房间/SAN监测站/Boss房等）后续叠加

## 二、坐标系与尺寸标准

### 2.1 坐标约定

| 约定 | 值 |
|------|-----|
| 原点 | 院区西南角地面 (0, 0, 0) |
| X+ | 东 |
| Y+ | 北 |
| Z+ | 上（绝对标高） |
| 用地范围 | X: 0–220, Y: 0–180 |

### 2.2 建筑原点约定

每栋建筑的 `.blend` / `.glb` 文件原点放在该建筑自身西南角底面：

```
building_origin = (building_x_min, building_y_min, ground_z)
```

Godot 场景中只需设置 `position = (building_x, building_y, 0)` 即可精确定位各建筑。

## 三、命名规范

以下命名规范可直接用正则表达式验证（`check_model.py` 模块 5）。

### 3.1 对象命名

**Blender Object 名**：

```
{Type}_{Building}_{Floor}_{Location}_{Index}
```

| 字段 | 含义 | 示例 |
|------|------|------|
| Type | 构件类型（见下表） | Wall, Col, Slab, Beam |
| Building | 建筑代码 | OP, IPA, IPB, REHAB, ADMIN, CAFE, DORM |
| Floor | 楼层 | B1, F1, F2, F3, F4, EQ(设备层) |
| Location | 方位/房间号 | N, S, E, W, R101, Corr |
| Index | 序号（同位置多个时） | 01, 02, 03 |

**构件类型前缀**：

| 前缀 | 构件 | 说明 |
|------|------|------|
| `Wall` | 墙体 | 内外墙、隔墙 |
| `Col` | 柱 | 结构柱 |
| `Beam` | 梁 | 结构梁 |
| `Slab` | 楼板 | 楼层板 |
| `Door` | 门 | 三种状态（见第四章） |
| `Win` | 窗 | 窗洞+窗框+玻璃 |
| `Stair` | 楼梯 | 踏步+平台+扶手 |
| `Elev` | 电梯 | 井道+轿厢 |
| `Ceil` | 吊顶 | 天花板 |
| `Plumb` | 管道井 | 给排水管道竖井 |
| `Elec` | 强弱电井 | 电气竖井 |
| `FireH` | 消防栓箱 | 嵌入式 |
| `Sign` | 标识牌 | 悬挂/壁挂 |
| `Nurse` | 护士站 | 柜台+工作站 |

| `Furn` | 家具 | 病床/床头柜等 (Prop) |
| `Equip` | 器械 | CT/EEG/B超等 (Prop) |

## 四、建筑构件标准

本章所有构件规格基于网上搜索结果 + 中国医院建筑设计规范 + 精神科特殊要求。

### 4.1 结构构件

#### 4.1.1 柱（Column）

| 参数 | 值 |
|------|-----|
| 截面 | 0.60×0.60m |
| 间距 | 7.2m（每 2 个 3.6m 开间） |
| 高度 | 贯通本层层高 |
| 边柱位置 | 外墙内缘 |
| 角柱 | 建筑四角 |

#### 4.1.2 梁（Beam）

| 参数 | 值 |
|------|-----|
| 截面 | 宽 0.30×高 0.60m |
| 位置 | 柱间贯通，楼板下方 |
| 开间方向梁 | 沿 X 轴，跨 7.2m |
| 进深方向梁 | 沿 Y 轴，跨 3.6m（视房间进深） |
| 与吊顶关系 | 走廊梁底=吊顶顶面（2.4m净高+0.5m吊顶空间=梁底2.9m） |

**门洞自动偏移算法**：

```
Input: 本层所有梁的AABB + 所有门洞的AABB
Output: 偏移后的门洞位置(或标记为【无法避让】)

for 每个门洞:
    for 每个梁:
        if 门洞AABB的XZ投影 ∩ 梁AABB的XZ投影:
            计算重叠体积
            if 重叠体积 > CONFIG.beam_door_overlap_threshold:
                尝试偏移: 门洞沿所在墙面移动到最近梁边缘外 ≥0.3m
                if 偏移后位置仍在建筑范围内 AND 不与相邻门洞重叠:
                    应用偏移
                else:
                    标记门洞为【过梁】(门洞上方加过梁, 门高降至梁底=2.9m)
```

#### 4.4.2 门状态

| 状态 | 模型形态 | 与玩家互动 |
|------|---------|-----------|
| 上锁（Locked） | **与关闭态外观相同** | 互动→无法打开反馈→**保持上锁** |
| 关闭（Closed） | 门扇 0°（闭合） | 互动→打开→变为开启态 |
| 开启（Open） | 门扇 90°（旋转打开） | 互动→关闭→变为关闭态 |

**关键规则**：
- 上锁的门与关闭的门**外观完全相同**，玩家通过互动失败发现上锁
- 上锁的门解锁后变为"关闭态"的普通门
- 铁栅栏门：上锁时仍可透过栅栏看到房间内部（天花板透视规则适用）
- 实心门：上锁时完全不可透视

#### 4.5.2 天花板透视规则（Godot 端实现）

- 天花板材质标记为 `M_Ceil_*` 的 mesh 在 Godot 中接收**圆形渐变 shader**
- 以角色位置为中心：中心区域天花板完全透明，向外渐变至完全实体
- 锁门 + 实心门（非铁栅栏门）的房间：天花板完全不透明
- 铁栅栏门的房间：即使上锁，天花板仍可透视（玩家可通过栅栏看到内部）
- 建模端职责：只需给天花板 mesh 分配正确的材质标记，不做额外处理

```
build_hospital.py (Blender)
  │
  ├─→ 逐建筑生成所有构件（独立对象）
  │
  ├─→ 合并前检查 (check_model.py --phase pre_merge)
  │     重叠检测/缝隙检测/命名合规
  │
  ├─→ 每层合并墙体为单 mesh
  │     写 merge_map.json
  │
  ├─→ 合并后检查 (check_model.py --phase post_merge)
  │     网格完整性/碰撞体/材质
  │
  ├─→ 导出 .glb (per building)
  │     写 name_mapping.json (blend对象名→glb名)
  │
  └─→ GLB 简化检查 (check_model.py file.glb)
        网格完整性/重叠/碰撞体/材质
```

### 10.3 Godot 导入

- 每栋建筑 `.glb` 作为独立场景导入
- Godot 主场景 `hospital_scene.tscn` 中按院区布局放置各建筑（position=院区绝对坐标）
- Props 作为独立子场景实例化到对应房间位置
- 天花板 `M_Ceil_*` 材质 mesh 在 Godot 中应用圆形渐变 shader
- 碰撞体从 merge_map.json 反向匹配到合并后 mesh
- 导航区域（NavigationRegion3D）在 Godot 中 bake
