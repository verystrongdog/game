# 剧情系统设计

> 本项目的剧情处理方案：模式 2 对话分支树统一载体（NPC/环境/内心三类节点）+ 人机协同素材库管线。对话树 = 运行时状态机（StoryEngine 解释器）+ 数据（nodes/conditions/effects/bindings JSON），与引擎现有"数据 + 解释器"模式同构。素材库 = 你构建背景（纯文本）+ AI 检索现实资料 + AI 派生工程化视图（.gen.json）双轨存储。
>
> **维度: 事件 + 管线** — 剧情触发与时间轴 = 事件；剧情数据/素材生产管线 = 管线。

## 一、设计起源与定位

### 1.1 起源

2026-08-16 grilling #86。用户感悟：游戏物理背景设计充分，但"有主观意识的个体如何与环境交互""剧情完整设计""选择如何影响个体变化"未细化。狗咬函数式的条件-分支-状态机思考法应用到叙事层。

### 1.2 关键方法论决策

- **不新增叙事结构层**：结构性主线 × 叙事性主线交汇即完整骨架（D1）
- **剧情代码本体 = 模式 2 对话分支树**（D3）——调研成熟 RPG（Bethesda Creation Engine 状态机任务、巫师 3 对话树、极乐迪斯科感官球 + 白文本、CRPG 3 万变量全局状态）后确认
- **人机协同素材生产**（M1）——AI 无法可靠判断"哪些经历塑造性格"（因果综合属人脑），AI 检索现实资料（事实收集属 AI 优势区）

### 1.3 与世界观硬约束的关系

- **D15 不可证实铁律**：对话节点 `text` 字段只存客观描述（"老王说：药房钥匙被收走了"），不存"真相"（钥匙在哪/谁是真凶）——真相由玩家通过呈现层自行拼合（S8 分层存储）
- **观察者效应**：同一对话节点对不同观察者呈现不同版本（S8 `perceptions` 受控类别层）
- **连续世界**：对话会话中途离开不回滚状态（S3）——与"不能回到过去"一致
- **敌我同构**：NPC 同样受观察者效应与月光坍缩，绑定 = 状态谓词（S4）而非静态表

## 二、主线结构（D 系列）

### 2.1 主线定义

故事主线 = 玩家在封闭医院中从「想回家」到「理解为什么回不去」的因果链（世界观 §9 驱动力）。由三个内容域构成：

```
主线 M = ⟨结构性推进 S_p, 叙事性演化 N_p, 结局态映射 E_p⟩
```

### 2.2 结构性主线（原"脊柱线"，D2 命名修正）

- 定义：门控承诺 → 钥匙链推进 → Boss 面对（任务目标系统 §6.1）
- 机制载体：空间门控（空间与关卡设计 §6.4 嵌套钥匙链）
- 玩家感知：结构性进度（能去的地方变多）
- 主线级判定：是否推进钥匙链

### 2.3 叙事性主线（原"理解线"，D2 命名修正）

- 定义：线索拼合 → 自问浮现/消解 → 世界观理解加深（任务目标系统 §6.1）
- 机制载体：笔记本线索层 + 自问层
- 玩家感知：认知变化（对世界的理解加深）
- 主线级判定：是否引发自问质变

### 2.4 结局态映射

- 三结局 = 月光三重叠加（游戏循环 §8.1），条件自动触发（§8.2），无真结局
- 触发条件公式（髓鞘化模式 + 见证 Boss 故事 + 探索深度 → 结局）**待定**——延迟到数值校准 grilling

### 2.5 命名修正记录

> **🔧 修正 (2026-08-16)**：「脊柱线」「理解线」废弃 → 「结构性主线」「叙事性主线」。原命名出处：决策树 :635、任务目标系统 §6.1。原因：用户不记得命名过，且"脊柱/理解"隐喻易与神经术语混淆。

## 三、对话树结构（S 系列）

### 3.1 对话系统形式化

```
对话系统 D = ⟨Node, Cond, Eff, Pres, M⟩

Node:   对话节点（三类同构，S5）
Cond:   条件谓词集，c: S × T → {true, false}（S = 剧情状态，T = 时段）
Eff:    副作用集，e: S → S'（仅改 Q/R/F/W，正交约束——不改 m/SAN/HP）
Pres:   呈现函数，Pres(S, obs, node) → 文本（观察者效应/D15/待机动作）
M:      已触发集（防重放）
```

### 3.2 剧情状态空间（S 系列基础）

```
S(t) = (Q, R, F, W, K, M_state, T)

Q        自问向量（qᵢ ∈ [0,1]，深化度）
R        阵营声望（r_A, r_B, r_C ∈ [0,100]）
F        NPC 关系矩阵（f_ij ∈ [-1,1]）
W        已见证事件集（防重放）
K        钥匙链进度（结构性主线）
M_state  已触发节点集（防重放）
T        时段/月相
```

### 3.3 图形态（S1）

- **DAG + 有界回跳**
- 类型 A（语境回跳）：共享子树汇合，天然支持，无需前进谓词
- 类型 B（重复询问）：允许有限重复询问；NPC 行为由状态差驱动——`Q/R/f` 无变化 → 重复原话；有变化 → 新回应（任务系统 R4 回访价值的微观版）
- 终止保证：无选项节点终止 + 状态差驱动的自然收敛

### 3.4 节点字段（S2）

```json
{
  "id": "n_0001",
  "type": "npc",                    // {npc, env, inner}，三类同构（S5）
  "speaker": "老王",                 // 受控词表 speaker_entities.json（S5）
  "tags": ["病房", "委托-药房"],      // 检索标签
  "entry_conditions": ["c_0001"],    // 节点进入谓词（入口级条件）
  "text": "…",                       // 客观层（D15 纯净）
  "perceptions": {                   // 呈现层（S8，可空）
    "玩家_低SAN": "…",
    "虔信者": "…",
    "default": "…"
  },
  "options": [
    {
      "text": "…",
      "condition": "c_0002",        // 选项可见性
      "effect": "e_0003",           // 选中副作用
      "next": "n_0002"              // DAG 跳转目标
    }
  ],
  "passive_checks": ["p_0001"]      // 阈值 → 额外内容（感官球式）
}
```

### 3.5 数据文件布局

```
data/story/
├── nodes.json          # 节点库（全部节点）
├── conditions.json     # 条件定义（查询 S 状态集 + L/φ/T 世界状态）
├── effects.json        # 效果定义（δ 副作用）
├── bindings.json       # 节点-世界绑定（状态谓词，S4）
├── speaker_entities.json  # speaker 受控词表（S5）
└── task_contract.json  # 对话树-任务系统接口契约快照（S7）
```

### 3.6 条件与效果语法（S7）

**条件语法**（复用疾病目录惯例 `{触发源} {运算符} {阈值}`）：

```
c_0001:  Q_3 >= 0.5            // 自问 3 深化度 ≥ 0.5
c_0002:  R_A >= 60             // A 阵营声望 ≥ 60
c_0003:  f_老王_玩家 >= 0.3     // 关系值 ≥ 0.3
c_0004:  W contains boss_A     // 已见证 Boss A
c_0005:  m_link_327 >= 0.8     // 链路髓鞘化 ≥ 0.8（技能检定门）
```

**效果语法**（δ 副作用，正交约束——不改 m/SAN/HP）：

```
e_0001:  Q_3 += 0.3            // 自问深化
e_0002:  R_B += 10             // B 阵营声望
e_0003:  f_老王_玩家 += 0.2     // 关系
e_0004:  W += boss_A_witness   // 见证标记（防重放）
```

**任务系统效果**（S7，接口调用——回报/放弃流程留待任务系统自身 grilling，路径 B）：

```
e_task_accept:    {quest_id, target}      → 承诺层写入
e_task_complete:  {quest_id}              → 承诺标记完成
e_task_deliver:   {quest_id, reward_ref}  → 回报结算（流程待任务系统补）
e_clue_write:     {clue_id}               → 线索层写入
e_question_raise: {q_id}                  → 自问浮现
```

### 3.7 会话语义（S3）

```
会话 Session = ⟨entry, pointer, active, ended⟩

进入:     玩家与 NPC/环境交互 → 创建会话，pointer = entry 节点（绑定实时求值，S4）
推进:     选选项 → 应用 effect → pointer = next
中途离开: 玩家主动退出 → ended = player_leave，状态不回滚（Q/R/F 已写保留）
重复对话: 再次交互 → 新会话，entry 重新求值（R4）
终止:     next = null / goto_type = end / 触发战斗 / 交付任务 → ended 置位
```

### 3.8 节点-世界绑定（S4）

绑定 = **状态谓词**，非静态表（极乐迪斯科是静态城镇，本项目是月光驱动动态世界，不能直接复用）：

```
binding_B老王:    L == L0 ∧ T ∈ {上午, 下午} ∧ φ < φ_crit → entry = n_0100   // 白天物理层
binding_老王_投影: T == 夜晚 → entry = n_0900                                  // 夜晚投影
binding_老王_扭曲: φ ≥ φ_crit ∧ T == 夜晚 → entry = n_1200                      // 扭曲空间形态

查询源: L（空间层）φ（月光场态）T（时段）——绑定在"玩家发起交互时"实时求值
```

时段粒度：三时段（上午/下午/夜晚，对齐游戏循环 §2.1），不引入新时间粒度。

### 3.9 多参与方对话（S6）

多人对话 = **顺序化一对一会话序列**（极乐迪斯科实际做法——对话始终一对一，第三方等当前会话结束）：

```
多人交互 M → 会话序列 [S₁, S₂, ..., Sₖ]
  每个 Sᵢ 完全独立（各自 entry/pointer/状态写入）
  生成规则: next(Sᵢ) = f(by_order | by_choice | by_condition, S 状态)
```

**规则演化**（S2+ 策略）：规则 = bindings.json 数据值，非引擎分支：

```
known_rules = {by_order, by_choice, by_condition}
未知规则 → fallback(by_order) + WARNING 日志（不崩溃，可降级运行）
新增规则 = 引擎 known_rules 加一行 + 一个策略方法（不影响其他规则）
```

### 3.10 对话树-任务系统衔接（S7，路径 B + 前瞻性）

```
对话树（只认识效果 id）     任务系统（拥有效果实现）
  e_task_deliver: {quest_id} ──→ TaskBridge.效果注册表
                                    ├── 已注册 → 调用任务系统实现
                                    └── 未注册 → PENDING（不崩溃，WARNING 日志）

契约演化: task_contract.json = 任务系统接口的"对话树视角快照"
          任务系统新增接口 → 契约追加（增 = WARNING 自由）
          对话树新效果引用 → 校验：引用必须 ∈ 契约（ERROR 级）
```

### 3.11 呈现层（S8）

分层存储：`text`（客观层，必填，D15 纯净）+ `perceptions`（呈现层，可空，受控类别）：

```
perception_observer ∈ {玩家_低SAN, 玩家_高SAN, 虔信者, 理性者, 完整体造物, default}
default 兜底：obs 不在类别表内 → 回退 text 或 default
```

### 3.12 演化策略（S2+）

- **增** = WARNING 自由：JSON 是超集（`JsonSerializer` 忽略未知属性），新字段随时加，AI 草稿带新字段不阻断
- **删** = ERROR 护栏：删被引用的 id / 改类型 → 阻断，提示清理引用
- **登记**：新字段进 `term_registry.json`（短标识符全入库规则）
- 契约层（C# record）= 当前理解的字段子集；存储层（JSON）= 超集——`F_C ⊆ F_J` 恒成立

### 3.13 功能需求覆盖（R 系列）

| 需求 | 设计满足 |
|------|---------|
| R1/R2/R7 任务入口/回报/线索管道 | 选项挂 effect → 写回承诺层 |
| R3 无感叹号 | Pres 待机动作派生 |
| R4 回访价值 | entry 重新求值 + 状态差驱动 |
| R5 观察者效应 | Pres(S, obs) 呈现派生 |
| R6 投降对话 | 战斗内标志 + 战斗外受限对话树 |
| R8 护士投影 | 无选项节点 `options: []`（无特殊设计） |
| R9 时段约束 | 任务层时间窗口（非对话节点） |
| R10 Boss 三阶段 | 三组节点，HP 阈值/见证标记门控 |

## 四、素材库管线（M 系列）

### 4.1 人机协同分工（M1）

| 角色 | 任务 |
|------|------|
| 用户 | 构建角色背景（人脑综合：哪些经历塑造性格）→ 返回纯文本 |
| AI | ①检索现实资料（传记/履历/社会背景/职业生态）②从纯文本派生工程化视图（.gen.json） |
| 用户 | 审阅/筛定 |

AI 无法可靠判断"哪些经历塑造了性格"（因果综合属人脑）；AI 检索现实资料（事实收集属 AI 优势区）。

### 4.2 输入约定（M2）

用户返回的纯文本 = **虚构人物前半生**（出生 → 进入精神卫生中心、遇到"月光"异常为止）。基本内容涵盖：出生地/上学/情感生活/亲密关系/爱好/日常等。

### 4.3 双轨存储（M2）

```
实体/角色背景/
├── <角色>.md            # 轨道一：纯文本原文，AI 不改写（原始素材）
└── <角色>.gen.json      # 轨道二：AI 派生结构化视图（可读，schema 可拓展）
```

**轨道一规则**：用户文本 = 原始素材，AI 不改写（可增补补充材料，但原文保留）——保证叙事资产真实性。
**轨道二规则**：从轨道一派生（时间线/关系/特质来源/剧情钩子），标注派生来源（引用即读取）；schema 字段可拓展（S2+ 演化策略）。
**双向链接**：md 头部挂 `gen: <角色>.gen.json`；gen.json `_metadata` 挂回原文。

**初始 schema 字段**（参考集，非强制模板）：`lifespan`（生平年表）/ `relations`（关键关系）/ `traits_origin`（特质形成事件）/ `story_hooks`（剧情接口）。

### 4.4 批次规划（M3，自下而上）

| 批次 | 内容 | 定位 |
|------|------|------|
| P1 | **普通 NPC 生态**（基础层） | 社会背景的"解剖实体"——引擎类比：先有脑区数据 |
| P2 | 重要 NPC（8 个） | 在生态网络中生长（高连接节点） |
| P3 | 14 角色核心层 | 面具装备载体 |
| P4（持续） | Boss 生命史 | 叙事引力中心，最后长成 |

顺序同构于引擎管线：`brain_regions.json`（基础实体）→ `tripartite_model.json`（连接）→ 技能涌现（高层现象）。

### 4.5 普通 NPC 策略（M4/M5）

- **规模**：编写时按情况定（不预设数量）
- **不构建生态位模板**：普通 NPC 也走"人机协同 + 双轨存储"管线，但按具体情境（职业/病房/关系）逐 NPC 单独构建，避免模板化千篇一律
- **素材驱动**：先积累素材池（用户构建的前半生文本），池子够大后从中挑选人物组合成生态（起点 = 住院楼 1F，M4）

### 4.6 起点切片（M4）

起点切片 = **住院楼 1F 生态**（玩家醒来的楼层，空间 §6.4 :261 唯一完全属于玩家的楼层）。含义：构建 1F 这一片 NPC 之间的完整关系网——病友/邻居/矛盾/护士站互动，玩家醒来即浸入。

## 五、与现有系统的关系

| 系统 | 关系 |
|------|------|
| 任务目标系统 | 对话效果 = 任务接口调用（S7）；回报/放弃流程留待任务系统 grilling（路径 B） |

| 核心机制 | 正交约束（叙事不改 m/SAN/HP）；被动检定查 m |
