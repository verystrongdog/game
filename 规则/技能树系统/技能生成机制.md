# 技能生成机制

> 基于链路上下文的技能系统（Grilling #20，D17/D21/D23）。技能 = 链路上下文（网络集合 × 主导角色）的链路组，效果从皮层节点激活 a(t) + CSTC gate_bonus(role) 派生（运行时状态模型 §八）。生成机制 = 规则穷举候选池（骨架）+ 涌现触发（动态）+ 设计锚点（用户灵感）。
>
> **维度: 规则** — 分拣：删除角色和地点后，技能生成逻辑仍然成立。

## 一、核心模型

```
技能 = 链路上下文（网络集合 × 主导角色）的链路组

context(link) = {(network, primary_role) for network in coactivated_networks}
  网络 = Kroell 14 网络 / Hansen 社区（集合归属，多网络链路属多个上下文）
  主导角色 = role_scores 最高分角色（primary_role）

skill_effect = skill_base_effect × gate_bonus(role)

  skill_base_effect 从 a(t) 派生（运行时状态模型 §八）:
    察觉分     = mean(4 察觉节点 a)（逐节点回落；公式正典见 [回合战斗流程](../回合战斗流程.md) §3.2/§3.3）
    精神攻击   = mean(a of cognitive nodes) × scale_mental
    物理技能   = 固定值 + a(Precentral) × w_execution
    记忆检索   = σ( mean(a of MTL nodes) − θ_mem )

  gate_bonus(role) = gate_somatic    if attack_physical
                    = gate_cognitive  if attack_mental
                    = gate_limbic     if defend/approach/flee/disrupt
                    = 1.0             if perceive/support (bypass)
```

**范式基础**：进化是"屎山"式积累复用（`参考/文献/复杂系统无边界分类-文献数据源.md`）——不划分硬边界，链路按集合归属参与多个上下文，跨上下文自然桥接。

## 二、Step 1: 规则穷举候选池

```
联合上下文 (14 网络 + Hansen 社区) × 8 角色 → 每个上下文 = 候选技能
过滤: 上下文内链路数 < 2 → 弃（无涌现基础）
产出: 候选技能池（数据驱动，见 link_contexts_tripartite.json）
```

## 三、Step 2: 涌现触发

候选技能 = 组内链路满足涌现条件时**浮现**（命名）：

```
涌现条件: 组内 ≥2 条链路 m ≥ 0.5 且 ≥1 条聚焦（构建层配置的聚焦链路）
产出: 玩家实际可用的技能集（随髓鞘化/聚焦构建变化）
```

- 涌现 = 玩家构建（髓鞘化 + 聚焦）的结果，不是学会的
- 技能集动态变化——调链路 → 技能浮现/消失/数值变化

## 四、Step 3: 设计锚点

用户灵感技能（`参考/灵感收件箱.md` 的忍无可忍/神经大条/恐惧逃离专精）作为**钦定涌现**写入：

- 机制/数值/叙事 = 用户提供
- 数据层 = 上下文链路组（指定链路 + 涌现条件）
- 锚点作用：系统生成的技能围绕锚点对齐（同上下文的生成技能风格与锚点一致）

## 五、效果计算

`skill_effect` 的计算已迁移至三层因果链动力学（Grilling #32）：

- **skill_base_effect** 从 69 个 functional_id 的 `a(t)` 派生 → [运行时状态模型 §八](运行时状态模型.md#八战斗输出映射)
- **gate_bonus** 从 3 个 CSTC 环路 gate 派生 → [运行时状态模型 §六](运行时状态模型.md#六layer-3cstc-门控粗粒度)
- 旧公式 `Σ m × rel × focus` 的迁移对照 → [运行时状态模型 §九](运行时状态模型.md#九mrelfocus-的角色迁移)

- **数值从 a(t) + gate 计算**（可模拟验证），不是人工文字描述
- 调链路（髓鞘化/聚焦）→ W 矩阵权重变化 → a(t) 和 gate 连续变化 → 技能数值连续变化——"调整链路改技能数值乃至机制"（D3 保留）
- 质量门禁：新技能必须能计算效果数值，否则不算完成（Grilling #20 用户确认）
- 验证载体：并入 Affordance Competition 计算管线——管线派生输出
