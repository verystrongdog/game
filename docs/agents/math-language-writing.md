# 数学语言书写规范

> 面向「AI 生成的任务 md / 规范文档」的书写规则：凡能用数学（公式、表格、受控词表、符号）表达的内容，优先用数学语言；系统性地降低自然语言的歧义，从而降低 AI 阅读理解与后续实施时的犯错率。自然语言只保留给「意图、动机、验收示例」等不可量化内容。

## 一、为什么用数学语言

1. **歧义传递**：任务 md 是「grilling 决策 → 实施」的桥梁。自然语言在每一跳都可能被 AI 错误解释（「较大」「少量」「一定概率」等模糊量词尤其危险）。
2. **可验证性**：公式和表格可以机械校验（对照 `term_registry.json` 的 `numerical_locations`、`tools/validate_params.py`），而自然语言段落无法被脚本验证。
3. **可测试性**：数学表达能直接映射为单元测试断言（如 `a(t)` 递推式 → 对应实现函数的测试用例）。
4. **减少往返**：一次写准，避免「AI 理解错 → 用户纠正 → AI 重写」的多轮返工。

**核心判据**：一段话，如果读者（人类或 AI）可能产生两种以上理解，且这些理解会影响实施结果，则必须改写成公式/表格/受控词表。

## 二、必须用数学语言的场景

以下任一场景出现时，不得用含糊自然语言，必须给出精确表达：

| 场景 | 示例（✗ 差） | 示例（✓ 好） |
|------|-------------|-------------|
| **数值关系** | SAN 低时大幅恢复 | `SAN' = min(SAN + 5, SAN_max)`，当 `SAN < 30` |
| **比较/阈值** | 士气较高才触发 | 触发条件：`SAN > 60` |
| **范围/区间** | 冷却时间不长 | `CD ∈ [2, 4]` 秒，步长 `ΔCD = 0.5` |
| **分支逻辑** | 视情况二分结算 | `val = max(a, b)·w₁` 当 `cond = true`，否则 `min(a, b)·w₂` |
| **概率/随机** | 大概率触发 | `P(触发) = 0.8`，伪随机：每 tick 独立抽样 `U(0,1) < 0.8` |
| **多表一致** | 各职业伤害不同 | 用一张 `| 职业 | 系数 c_j |` 表 + 公式 `dmg = base × c_j` |
| **受控枚举** | 用常见几种信号 | `signal_type ∈ {GO, NO-GO, STOP, ...}`（引用 `data/signal_types.json`） |
| **速率/递推** | 神经活动随时间变化 | `a(t+1) = a(t) + Δa(t)`，`Δa(t) = f(W, s(t))`（引用定义） |

### 判定触发词

写 md 时，若句中出现下列任一词汇，**强制进入数学检查**，先改写再继续：
`增加/减少/升高/降低/较快/较慢/较大/较小/若干/一些/适量/适度/偶尔/经常/通常/大概率/小概率/取决于/视情况/根据条件/成比例/延迟/立即/短暂/持续一段时间/从…到…` 等模糊量词或程度副词。

## 三、禁止用自然语言替代数学的场景

- ❌ 用"较高/较低"表达阈值，而非数值 `>` `≤`。
- ❌ 用"几个/多个"表达计数，而非确切数量或范围 `n ∈ [3,5]`。
- ❌ 用"很快/很慢"表达速率，而非 `v`/`Δt` 或频率 `Hz`。
- ❌ 用"一段时间"表达持续，而非 `T ∈ [...]`。
- ❌ 用"某种/某类"表达枚举成员，则必须展开为受控列表或引用数据文件。
- ❌ 用"按比例"表达线/非线性，而未给比例系数或函数形式。
- ❌ 在已有 `term_registry` 定义参数的场景，重新用自然语言描述而**不引用符号**。

## 四、可以保留自然语言的场景

这些内容不可量化，允许保留叙述：

1. **设计意图 / 动机**：为什么这样做（例如「避免过度设计」「保持可测试性」）。
2. **验收示例 / 期望行为**：描述「角色应能根据地环境自行决定靠近/远离」这类演示目标。
3. **风险与权衡说明**：非数值层面的注意事项。
4. **标题、摘要、目录、交叉引用文本**：展示性文本。

> 保留自然语言的前提是：该句不含**影响实施结果的数值或分支语义**。拿不准时就改写为数学。

## 五、数学记号的书写约定

1. **行内公式**（与文字混排）用行内代码 `` ` ` `` 包裹，如 `` `SAN' = min(SAN+5, SAN_max)` ``；独立公式用 markdown 代码块或 `$$...$$`。
2. **符号命名**：单字符参数（`g_0`、`η`、`κ`、`β`、`w_perception`）**必须与 `data/term_registry.json` 保持同名**，不得临时造新符号。
3. **下界注释**：公式中每次出现参数，首次出现处标注默认值与来源（引用 `rules/核心机制.md §N` 或 `数值参数速查表` 位置）。
4. **离散/连续**：明确「单位 tick / 秒 / 回合」；离散递推写 `a(t+1)`，连续演化标注 `Δt`。
5. **结算顺序**：多步结算用编号步骤 `(P1) ... → (P2) ...`，与 `review-plan` 的 trace 对齐，便于符号执行审查。
6. **量化函数**：四舍五入/截断必须显式，如 `round1(x)`、`floor(x)`，否则默认为保留小数的精确结算。

## 六、术语符号与注册表对齐

- 写 md 前先查 `data/term_registry.json`：术语名、参数符号、默认值、`numerical_locations`。
- 使用的每个核心术语/参数符号，都应能在注册表中查到，或明确标注 `[NEW]` 待后续 grilling 入库。
- **禁用废弃术语**（`status: deprecated`，如 `态度`、`7驱动`、`5模块`、`CPM`、`预烘焙`、`g_0/η/κ/lunar` 等月光场 v2 参数）——除非在标注 `⚠️ 已废弃` 的段落中作历史说明。见 `term_registry.json` 的 deprecated 列表。
- 引用链接统一 `[显示名](相对路径)`，标注段落 `§N`，遵循「引用即读取铁律」。

## 七、自查清单

写完后逐项自查：

- [ ] 全文扫描「判定触发词」（§二），触发处已改写为数学？
- [ ] 每个数值参数有符号、有默认值、有来源（文档章节或注册表）？
- [ ] 所有分支/比较/阈值已用 `>` `≤` `∈` `=` 表达？
- [ ] 所有枚举已展开为受控列表或引用数据文件？
- [ ] 所有符号与 `term_registry.json` 一致，未自创新符号？
- [ ] 离散/连续、结算顺序、量化函数已明确？
- [ ] 自然语言保留段落确认不含影响实施结果的数值/分支语义？
