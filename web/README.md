# 叙事 Web UI 本地预览

这里提供与 `ev-logistics/web` 相同的 Vite 本地开发服务器入口，但不复制页面内容。Vite 直接托管设计权威文件 `design/presentation/叙事界面原型.html`，并把根路径 `/` 重写到该页面。

## 启动

```bash
cd web
bun install
bun run dev
```

服务器监听远端 `127.0.0.1:8899`，端口被占用时直接报错，不会静默切换地址。当 Windows 端使用以下 SSH 隧道时：

```powershell
ssh -N -L 8901:127.0.0.1:8899 chen@100.74.30.71
```

浏览器打开 <http://127.0.0.1:8901/>。

## 构建与预览

```bash
bun run build
bun run preview
```

构建结果写入 `web/dist/`（不入库），预览地址为 <http://localhost:4173/>。

## 公网预览（GitHub Pages）

<https://verystrongdog.github.io/game/> —— 直接点开即可，不需要本机进程，也不需要 SSH 隧道。

- 发布物**只有 `web/dist`**：原型页、打包后的 JS/CSS，以及 `public/` 原样复制的资源（含 `hospital-floor/models` 的 AWS RoboMaker 模型与其 LICENSE/NOTICE）。`design/`、`data/` 的源文档不进站点。
- 由 [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) 在 push 到 `main` 时构建并部署，也可在 Actions 页面手动触发（`workflow_dispatch`）。**它不是门禁**：只在 `main` 上跑，失败不拦任何 PR。
- 项目站点挂在 `/game/` 子路径，构建必须带 `PAGES_BASE=/<repo>/`（workflow 用仓库名拼出），否则打包出的 `/assets/*` 会指到域名根而整页 404。页面里的运行时资源路径同样跟随该 base，见 `src/hospital/floor-config.js`。
- GitHub Pages 用 `dist/index.html` 作目录索引，而构建产物只有中文名的 `叙事界面原型.html`，故构建后由 `scripts/make-pages-index.mjs` 复制一份 `index.html`。
- **不发布** Unity Web 阶段 A 的产物（`web/public/unity/` 不入库）：公网页面请求 `/unity/manifest.json` 会 404，表现与本机没跑过 Unity 构建时一致。
- 仓库 Settings → Pages 的 Source 需选 “GitHub Actions”；否则部署 job 会在 `deploy` 步骤失败。

本机复现同一产物（不需要 GitHub）：

```bash
cd web
PAGES_BASE=/game/ npm run build:pages     # 等价于 workflow 的构建步骤
PAGES_BASE=/game/ npx vite preview        # 在 http://localhost:4173/game/ 下按子路径查看
```

当前页面是交互原型，不连接游戏后端或 Unity StoryEngine；加入 Vite 只解决稳定托管、热更新和宿主浏览器访问。

点「开始新游戏」后进入**开局**，这一屏**就是游戏里的那一屏**：**左边是世界（诊室，桌上摊着那份门诊初诊病历，一直在画面里）· 右边是叙事面板（医师问一句 · 患者答一句 · 医师落笔一句，回应接着排在叙事流的末尾，可按数字键）**。问诊完全按真实**精神卫生门诊初诊**的流程走（形态与口径见 [开局门诊问诊](../design/presentation/%E5%BC%80%E5%B1%80%E9%97%A8%E8%AF%8A%E9%97%AE%E8%AF%8A.md) §十四，栏目出处见 [精神科门诊病历-书写规范-检索记录](../design/spec/material/ref/%E7%B2%BE%E7%A5%9E%E7%A7%91%E9%97%A8%E8%AF%8A%E7%97%85%E5%8E%86-%E4%B9%A6%E5%86%99%E8%A7%84%E8%8C%83-%E6%A3%80%E7%B4%A2%E8%AE%B0%E5%BD%95.md)）。

- **开场与主诉 → 按主诉分支问症状群 → 风险 → 物质与躯体 → 既往 / 个人 / 家族史 → 精神检查（医师观察，只读）→ 结束与求诊期望 → 落款**。题库 114 条（覆盖 owner 给的参照 113 问），任何一局的必问骨架 25 问，一局实际 **31–39 问**。
- **每一问都可以答「不愿说」**：那一栏会少掉这一段，并在栏内单起一行小字写「未答：夜里会醒 · 诱因与缓解加重」——你能拒绝开口，拒绝不了记录被写下去；全部拒答也能把病历写完并签字。
- **纸上写的是整合成句的病史**：一层是**患者嘴里的那句**（选项与患者气泡，可以带「说话的调子」），另一层是**整理过的文书句**（`clause` 拼成的整段现病史 / 既往史 / 个人史 / 家族史，没有「栏目：取值」那种填表痕迹）。依据：《精神病学》第 7 版 第三章第三节（二）4（入院检索 §5.7）。
- 🔧 2026-09-27 阶段 6：**怎么说话就是病在哪儿现形**。四套**语言指纹**——沉下去（抑郁相）· 往上冲（躁狂相）· 有人在盯（偏执）· 要数清楚（强迫）——挂在选项与患者那一句上，共 **61 档**打标；一局里挑出来的次数决定「他说话的调子」（不足 3 档不算），并落到精神检查的**一般表现 / 言谈与思维 / 情绪状态**三行上。
- 🔧 **2026-09-27 阶段 7：经历与疾病接回这一屏**（形态与口径见 [开局经历疾病接回](../design/presentation/%E5%BC%80%E5%B1%80%E7%BB%8F%E5%8E%86%E7%96%BE%E7%97%85%E6%8E%A5%E5%9B%9E.md)）。owner 裁定「经历首先需要满足能够激活疾病」「诱因往往是**围绕着一件事**展开的」「设计要为游戏服务」，所以一局的经历**不再是十段散点，而是一件事**：
  - **那件事**：问诊答案定位出**恰一件**诱因事件（[`data/opening.json`](../data/opening.json) 的 `events`，9 件样板批）；问完之后医师那句与院方那句进叙事流。**一问都没新增**（一局仍是 31–39 问）。
  - **认下诊断**：那件事**激活的病**（每件 4 张，一套语言指纹一张）当回应摆在叙事流末尾；说话调子定下来就收窄到代言那 1 张（「怎么说话就是在说哪张病」）。玩家点「认下这一张」（或按数字键 1–4），**再点一次 = 反悔**；**不新开一屏、纸上不加「患者意见」栏**。
  - **诊断栏落笔**：认下之后由**医师**把「初步诊断」写上纸（那一栏 `who: hospital`、`fill: derived`，玩家只做「认」）；精神检查三行同时改按**病**落笔。**认病之前那一栏是空白态**（「（接诊医师尚未书写）」），治疗意见栏仍留白。
  - **交出去的东西有据**：一局走完，`profileOf()` 的 `experiences` = 那件事扩写自的素材（4 段），`diseases` = 认下的那张——这两个数组以前恒为空（属性恒 0、疾病分支恒空，且没有测试兜底）。
  - **退役**：十段配额 · 池子与四级放宽阶梯 · 「逐条核对以上属实，认满十段」· 病并集 2–4（键都留着，`web/src/character-creation/**` 与它的测试照旧全绿）。诊断与治疗意见**不写医嘱**。
- **三种笔不变**：答 · 认（不愿说 / 认下诊断）· 签；仍然**没有自由文本输入**，纸上的每一句、每一个取值都来自 [`data/opening_clinic.json`](../data/opening_clinic.json)（唯一权威数据，含阶段 7 的 `event_wiring` 上屏文案）。落款只两处：接诊医师与病史陈述者。
- 🔧 2026-09-27 阶段 5：`data/opening.json` 的八问 / 池子 / 配额与 `data/diseases.json` 的 `pool_rule` **退役但键不删**；旧模块 `src/character-creation/` 里**人物来源与属性结算仍在被现行代码调用**（不是存量）。桌上那张纸是**正白纸 + 深墨字**（正文 ≥ 4.5:1）；世界与右侧叙事面板沿用夜色基调。
- 🔧 2026-09-27 形态裁定（owner 在真浏览器里看过成品之后，口径见 [开局经历疾病接回](../design/presentation/%E5%BC%80%E5%B1%80%E7%BB%8F%E5%8E%86%E7%96%BE%E7%97%85%E6%8E%A5%E5%9B%9E.md) §十二）：**纸不随每次点击滚到底**（只有「正在填的那一栏」换了才滚进视野一次，无平滑动画）· **叙事流的滚动 = 让回应整块进视野**（块 + 24px 装得下就滚到刚好带进视野的最小位置，前面医师那一句能留多少留多少；块比视野还高就从块顶往上留 24px 起读，不再「永远滚到最底」）· **右栏只有一个滚动区**（回应并进叙事流末尾，不再是第二个滚动块）· **四套语言指纹各一个颜色，只画在选项上**（细边 + 调子名那一小块；调子名照旧写着，颜色是冗余信息；四色拉明度差，正文仍 ≥ 4.5:1）。⚠️ 那是**言语指纹的分组色**，不是被否决的「颜色表示情绪 / 态度」那套体系（[项目规约](../design/conventions/README.md) §二 第 46 行禁的是后者）。
- 形态自检：`bun web/scripts/render-clinic.mjs --check`（世界 / 桌上那张纸 / 叙事面板 / 数字键回应 / 病史整合成句 / 语言指纹，加上阶段 7 的「那件事 → 病 → 诊断栏」与**界面接线八项**，再加**形态裁定 ①②③ 十项**）；文档里那几张表跑 `bun web/scripts/clinic-tables.mjs --voices`（语言指纹与拼句）与 `--events`（那件事 · 定位规则 · 指纹挂病 · 候选分布）重出。

同一区域的“显示设置”可把本地显示亮度调到 70%–140%，选择保存在浏览器本地；它不改变 Three/Unity 场景灯光参数。

## 一层地图：房间描述与开局人物

来源：[一层跑团地图原型 §2.2—§2.4](../design/presentation/500%E5%BA%8A%E4%B8%80%E5%B1%82%E8%B7%91%E5%9B%A2%E5%9C%B0%E5%9B%BE%E5%8E%9F%E5%9E%8B.md)。这三层都是**原型占位，不是正典**：

- **点击闭环 → 右侧对话框显示描述**。描述由 `src/hospital-map-prototype/room-description.js` 按几何自动生成（面积、包围盒长短边、长宽比、顶点数），分类为长走道 / 大跨空间 / 短通道 / 标准房间模块 / 常规房间 / 小房间 / 极小围合。**不含房间名称与用途**，对话框把“几何事实 / 依据 / 尚未确定”分开列出。189 个闭环的几何读数见设计文档 §2.2。
- **开局人物在对应位置**。`src/hospital-map-prototype/npc-placements.js` 把有对话数据的五位（郑晓敏 · 谭丽娟 · 吴桐 · 周卫国 · 唐念安）按 [NPC 生态台账](../design/spec/material/NPC%E7%94%9F%E6%80%81%E5%8F%B0%E8%B4%A6.md) 的驻地落到闭环上，并按上午 / 下午 / 夜晚分别落位；标记随右侧时段切换而移动。落位是占位，`basketball_court` 没有几何候选，已登记在 `unmappedLocations`。
- **点人物 → 开局那套对话浮层**。`src/map-dialogue/dialogue-overlay.js` 只调用对话运行时的 `selectNpc` / `choose` / `leave` / `subscribe`，与右侧叙事面板共用同一份状态，不自己判断条件。⚠️ 一层还没有玩家坐标，因此原型不做“同地点才能交谈”的距离判定，这条也写在浮层界面上。

验证：`bun test` 覆盖分类判据、活动文案与人物数据的逐字一致、落位与闭环/人物的引用完整性。

## Unity Web 阶段 A

Unity 生成物写入 `web/public/unity/`，该目录不入库。Vite 会把它以 `/unity/` 暴露，并在生产构建时复制到 `web/dist/unity/`。Unity Editor 中执行菜单 `YANTF → Web → 构建阶段 A 到 web/public/unity` 后，网页宿主从 `/unity/manifest.json` 读取带哈希或压缩后缀的实际文件名。

`web/src/scene-host/` 是网页与三维运行时之间的唯一接缝；页面代码不得直接持有 Unity 实例或调用 `SendMessage`。
