# Unity 沙盘角色动作集规格（Grilling #123）

> 呈现/管线维度的**工程级规格**（非正典实体模板，演示口径）：为 Unity 呈现沙盘定义动作受控词表、动画来源、引用契约与实施批次——让后续功能（反馈动画、状态面板、NPC 行为演示）只做"简单动作引用"，并作为用户学习 Unity Animator 的路径。
>
> **维度: 呈现 + 管线** — Issue [#123](https://github.com/verystrongdog/game/issues/123)。
>
> **🔧 闭合后修正 (2026-09-08, Grilling [#124](https://github.com/verystrongdog/game/issues/124))**：① 载体默认从 KI dummy → **Mixamo X Bot（默认）/ Y Bot（备用）**（KiWalkerLab 保留 KI dummy 作对照）；② 来源矩阵实证（5 条 Mixamo clip 已下载并核验，均无蒙皮纯动画）：PhysicalAttack=`Jab Cross`、MentalAttack=`Charge`（伸手指人 = A 前指宣言，原「无合意→程序化兜底」预测被推翻）、Defend=`Short Left Side Step`（预览为循环格挡）、HitReaction=`Head Hit`、Down=`Dying`——**文件名 ≠ 动作语义**，以预览/Play 目视为准；③ 实施执行层契约（Batch0 代码结构 / 防漂移分档断言）见 #124 决策记录。词表结构、契约 A、扩展协议、批次划分均不变。

## 一、定位与边界

- **载体**：新建 `ActionLab` 动作演示场（**Mixamo X Bot 真人模型** 🔧 默认，Y Bot 备用 + 词表 controller + 按键触发 + HUD 当前动作名），无回合逻辑。
- **排除**：数值、UI 规格、特效与声音（留给「反馈动画方向」grilling）；技能动画（P1 技能系统接入时另立）；回合流程扩展动作（沙盘 #122 D1 范围外）。
- **下游消费者**（本规格只备底子，不实现）：DemoSandbox 白盒换真人模型、NPC 行为演示（unity-brain-connect）、反馈动画 grilling。

## 三、词表元规则

### 3.1 分层判定（二维）

- **Q-a 消费端就绪度**：现役消费者在驱动？若无，是否在已排期路线图（设计已闭合/批次已列）？
- **Q-b 动画来源就绪度**：现成资产可引用，还是缺口（采购/制作/程序化）？

| Q-a | Q-b | 层级 | 处理 |
|---|---|---|---|
| 现役 | 现成 | L1-引用 | 本期接 clip |
| 现役 | 缺口 | L1-制作 | 本期补缺口 |
| 已排期（设计闭合） | 现成 | L2-登记 | 锁名 + 资产锚，不制作 |
| 未排期 或 形态未设计 | — | 不入表 | 扩展协议快轨 |

### 3.2 分类枚举（受控）

`category ∈ {locomotion, combat, reaction, social, interaction, status}`——词条必带，可按类检索；新类出现走扩展协议。

### 3.3 扩展协议（元规则，Grilling #123 用户采纳）

1. **命名只增不删**：动作 id 发布后不改名；改名/删除走 `🔧 修正注记`（同决策树闭合后修正机制）+ 全项目一致性清扫。
2. **新增 = 快轨**（不等 grilling，沿 term_registry 即时更新惯例）：提出须满足三条件——(a) 有正典来源或呈现形态定义，(b) 命名符合词表规范，(c) 声明状态（L1/L2）与来源；裁决后入表。仅当触碰命名规范或新资产采购/制作 → 升级 grilling。
3. **状态迁移**：L2→L1 触发 = 消费端就绪（批次/issue 启动）；L1 动画落地单独走实施批次。
4. **防漂移校验**：PlayMode 测试断言 controller 状态覆盖全部 L1 id、每状态有 clip；AI 引用动作只允许词表内 id。

### 3.4 升级触发器（引用契约 A → B/混合）

出现任一需求即评估迁移（locomotion 迁参数化/层，一次性动作可留 A）：① 连续速度/方向混合（blend tree 需求）；② 上半身/下半身层分离；③ 动作组合复杂度超出 C# 可读范围。词表 JSON 化同样在此评估（当前机器源 = C# 常量）。

## 四、引用契约（形态 A）

- **Controller = 纯状态集**：零参数、零手动 transition；每动作 1 状态，**状态名 = 词表 id = 代码字符串**（三面对一）。
- **切换 = 运行时 `Animator.CrossFade(id, fade)`**（不依赖 transition）；衔接决策在 C#（`ActionPlayer`）：
  - 优先级：`Down > HitReaction > 一次性动作(物攻/精攻) > locomotion`（受击/倒下可打断出招；动作播放期间锁移动切态）。
  - 一次性动作播完（计时 clip.length）→ CrossFade 回 `Idle`。
  - 位移全走 CharacterController（`applyRootMotion = false`，同 KiWalkerLab）——CrossFade 只插值姿势，无滑步风险。
- **工程先例**：KiWalkerLab（`AnimatorWalker` + 4 状态 controller）即形态 A 的已验证样本。
- **手动侧微流程**（每动作恒定 3 步，用户手动，兼作 Animator 学习）：① Create State ② 挂 clip ③ 命名 = 词表 id。
- 衔接手感（fade 时长/过渡帧）属 Play 目视验证项，不可接受 → 调 fade / 换 clip / 该动作局部迁 B。

## 五、来源与许可

- KI 包（Kevin Iglesias Human Animations，Asset Store 免费）：locomotion/Talk 引用。已导入用户本机工程 123 FBX。
- Mixamo（Adobe 免费，含商业用途，禁止独立转售动画本体）：L1 缺口战斗/反馈类。**批量下载**（每动画一 FBX）→ 解压 → 拖入 `Assets/Animations/Mixamo/Combat/` → Rig 设 Humanoid → **资源名 = 词表 id**。🔧（2026-09-08 #124：5 条已下载核验，**均无蒙皮纯动画**，参数正确；下载预览角色建议选 X Bot；**文件名 ≠ 动作语义**——`Charge` 实为伸手指人、`Short Left Side Step` 实为循环格挡，已按预览实际归槽，见 §二 来源列）
- 程序化兜底：精攻前指等无合意 clip 时，沿用 `CharacterVisual` 白盒参数（5 缺口动作程序化实现全部现成）。
- 来源/许可逐词条记录于 §二 表格；README 与本文档为来源记录位。

## 六、实施批次与验证协议

| 批次 | 内容 | 执行 | 验证 |
|---|---|---|---|
| **0** 词表与骨架 | 本规格落盘；机器源 `ActionIds` 常量类（C#）；`ActionPlayer.cs`；ActionLab 场景/controller 生成 builder 或手建指引；PlayMode 测试（controller 覆盖全部 L1 id、每状态有 clip、触发后 state 正确） | AI 写码提交 → 用户 pull | 编译过；测试绿（用户 Test Runner 或 unity-cli） |
| **1** 资产与手摆 | 用户按手册：Mixamo 批量下载 5 clip → Humanoid 导入 → 建 ActionLab → 手摆 9 状态（命名=id）→ 挂 ActionPlayer | 用户手动（学习环节） | 用户 Play：逐键触发 9 动作 |
| **2** 手感与收尾 | 衔接手感调 fade；测试跑通；README/词表收尾 | 用户 Play 反馈 → AI 微调 | 测试绿 + 目视清单全过 |

**目视清单（用户 Play）**：① 待机→走→跑→停 切换顺滑；② 每动作触发后 HUD 显示正确动作名；③ 物攻→受击（打断）→回待机；④ 防御姿态循环不穿模；⑤ 倒下停留不悬浮；⑥ 衔接过渡帧是否可接受。
